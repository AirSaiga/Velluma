> 状态：**已施工（2026-09-18，M1-M3 落地，验收绿：后端 1585 / 前端 381 + tsc 净；
> M4 度量回看待真实问题分布）**。施工叙事见 `docs/incidents/nle-adf.md`「问书」；
> 契约见 `docs/agent/nle-adf.md`。问题原文随每次回答落 `data/ask_book_metrics.jsonl`
> （05 瘦身口径独立台账），M4 用它校准六类覆盖度与笼子大小。
> 形态拍板：2026-09-18 会话（**只采用行间手势**）。
> 性质：给「更懂这本书」装上调用口——系统对书的认知目前只用于它主动「递」，
> 本设计补上作者主动「问」的通道。
> 定位铁律：**图书管理员，不是合著者**——只读作者自己的数据、答完即止无对话上下文、
> 每个事实附出处、一个字都不创作。在「安静知情、绝不越界」线内。

## 0. 要解决的问题

写作中存在「只想查一个事实」的瞬间：「轮渡时刻表我在哪章定的？」「X 此刻知道 Y 吗？」
「明姐上次出场什么状态？」现在只能放下写作去世界页翻（心流断），或等心跳恰好喂到。
系统的四个知识体系（世界账本/真相表里/文风测量/前情检索）只服务「递」，不服务「问」。

**否决的形态**（留档）：副驾查询框（转头成本，笨）、情境浮卡扩展（浮卡是点实体名的
固定答案卡，自由提问会把它拖重）。**采用：行间手势**——想问的瞬间人在键盘上、在行间，
答案出现在正在看的地方，不断心流。

## 1. 形态：行间手势

- **触发**：行内输入 `??问题`（速记手势，与 `[[` 细纲胶囊同族；施工时排查与既有
  TipTap 输入规则的冲突）。
- **答案呈现**：以幽灵式浅字浮现于行间——**只读、不可采纳、不进正文**，
  Esc 蒸发（与幽灵草稿的视觉语言一致，但无采纳语义，天然杜绝滑向代笔）。
- **出处**：答案中每条结论附「出处：第 N 章 / 某条事件」，可点验（跳世界页或章节——
  注意：这是唯一的跳走动作，只发生在作者主动点验时）。

## 2. 底层架构：混合驱动，纯代码骨架

LLM 的角色被压到最小：**它是翻译和文员，不是知情人；知情人永远是作者的库。**

```
问题 → 纯代码先接（实体名/别名匹配 + 意图模式识别）
       → 能答：查表/折叠推演 → 模板拼装答案 + 出处（瞬间，零 LLM 成本）
       → 听不懂：LLM 意图解析（笼内，见 §3）→ 检索真实材料 → LLM 只在材料内组织语言 + 逐条出处
       → 检索不到：答「没查到」（诚实是功能，不是失败）
```

### 纯代码可答的六类（全部基于现成模块，零 LLM）

| 问题型 | 示例 | 数据源（现成） |
|---|---|---|
| 上次出场/状态 | 「明姐上次出场是什么时候？」 | 事件账本按实体名扫描（jieba 书级词库注入现成） |
| 谁知道什么 | 「X 此刻知道 Y 吗？」 | 认知域折叠推演（四值判定，世界内核 B3） |
| 距离/日程 | 「北岸要塞到渡口走几天？」 | 比例尺标定 + 坐标换算（D4） |
| 哪章写过 | 「轮渡时刻表在哪章定的？」 | 记忆流词法检索（jieba 关键词 + 预筛，附原句章号） |
| 线头清点 | 「还有几条没收的伏笔？」 | 伏笔台账开放项 |
| 揭示到期 | 「这章该抖出什么真相？」 | 揭示计划合并读（expected_reveal_chapter 比对） |

### LLM 笼子的两条开口（除此之外不开）

1. **意图解析**：模式匹配听不懂的问题，交 LLM 解析成结构化查询（同 Alt+N 速记的
   「解析/落库分离」纪律——LLM 只理解，产出过硬闸，绝不直接生效）；
2. **复合问题合成**：需综合多条记录的问题（「甲和乙上次见面何时」），LLM 把**检索到的
   真实材料**组织成通顺答案。

**笼门三不**：不许答检索材料之外的；不许动用模型自身「知识」；检索不到必须答「没查到」。

## 3. 信任设计

- **出处铁律**（同挂件 note 后端拼装原则）：答案里每个事实必须能指回库中一条真实记录，
  指不回的不许说；
- 「没查到」是一等功能：会编造的图书管理员比没有更糟——错误的事实比无知贵得多
  （作者可能基于错误答案写错正文）；
- 答案浅字只读，永不污染画布（画布即事实源）。

## 4. 非目标

- 不做对话/聊天：一问一答，无上下文记忆，无「顺着聊下去」；
- 不做剧情建议/走向参谋（只答事实，不答「该怎么写」）；
- 答案不进正文、不可采纳；
- 不替作者做任何判断（出处给足，核实动作是作者的）。

## 5. 分期建议

| 期 | 内容 | 验收 |
|---|---|---|
| M1 | 行间手势 + 六类纯代码问答 + 浅字只读呈现 + 出处点验 | 六类问题秒回且逐条可点验；零 LLM 调用 |
| M2 | LLM 意图解析笼子（听不懂的问题） | 解析失败答「没查到」；不答材料外内容（用回归语料对拍） |
| M3 | 复合问题材料内合成 | 每条结论有出处；编造出处被校验拦下 |
| M4 | 度量回看：问题类型分布 → 校准六类覆盖度与笼子大小 | 真实问题分布回收后调参 |

## 6. 风险与开放问题

- **六类覆盖度待验证**：作者实际会问什么，目前靠推测——M1 起埋点记录问题原文
  （本地 jsonl），用真实分布校准（这可能反过来要求扩大或缩小 LLM 笼子）；
- 手势冲突：~~`??` 与既有输入规则（`[[` 胶囊、Markdown 语法）需施工时排查~~
  **已排查（交叉验证轮）**：chineseTypography 把「中文后半角 ?」即时转 `？`，
  手势改认 `[?？]{2}`（半/全角两形态）——中文正文后实际打出「？？」也能触发；
- 零数据书：世界为空时全部答「没查到」——符合零变化契约，不设补偿；
- 自由提问的意图解析准确率是 LLM 笼子的第一个真实压力点，M2 需回归语料准入
  （同约束治理期的语料纪律）。
