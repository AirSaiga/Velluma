# 开章卡与读者清单（设计稿）

> 状态：**已施工（2026-09-18，M1+M2 落地，验收绿：后端 1568 / 前端 381 + tsc 净；
> M3 调参待真实使用数据）**。施工叙事见 `docs/incidents/nle-adf.md`「开章卡与读者清单」；
> 契约见 `docs/agent/nle-adf.md`（端点表 + 完稿审计节）。
> 性质：两面「镜子」——只呈现作者自己录进系统的数据，**零 LLM 调用、零剧情建议、零修改建议**。
> 讨论渊源：作者明确卡点=「知道本章流向，但落实到文字难」，卡片舱主治此病，故 AI 辅助密度
> 压在打字时刻是对的；AI 不参谋剧情（理由：AI 剧情不稳定，方向错了作者纠正成本高于收益）。
> 本设计只解决一件事：**作者自己的记录，在最关键的两个时刻（开写前、写完后）不在手边**。

---

## 0. 要解决的问题

写作台现有辅助几乎全部服务「打字中」与「设定维护中」两个状态。但一章的生命周期有两个
边界时刻，作者此刻是独自一人翻自己的笔记：

1. **开写新章时**：这章该抖出哪条真相？哪几条真相还不能说破？前面还吊着几条没收的线头？
   ——这些数据作者都录过（揭示计划、伏笔、期待），但散在世界页各处，开写那一刻看不到。
2. **一章完稿时**：完稿体检查的是「有没有写错」（残句/泄密/文风漂移），但没有一个
   「读者视角」——一个只读到这章的读者，此刻知道什么、还不知道什么。系统里存着全部
   数据（真相层的表/里 + 预期揭示章），从未拿它量过正文。

两个功能的定位都是**镜子**：不出主意，只把作者自己的数据折出来摆在眼前。
核对与裁决动作永远属于作者。

## 1. 核心矛盾：全面 × 密度 × 负担

讨论中作者提出的反对意见被采纳为本设计的第一约束：

> **显示一半的信息，比不显示更害人。**
> 作者不敢信「这四行就是全部」，就得自己再翻一遍核对——功能不但没省功夫，还多出一样
> 要看的东西；几次之后作者学会无视它，它沦为视觉垃圾。

因此「克制」与「完整」不能用折中解决（五行还是六行没有区别），必须用下面三条显示规则
消解矛盾。**三条规则是两个功能的共同宪法，任何一行都不许违反：**

### 规则一：按「跟这章有没有关系」圈范围，不按条数截断

- 显示的每一个集合都由一条**作者一句话能复述的规则**定义（例：「跟这章在场人物有关、
  还没揭示的真相」），集合天然小；
- 显示的计数永远是该集合的**真实总数**——写「2 条」就是真的只有 2 条，不存在
  「还有 25 条没给你看」；
- 当相关性无法计算时（空章无场景钉），集合退为定义良好的全书口径（「全书未收线头」），
  并在行内明示口径（「与在场相关」/「全书」徽标）——信任的前提是规则可预测。

### 规则二：点一下就地展开全部，永远不跳走

- 每一条目点一下即在副驾内展开**完整内容**（伏笔原文、真相的表与里、揭示计划原文），
  看完收起，人不离开写作台；
- 一次点击必须能彻底回答这个问题；回答不了是功能失败，不是作者该多跑一趟世界页。

### 规则三：没有要说的，整块消失

- 「这章没有不能说的真相」不渲染成「0 条」，而是该块根本不出现；
- 空集零像素：作者眼里每个字都是「有事」，「它出现了」本身即信号。

### 超载降级推论

若相关集合超过阈值（暂定 6 条，待真实数据校准），行内只显示**最要紧的一条**
（吊得最久的线头 / 逾期最深的揭示）+ 真实总数，展开见全量。
**完整的是「相关性」，不是「一切」**——硬塞二十条等于又变回噪音。

## 2. 功能一：开章卡

**时机与位置**：进入空章时，副驾默认落在「打算」页（InspectorPanel 五分区之一，
空章落「打算」为既有行为）。开章卡置于该页计划编辑区上方，最多四行小字。
非空章（续写老章）默认落「此刻」页，该页已有伏笔/期待行，**开章卡不重复显示**（一期）。

**内容**（每行独立遵守空集消失；全空则整块不渲染）：

| 行 | 内容 | 数据源（全部现成，纯查表零 LLM） |
|---|---|---|
| L1 该揭 | 「这章该抖出 X 了」/「X 已逾期 N 章」 | `intent_repository.read_merge_reveals`（揭示合并读：新表 reveal 意图 + canon_nodes.expected_reveal_chapter 兜底，逾期计算现成） |
| L2 别说破 | 「这章还不能说破的：N 条」 | 未揭真相（预期揭示章 > 本章）∩ 本章在场实体集 |
| L3 线头 | 「没收的线头 N 条，最久吊了 K 章」 | PlotLedger open + scene_slice 既有口径（在场名/别名命中、chapters_open 计算现成） |
| L4 场景行 | 此刻时间/地点/谁在场 | scene slice 现成 |

**交互**：零强制交互。不弹窗、不确认、不打断打字。扫到就扫到，扫不到就直接开写。
**开关**：设置里一个开关，关掉即整块消失，写作体验与现状逐字节一致。

## 3. 功能二：读者清单

**位置**：完稿体检报告（`/adaptive/finish`）末尾新增一栏「读者此刻」。
完稿是作者主动停下的仪式时刻，阅读负担天然低于写作中——**这一面镜子可以也应该
比开章卡完整**（但仍分组折叠）。

**内容**（纯章号算术，零 LLM）：

- **本章新知道**：预期揭示章 == 本章的真相（表文本）；
- **已经知道**：揭示已发生的（预期揭示章 ≤ 本章 / 已落 reveal 意图）；
- **还不知道**：预期揭示章 > 本章，**按计划章分桶成前瞻时间线**（第 N 章、第 M 章…），
  未排期的单列一组。

数据源同 L1（`read_merge_reveals` + PlotLedger 的 canon_text/public_text/reveal_plan）。
后端在 finish 响应顶层累加 `reader_ledger` 键，沿用报告区既有模式：try/except 不阻塞
完稿、零命中不设键（响应增量最小）。

**用法**：作者扫一眼，心里核对「我以为读者这章该知道 B 了——我写出来了吗？」
系统只给清单，**不给任何修改建议**；系统也不知道正文写没写，核对动作永远是作者的。

**可选二期（默认不做，单独拍板）**：把「本章新知道」的条目与正文做粗匹配，出现过
打个勾，不出现不吭声——宁漏勿误、只勾不警告。

## 4. 负担核算

| 项 | 成本 | 说明 |
|---|---|---|
| 开章卡存在时 | 扫一眼 ≈ 2 秒 | ≤4 行小字，在副驾不占编辑区 |
| 开章卡空集时 | 0 | 整块不渲染 |
| 读者清单 | 0 增量 | 附在作者本就会看的完稿报告里 |
| LLM 成本 | 0 | 两面镜子全为查表/折叠/算术 |
| AI 内容风险 | 0 | 没有一个字是模型生成的，不存在「方向错了要纠正」 |

## 5. 度量与去留

克制的度不靠设计时猜，让真实行为投票。**（05 埋点瘦身 §4 修订：不走协作埋点总线）**
开章卡带专用极简计数——`GET/POST /adaptive/opening-card/touch`（action=shown/expand）
写本地 `data/opening_card_metrics.jsonl`，独立台账零面板，看数直接看文件：

- **显示次数 / 展开次数**：展开率 <10% → 行内容自足（或无人看——结合副驾 tab 停留区分）；
- **展开后再跳世界页率** 高 → 就地展开的内容不够，按规则二加内容；
- **长期零交互** → 整块撤掉，不留尸体。

## 6. 非目标（全程有效）

- 不做任何剧情建议、走向建议（AI 剧情不稳定，纠正成本高于收益——作者拍板）；
- 不做任何修改建议（镜子只呈现，不参谋）；
- 不弹窗、不抢焦点、不打断打字；
- 不自动触碰正文与设定库（采纳线纪律不变）；
- 不替作者核对正文（核对永远是作者的动作；二期粗匹配只勾不警告）；
- 一期不做非空章开章卡（「此刻」页已有同类行，不重复建设）；
- 不在写作台催促补录揭示计划（录入引导是世界页的事）。

## 7. 施工分期（建议）

| 期 | 内容 | 验收 |
|---|---|---|
| M1 | 开章卡：后端聚合读（复用 scene_slice + read_merge_reveals）+「打算」页新区块 + 开关 + 埋点 | 空章进「打算」页可见；全空集时整块不存在；vue-tsc 净 |
| M2 | 读者清单：finish 响应加 `reader_ledger` + 报告新栏 | 完稿报告末尾可见三段清单；零命中不设键；后端既有测试全绿 |
| M3 | 度量回看与校准（超载阈值、「最要紧一条」排序键：逾期深度 vs 吊着章数） | 真实使用数据回收后调参，记录于此 |

## 8. 风险与开放问题

- **在场集质量决定 L2/L3 相关性**：零事件书的在场靠词法兜底，可能不准。纪律：在场
  不可靠时退全书口径并明示徽标（规则一），宁可全书集合也不显示「假装相关」的子集。
- **揭示计划数据稀疏**：作者没标预期揭示章时 L1/L2 与读者清单自动隐形（规则三），
  不产生噪音；但也意味着功能价值与录入完整度正相关——这是录入→放大契约的又一次
  兑现，不额外补偿。
- **「该揭」误报**：作者改了计划没更新数据时会显示过期提醒。定位是镜子不是警告，
  无视成本=一眼；宁可过期不可编造。
- **开放问题**：超载阈值 6 与降级排序键均为占位，待 M3 真实数据校准。
