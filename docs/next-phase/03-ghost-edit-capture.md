> 状态：**已施工（2026-09-18，M1-M3 落地，验收绿：后端 1585 / 前端 398 + tsc 净；
> M4 度量回看（粮食速率/干净采纳率/暂留转化率）待真实写作数据）**。叙事见
> `docs/incidents/nle-adf.md`「幽灵改稿自动捕获与三键」；契约见 `docs/agent/nle-adf.md`
> 续写节与 `docs/deai-integration.md` §5a。
> 交互模型拍板：2026-09-18 会话（三键阶梯/书签纪律/提示形态经作者逐点确认）。
> 性质：deai 数据飞轮的收集端重做 + 幽灵交互健壮性升级，一次设计、同一交互模型。
> 一句话定义问题：作者微调完成前必然大量修改幽灵草稿——**这些改动是训练小模型最好的粮食
> （bad=AI 原样、good=作者亲手版），但现在的收集方式（手动两步五步操作）实质停滞**
> （2026-09-08 至今仅 2 对）。本设计让收集变成零操作，并让幽灵交互本身防呆。

---

## 0. 讨论中确立的边界

- **不做系统自学品味/口味函数**（作者拍板）：改动数据的唯一去向是 deai 训练对，
  经既有六闸 + 人工过目后才进训练集；学习只发生在小模型重训，不发生在运行时。
- 手动「记改前/记改后」**保留**（自由选段场景），自动捕获与其并存。
- 一期只收 ≤100 字短稿（契约 C1 窗口；stitch/continue 主战场）；长稿句级拆分留 v2
  评估（与 `docs/deai-integration.md` §6「句级分片待评估」对齐）。
- 捕获范围：五模式幽灵采纳 + 细纲胶囊扩写采纳——凡「AI 原样文本系统已知」的场景。

## 1. 自动捕获原理：书签位置映射

**核心思路：不找文字，跟住位置。** 幽灵与改后文本长度必然对不齐，文本比对是死路；
跟踪的是那段文字的**首尾两个位置**。

- **采纳瞬间**：暂存幽灵原文 + 在段首段尾各放一个书签（纯内存 ProseMirror position
  mapping，**不写入保存的 HTML**——画布即事实源不受污染）。插入点系统自知，放置必精确。
- **写作中**：书签随每次编辑自动移动（中间插字→尾书签后移；删句→靠拢；前文加段→
  整体后移）。长度变化天然免疫。
- **定稿**：读出两书签间现文，与暂存原文对比——相同则静默跳过（干净采纳），不同则
  自动成对（bad=幽灵原文 / good=现文），提交 `POST /api/deai/pairs`。

### 三条健壮纪律（会话中逐一推演确立）

1. **书签跨保存存活**：1s 防抖自动保存只做「对比并更新」（有改动→写/覆盖该幽灵的对，
   同一幽灵只留最新版；无改动→继续安静跟踪）。书签寿命=整个章节会话，切章定稿。
   ——堵住「手滑采纳 → 自动保存先触发 → 误判干净采纳 → 书签被清 → 之后的修改无人跟踪」。
2. **塌缩不死**：整段删除时书签塌缩为零宽度的点**守在原地**；作者原地重打（「删了重打」
   习惯）书签重新张开包入新字，照样成对；到切章仍为零宽 → 记「完全否决」信号（不成对）。
   剪切粘贴、整段替换等导致塌缩的场景同此处理。
3. **误采纳自然消融**：手滑采纳后，Ctrl+Z（塌缩，无事发生）/ 删除（进纪律二）/
   将错就错改了它（真实教材）——系统**无需区分故意与误触**，书签生命周期全部正确吸收。

### 边界与取舍

- 应用关闭重开 → 内存书签丢失，该段漏记。**一期接受**（改动高频，漏一段不痛；
  锚点落本地+重开找回的补救方案留档，默认不做）。
- 多幽灵并存：每个采纳独立书签，互不干扰。
- 章内跨天续写：重开前已保存的对保留（最后保存时版本），重开后新编辑不追踪（同丢失条款）。

## 2. 三键承诺阶梯（交互层防呆）

| 键 | 含义 | 承诺程度 |
|---|---|---|
| **Tab** | 采纳——转正为普通文字，书签开始跟踪 | 正承诺 |
| **Enter** | **暂留**——幽灵不蒸发，停在原地保持幽灵态；光标移到其下方新起一行继续写；随时回来点它 Tab 转正 / Esc 丢弃 | **零承诺** |
| **Esc** | 丢弃——蒸发（短时间窗内可找回：重按触发键原样重现，不重新生成） | 负承诺 |

设计原则：**最易手滑的 Enter 映射到零承诺动作**——误触不是靠小心避免，是靠让误触无害
来消灭。手滑 Enter 的结果只是「幽灵还在、光标换行」，零损失。

配套防呆：

- **未灌完不上膛**：打字机流式灌出期间，按键只打断不采纳；
- **灌完缓冲窗**：流式完成后短暂窗口内的按键不触发采纳（防生成延迟期误触）；
- **暂留态工程项**：幽灵死亡收割（reapGhostIfDead）对暂留豁免；**一期只允许一个暂留位**
  （新暂留/新召唤会蒸发旧的，防幽灵垃圾）；暂留后最终丢弃 = 「看过了但没要」的强信号，
  喂学着闭嘴（比未看即蒸发更真实）。

## 3. 视觉层

- **幽灵边界轻增强**（三选一，施工时定）：边界虚线 / 行首槽位幽灵标 / 灌字尾端活点。
  原则：还是文字，但边界一眼可辨。
- **框体方案已否决**（留档）：框体把候选正文变成界面控件（审稿心态取代文感）、斩断
  半句接续、灌字时持续重排抖动。框体适合的场景是**历史回顾**（如本章幽灵采纳记录列表），
  不在写作现场。
- **「AI 来源·未审」标记**：转正后的幽灵段以细虚线标记（= 书签可视化），持续到作者
  首次编辑该段。取代此前设想的「渐隐余韵」——更持久、语义更准（服务「过会儿来改」场景）。

## 4. 提示形态

- 保存时**完全静默**（自动保存每秒触发，逐次提示=轰炸）；
- **切章聚合一条**：「本章为你记下 N 对（可撤销）」；有未决暂留则合并：
  「本章记下 3 对；还有 1 段暂留的幽灵（去处理）」；
- 撤销走既有 `DELETE /api/deai/pairs/{id}`，6 秒胶囊先例扩展为按批撤销。

## 5. 数据纪律（全部沿用，不变）

- bad 必须是 AI 原样产出——自动捕获**由构造保证**（比手动两步更可靠：手动靠作者自觉）；
- 收集侧仅三条硬校验（bad 非空且 ≤100 字、good ≤600 字）；**六闸与「人工过目才合并
  训练集」的纪律原封不动**（`deai/scripts/ingest_behavior_pairs.py` 管线不变）；
- 自动对与手动对同池（`data/deai_pairs.jsonl`），以 source 字段区分（auto_ghost /
  capsule / manual），便于入库侧分组统计质量。

## 6. 非目标

- 不做系统自学品味/口味函数（§0 已拍板）；
- 不做框体幽灵（§3 已否决留档）；
- 不做应用重开后的书签找回（一期接受丢失）；
- 不动 deai 抛光挂点/保底/契约（呈现平面链路不变）；
- 不改变幽灵触发方式（Space 召唤照旧）；不动挂件/走向卡交互。

## 7. 分期建议

| 期 | 内容 | 验收 |
|---|---|---|
| M1 | 书签跟踪 + 自动成对 + 切章聚合提示（核心捕获链路） | 采纳→修改→切章全自动成对入 jsonl；干净采纳不误记；撤销可用 |
| M2 | 三键改造（暂留态 + 死亡收割豁免 + 找回窗 + 未灌完不上膛 + 缓冲窗） | 手滑 Enter 零损失；暂留可回转/丢弃；旧有 Space 召唤行为不变 |
| M3 | 视觉轻增强 + 未审虚线标记 | 幽灵边界可辨；转正段未审可辨、碰过即消 |
| M4 | 度量回看与校准 | 见 §8 |

## 8. 验收与度量

- **粮食积累速率**：基线 2 对/10 天（手动时代）→ 目标：真实写作一周即超过手动时代总量；
- **干净采纳率**（自动统计的副产品）：采纳后零修改的比例=AI 稿质量的个人镜子；
- **暂留转化率**：暂留→采纳 vs →丢弃的分布（幽灵质量与时机质量的信号）；
- **入库质量**：自动对的六闸通过率不低于手动对（验证「构造保证 bad」的论断）。
