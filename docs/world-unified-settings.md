# 世界页统一设定入口设计（静态数据录入与可视化融合）

> 状态：设计稿（待评审）
> 范围：`frontend/src/features/world/` + `backend/routes/world.py` + 桥接层
> 前置讨论：世界页以事件溯源为底座（`computeWorldState` 纯函数推演），本设计把设定中心
> （`BibleView` 九分区）中以表单录入的静态数据融合进世界页，实现"零翻译录入 + 单一事实聚合视图"。

---

## 0. 目标与非目标

**目标**

1. 设定中心的静态数据录入（角色 / 关系 / 资产 / 世界观 / 伏笔 / 期待 / 地点）全部迁移进世界页，
   以直接操纵（direct manipulation）方式录入，以三个投影透镜（地图 / 脑图 / 时间轴）可视化。
2. 作者心智模型对齐：**画出来 = 录进去**。开书时零前置表单，档案随写作生长。
3. 生成侧（`settings_bundle` / perceive / RAG）数据供给不断：桥接层先双读，后切换。

**非目标**

- 文风（StyleCardManager）、笔记、应用设置**不进世界页**——聚合要有边界，世界页只收
  有空间性或时间性的设定。
- 本期不改生成引擎的 prompt 消费格式（只加数据源，不动消费端）。
- 不做多时间线/平行世界（事件溯源架构天然支持，留作后续）。

---

## 1. 设计原则（不可妥协项）

| # | 原则 | 含义 |
|---|------|------|
| P1 | 零翻译录入 | 界面操作直接对应作者脑中的概念（拖人物=移动事件、圈多边形=疆域），无"先想该填哪个字段" |
| P2 | 实体底座唯一 | `WorldEntity` 是所有静态设定的唯一家；旧 `characters`/`assets` 表迁移后退役 |
| P3 | 时变不入库 | 沿用事件溯源铁律：位置/生死/疆域由事件推演。关系的时间性也走事件锚定，不存"当前关系"快照 |
| P4 | 聚合 = 透镜切换 | 同一底座的三个投影（空间/语义/时间），切换而非堆叠；每层可独立显隐 |
| P5 | 档案生长式 | 实体卡默认只有"名字+一句话"；字段按需添加、AI 沉淀建议回填、作者确认入库 |

## 2. 数据模型设计

### 2.1 WorldEntity 扩展：档案字段 schema 化（不建新表）

现有 `props: JSONB` 足够，定义表驱动 schema（前端 `engine/entitySchema.ts`，仿 `EVENT_TEMPLATES`）：

```ts
// character 档案字段（每个字段 = 一个可就地编辑的行，不是一个表单页）
CHARACTER_FIELDS = [
  { key: 'appearance',    label: '外貌',     hint: '一句话，写到再补' },
  { key: 'personality',   label: '性格',     hint: '核心特质 2-3 个' },
  { key: 'background',    label: '背景',     hint: '出身/经历' },
  { key: 'goal',          label: '目标',     hint: '他想要什么' },
  { key: 'motive',        label: '动机',     hint: '为什么想要' },
  { key: 'speech_style',  label: '说话风格', hint: '语气/口头禅/称谓习惯' },
  { key: 'habits',        label: '习惯',     hint: '小动作/癖好' },
  { key: 'skills',        label: '能力',     hint: '武功/法术/技术，逗号分隔' },
]
// faction: ideology / structure / leader_ref / member_refs
// asset:   description / origin / current_holder_ref
```

实体级通用字段（非 props，实体表直接承载）：`aliases[]`（**新增列**，别名对 RAG 检索和 POV 名闸门
都关键）、`importance`（1-10，上下文注入优先级，对应旧表 `importance_level`）、
`visibility`（`public`/`private`——读者已知 vs 作者已知，**从 Canon 吸收的关键维度**，
AI 生成时防止把作者视角的秘密写进正文）。

> 决策：档案字段放 JSONB 而非拆列。字段集会随反馈演化，schema 表驱动让"加一个字段"只是
> 改一个数组项；旧 CharacterPanel 的 `static_prompt` 大文本在迁移时由 LLM 拆分为结构化
> 字段（一次性迁移脚本，作者过目确认）。

### 2.2 关系：新表 `world_relations`（脑图透镜的边）

```
world_relations:
  id, book_id
  source_entity_id, target_entity_id   -- 有向：source 对 target 的认知/态度
  relation_type   -- 枚举核心（亲属/敌对/同盟/师徒/从属/恋人/宿敌…）+ 自定义标签
  label           -- 显示名（"义兄弟""杀父仇人"）
  affinity        -- 可选数值 -100..100（对应旧表 affinity_score）
  note            -- 互动设定（对应旧表 description）
  -- 时间性（P3）：两种形态
  static: bool    -- 一直成立（默认）
  event_ref       -- 可选：锚定到 alliance/war_declare/custom 事件 → 边随时间轴游标显隐/变色
  valid_from / valid_to  -- 推演缓存列（由事件回放维护，非作者录入）
```

`computeWorldState` 扩展第四类推演：`relation_states`（时刻 t 的活跃边集合）。
静态边恒在；事件锚定边在锚事件回放后激活，`war_declare` 类可覆盖同对势力的旧关系。

### 2.3 伏笔 / 期待：双时间锚点对齐世界时间

- `plot_ledgers` 增列 `world_time_planted` / `world_time_resolved`（int，可空）。
  已有 `chapter_id` / `resolved_in_chapter_id` 保留；**换算规则：优先显式世界时间，
  缺省由章节叙事时间锚换算**（纯设定型伏笔可不关联章节，直接落世界时间）。
- `reader_expectations`（期待账本）同理增 `world_time_planted` / `world_time_released`。
- 弧线带渲染数据 = 两表按锚点投影到时间轴（作者层伏笔紫色、读者层期待金色）。

### 2.4 章节叙事时间锚（本设计的枢纽）

`chapters` 增列 `narrative_time`（int，可空 = 本章发生的世界时刻）。

- 这是**两套时间系统（章节轴 ↔ 世界轴）的第一座桥**。它一旦存在：伏笔/期待弧线自动落位、
  时间轴叠加章节刻度、写作时按 `computeWorldState(narrative_time)` 取时间切片快照。
- 与既有 `Chapter.world_snapshot`（V4.0 发布时 SnapshotExtractorAgent 的 AI 抽取快照）的关系：
  **保留不动，定位降级为"AI 观测快照"**；事件账本推演的是"作者事实快照"。二者并存互补，
  远期方向是发布时的 SnapshotExtractor 改为**抽取候选事件**（进事件账本待作者确认），
  快照由推演生成。本期只在 UI 桥接显示，不动该链路。

### 2.5 API 变更清单（`routes/world.py`）

| 端点 | 变更 |
|------|------|
| `GET /world/overview` | **新增**：一次返回 entities+relations+locations+events+ledgers+expectations+chapters(锚点)，替代世界页 6 次串行请求 |
| `/world/relations` CRUD | **新增**（含 event_ref 校验） |
| `/world/entities` PUT | 扩展 props 档案字段 + aliases/importance/visibility |
| `/world/state` | 扩展 relation_states |

后端迁移：`database.py` MIGRATIONS 加 `world_relations` 建表、`world_entities` 加列
（aliases/importance/visibility）、`plot_ledgers`/`reader_expectations` 加时间列、
`chapters` 加 `narrative_time`。ORM 对应更新（`models.py`）。

## 3. 交互层设计

> 2026-08-14 讨论定稿。操作哲学见 3.0；三个关键分歧已拍板（见 3.2 决策记录）。
>
> **⚠ 2026-08-15 方向修订：三透镜 → 单一画布。** 脑图透镜已退役（`WorldLensMindmap` 删除），
> 地图成为唯一编辑画布：所有实体统一上地图（有事件历史的按推演位置显示，拖=录 move 事件；
> 没故事的按**画布锚位** `canvas_x/y` 自由摆放，拖=移锚位）；关系画在两端实体当前位置之间
> 随游标演变（激活生长动画）；⇧+拖节点=建关系、右键空白=建实体（脑图手势平移到地图）。
> 原因：双画布迫使作者在两个空间维护同一批实体，割裂。3.1 的布局图与 3.5 脑图节保留为历史记录。

### 3.0 操作哲学与统一机制

**心智模型：作者书房里的一张大桌子。** 地图是沙盘（空间），时间轴是编年史（时间），
脑图是人物关系板（语义），侧栏是散落的卡片（结构清单）。

**免模式优先**：屏幕上已有可抓的目标物 → 免模式直接操纵（拖人物 marker、拖疆域顶点、
拖弧线端点、脑图拖线——各有明确目标，互不冲突）；要凭空创造 → 模式化拾取（点地图建地点、
圈绘疆域——它们争夺"空白处点击"的含义，互斥、Esc 逐层退出）。

**时间轴游标 = 输入焦点**：游标时刻不只是观察点，还是所有新录入的默认时间。
"先把游标拖到事情发生的时刻，再记录它"——拖人物、埋伏笔、建实体全部默认发生在游标时刻，
头部大字显示当前时刻。这一个机制把"回放观察"和"录入"缝成同一个动作流。

### 3.1 世界页布局升级

```

│ Header  统计 · undo/redo · [地点][事件][实体][批量]          │
├─────────────────────────────────────────┬───────────────┤

│  ┌───────────────────────────────────┐  │ 地点 / 事件 /   │

│  │ 地图 = Leaflet（现有）              │  │ 资产            │
│  │ 脑图 = Cytoscape 力导向（新）        │  │ （分组折叠）     │
│  └───────────────────────────────────┘  │                │
│                                          │ 关系住脑图、     │
│                                          │ 伏笔期待住时间轴 │
├─────────────────────────────────────────┴───────────────┤
│ 时间轴头部：当前时刻 · 「悬空伏笔 N」徽标 · 分层开关           │
│ 时间轴（自下而上分层，均可开关）                              │
│   ⑥ 游标 + 播放                                            │
│   ⑤ 事件标记点 + 密度直方图（现有）                           │
│   ④ 伏笔弧线带（紫，作者层）   ③ 期待弧线带（金，读者层）        │
│   ② 章节刻度层（第N章 ↔ 世界时间，点击跳该章叙事时间）           │
│   ① 年份刻度（现有）                                        │
└─────────────────────────────────────────────────────────┘
```

**实体详情抽屉**（新增，点侧栏卡或地图/脑图节点弹出，右侧滑入）：
档案字段就地编辑（每字段一行，"+"按需添加）、该实体编年史（涉及其的事件按时间排列）、
出现章节、快捷动作（记录移动/记录死亡/记录疆域变更——都是**预填事件表单**，不产生越轨数据）。

**选中联动**：地图/脑图/时间轴/侧栏共享同一选中态——选角色 A，地图飞到其在游标时刻的位置，
脑图高亮其节点及一度关系，时间轴高亮其事件，抽屉展开其档案。

### 3.2 拍板决策与场景走查

**决策记录（2026-08-14 讨论）**

| 分歧点 | 拍板 | 理由 |
|--------|------|------|
| 拖人物 marker 松手后 | **直接创建事件 + toast「Ctrl+Z 撤销」**，不弹确认 | 作者操作目标明确，弹窗打断心流；误触成本 = 一次撤销，与疆域圈绘同哲学 |
| 事实清单侧栏边界 | **只放结构**（地点/事件/角色/势力/资产）；关系住脑图、伏笔期待住时间轴 | 每类数据一个主场透镜，不重复；侧栏瘦身后时间轴头部加「悬空伏笔 N」徽标补偿 |
| 埋伏笔主入口 | **时间轴右键/长按菜单**（埋伏笔 · 记录事件 · 标记本章叙事时间） | 可发现性好，天然绑定"在此时刻"语义；不用拖段手势（与拖游标冲突、难发现） |

**场景 A · 理关系（脑图透镜）**：从 A 节点边缘拖橡皮筋线到 B 松手 → 浮在连线中点的**内联表单**
（类型下拉 + 标签 + 可选态度值 + 「一直成立 / 从某事件起」开关，后者出事件选择器）。
入库后把游标拖到锚事件之前，边半透明显示"将于第 3 年·鸿门宴后成立"——关系的时间性看得见。
拖到空白处松手 → 快捷建实体，顺手补漏。

**场景 B · 记迁徙（地图拖拽）**：游标拖到目标时刻（时间轴=输入焦点）→ 抓住 marker 拖动
（起点锚定虚线 + 顶部模式条「正在记录【角色】的移动 · 北境 → 此处 · 第 5 年 12 月 4 日〔改〕」）
→ 松手**直接生成** move 事件，轨迹线立即上图；toast 带「+同行者」可展开补选多人
（避免拖前先做多选）。

**场景 C · 埋伏笔（时间轴右键）**：右键/长按某时刻 → 「埋伏笔」内联小表单（内容一句话 + 类型，
回收时机可空）→ 紫色弧线落位；无回收锚则延伸至游标右侧渐隐 + 尾标「悬空 N 章」。
回收来源：perceive 建议（写到某章后提示"这章似回收了『主角身世』"，作者点✓ 闭合）或手拖弧线端点。

**场景 D · 补档案（实体抽屉）**：任意透镜点中实体 → 抽屉滑入（名字 / 一句话 / 推演状态标签
（位置/生死，只读）/ 编年史最近 3 条）。「+ 添加字段」→ schema 字段菜单（已加过的不出现）→
一行输入，**失焦即存，无保存按钮**。AI 沉淀建议住抽屉"生长区"（✓/✗/✎，红点计数，
永不静默写入）。抽屉底部快捷动作（记录移动/死亡/疆域）全部 = 预填事件表单。

**场景 E · 查一致性（回放）**：点章节刻度层第 8 章 → 游标跳至该章叙事时间 → 地图呈现该时刻
快照（在场角色/疆域/悬空伏笔）；发现某角色编年史空白期 → 抽屉内就地补 move 事件。

### 3.2.1 手势与入口总表

| 数据 | 手势/入口 | 类型 | 落地方式 | 产生 |
|------|-----------|------|----------|------|
| 地点 | 点地图 → 命名 | 模式化（✅ 已有） | 即建 | WorldLocation |
| 事件 | 模板 + 圈绘 | 模式化（✅ 已有）；时间轴右键亦可 | 表单 | WorldEvent |
| 角色/势力/资产 | 侧栏「实体」连续建 | 模式化（✅ 已有）；脑图空白拖线落点快捷建 | 即建 | WorldEntity |
| 关系 | 脑图 A 拖线到 B | 免模式（新） | 内联表单（连线中点） | WorldRelation |
| 移动 | 拖人物 marker | 免模式（新） | **松手直接创建** + toast 可撤销/同行者 | move 事件 |
| 死亡 | 抽屉「记录死亡」 | 免模式（新） | 预填 death 表单（时间=游标） | death 事件 |
| 疆域变更 | 圈绘 | 模式化（✅ 已有） | 表单回灌 | territory_change |
| 伏笔/期待 | **时间轴右键/长按** | 模式化（新） | 内联小表单，落右键时刻 | PlotLedger / Expectation |
| 章节叙事锚 | 时间轴右键「标记本章叙事时间」 | 模式化（新） | 直接落，可拖改 | Chapter.narrative_time |
| 档案字段 | 抽屉「+ 添加字段」 | 免模式（新） | 一行一存（失焦即存） | props |

**模式编排**：模式化操作互斥（底图编辑 > 绘制 > 拾取，Esc 逐层退）；免模式手势不互斥
（目标物不同：marker / 弧线端点 / 脑图节点）。任何免模式手势拖动中，模式化入口按钮置灰；
免模式手势不进 undo 之外的任何确认环节。

### 3.3 档案生长（替代 CharacterPanel 表单，P5 落地）

三个生长时机：

1. **写到时补**：写到角色第一次开口，点开实体卡补一行"说话风格"。每次只面对一个字段。
2. **写完自动长（M3）**：`/adaptive/settle` 已从正文抽实体 → 扩展为抽档案字段与候选事件，
   以**建议卡**形式出现在实体抽屉（AI 提议 · 作者 ✓/✗），确认后入库。永不静默写入。
3. **录入时预填**：建实体后若已有相关事件，AI 据事件建议档案字段（一次性，可关）。

`importance`/`visibility` 用卡角徽标点击切换，不占表单位。

### 3.4 伏笔 / 期待弧线带

- **录入入口（已拍板）**：时间轴右键/长按菜单「埋伏笔」，落右键时刻（非游标时刻——
  对着哪个时间点埋就落在哪）；期待同构，入口并列。
- 弧线从 plant 锚点画到 payoff 锚点；`open` 状态的伏笔弧线延伸到游标位置后渐隐 +
  尾部标"悬空 N 章"（N 由章节锚换算）——**"该收了"一眼可见**。
- 时间轴头部常驻「悬空伏笔 N」徽标（侧栏不放伏笔清单后的聚合视图补偿），点击 = 过滤只看悬空弧线。
- 点击弧线 → 详情卡：内容 / 类型 / 证据（关联章节链接，点击跳写作台该章）。
- 拖弧线端点 = 改锚点（undo 入全局栈）；回收闭合可由 perceive 建议触发（作者点✓）。

### 3.5 脑图透镜（`WorldLensMindmap.vue`）

- Cytoscape 力导向（依赖已有，`CanonGraph.vue` 为先例）。节点：角色●/势力■/资产◆，
  按类型着色；有坐标的地点可作为可选节点显示（默认关，防止大图噪音）。
- 边 = `WorldRelation`：类型色 + label；**事件锚定边随时间轴游标激活/失活**（P3 的可视化体现，
  拖一下游标看到结盟变宣战，是"设定→事态"最直观的演示）。
- 世界观自由节点：规则/概念卡（魔法体系/禁忌/地理概念），可连线"影响/属于/违背"——
  世界观从一篇长文本变成可检索的图谱。
- 拖线建关系、双击节点开详情抽屉；布局支持按"势力聚类"一键重排。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 双数据源撕裂（世界页改了名，生成侧用旧名） | 桥接读时映射 + 设定中心面板迁移期只读 + M4 收口 |
| `useWorld` redo 重建新 id 导致关系/事件引用悬空（已知 M1 债） | **引入 relations 前先修**：undo/redo 改幂等（软删 + 恢复），不再物理重建 |
| 时间轴信息过载 | 弧线带/章节刻度默认折叠为一行开关；沿用 `layerVisible` 分层模式 |
| 脑图大图性能（>200 节点） | Cytoscape 按类型/势力过滤 + 局部渲染（只展开选中节点的二度邻域） |
| 拖拽手势误触产生脏事件 | 模式确认条 + 事件可 undo + 脏数据有"未确认"徽标可选 |
| WorldTerminalState 与事件账本语义冲突 | 本期并存（AI 观测 vs 作者事实），UI 分别标注来源；远期统一为事件抽取 |

## 8. 与现有系统的边界确认

- **Canon（CanonView）**：本设计不直接动它。实体底座统一后（M2+），CanonNode 的
  character/place/object/hook 与世界实体合并评估，另行设计。
- **章级绑定（AssetPanel 勾选）**：M2 后由"时间切片快照 + 作者焦点标记"逐步替代。
- **ReaderMirror 期待账本 / PlotLedger 伏笔账本**：表和 API 不动，只加时间锚列 +
  世界页可视化消费；设定中心的两个面板保留为表格视图（高级用户），世界页弧线带为主视图。
