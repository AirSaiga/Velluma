# Velluma 前端整体重构设计（配合 3.1 统一引擎）

> 日期：2026-07-19
> 配套：`generation-v3.1-unified.md`（后端统一引擎）、`generation-v3-design.md`（3.0）。
> 目标：**专业**。衡量标准：写作是主角、AI 是副驾；输入简单有效；交互合理克制；视觉像写作工具而不是控制台。
> 术语遵循 `generation-v3.1-unified.md` 附录 A。

---

## 1. 设计原则

| # | 原则 | 含义 |
|---|---|---|
| F1 | **编辑器是唯一的舞台** | 一切 AI 结构（铺垫结构图、质量报告、设定）退居侧栏与独立视图，绝不遮挡正文；任何流程中编辑器始终可见 |
| F2 | **人的注意力投向 5%** | 三个确认点（高潮点/铺垫结构/高潮段成稿）按档位自动开合；其余全部通知式，可一键带过 |
| F3 | **输入简单有效** | 用户的日常输入面只有三处：章节卡横条、确认点、正文本身。消灭 90vh 大弹窗和九 tab 悬浮栏 |
| F4 | **AI 存在感统一且克制** | AI 产物用单一强调色 + 细线徽标；界面 chrome 零 emoji；状态用词即写作语言（漏埋/泄底/未回收），不用工程黑话 |
| F5 | **信息按"章节"聚合** | 用户思考的单元是"这一章"：定档、高潮点、铺垫、审校、伏笔都在"本章"语境下触手可及 |

## 2. 现状诊断（为什么必须重构而不是修补）

- **无路由、单视图**：AppContainer 1663 行承载一切，无法承载新视图（大纲板/设定中心/数据）。
- **面板蔓延**：右栏 9 个悬浮 tab（角色/资产/世界观/文风/地图/评审/笔记/章节配置/设置），其中多个是直接 import services 的违规组件。
- **孤儿代码**：novel-wizard（完整 5 步向导未接入）、intent-driven 推荐组件、QualityReportPanel/CostReportPanel/SketchEditorPanel、character-panel feature 版。
- **生成 UI 割裂**：双轨走 BeatReviewModal（拍预览大弹窗），引爆链走 420px 抽屉三闸门；"引擎开关"实际不分流调用。
- **伏笔（PlotLedger）完全没有 UI**——只在节拍预览的标签里露过脸。
- **样式双轨**：Tailwind 原子类与 CSS 变量混用；图标两套（Icon.vue/Icons.vue）。
- **SSE 消费是单例 composable**（useChapterGenerator），与编辑器状态耦合。

## 3. 信息架构

引入 `vue-router`，五个顶层目的地，左侧窄应用栏（App Rail，图标+文字）导航：

```
┌──────────────────────────────────────────────────────────┐
│ 架 │  书架 /library          书籍网格，新建向导入口        │
│ 写 │  写作台 /workspace/:bookId/:chapterId?   ★ 主视图    │
│ 纲 │  大纲板 /outline/:bookId                 卷弧章节卡   │
│ 设 │  设定中心 /bible/:bookId                 故事圣经     │
│ 数 │  数据   /insights/:bookId                成本与质量   │
└──────────────────────────────────────────────────────────┘
```

- **书架**：书籍卡片网格（封面色块+书名+进度+最近打开）；"新建书籍"**启用现成的 novel-wizard**（5 步向导早已写好，直接接入路由，结束落地写作台）。
- **大纲板**：卷/弧 → 章节卡的看板视图（卡片列=弧，卡=章节卡：标题/主旨/定档/状态徽标），拖拽排序；点卡进写作台。这是 Novelcrafter Grid 视图的对应物，承载 3.1 的层级大纲。
- **数据**：GenerationRun 成本报表 + 质量指标趋势（禁词命中率/高潮评分/断线数按章）+ 降级事件流。专业工具的可观测面。
- **设定中心**：见 §7。

## 4. 写作台（主视图）详细设计

三栏布局（可用 splitpanes，依赖已装未用）：

```
┌────────────┬──────────────────────────────────┬────────────────┐
│ 章节导航    │  章节卡横条（可折叠）               │ 智能副驾        │
│ (binder)   │  ┌──────────────────────────┐    │ (inspector)    │
│            │  │ TipTap 编辑器             │    │ 本章│结构│审校│速查│
│ 卷一        │  │                          │    │                │
│  第1章 ●    │  │  （正文，生成流式渲染）     │    │                │
│  第2章 ⚡8.5│  │                          │    │                │
│  第3章 ⚠2   │  │                          │    │                │
│  卷二        │  │                          │    │                │
│  …          │  └──────────────────────────┘    │                │
│ [+ 新建章节] │  状态栏：字数·档位·生成状态        │                │
└────────────┴──────────────────────────────────┴────────────────┘
```

### 4.1 左栏：章节导航（binder）
- 树：书 → 卷/弧 → 章节；拖拽调整顺序与归卷。
- 每章一行状态徽标（细线小图标，不喧宾夺主）：定档（高潮章●/转折◐/推进○/过渡—）、生成状态、**高潮评分**（如 ⚡8.5）、待处理审校问题数（⚠n）、新增伏笔标记。
- 底部"+ 新建章节"：先创建空章并引导填章节卡（AI 草拟 → 人改，见 4.2）。

### 4.2 中栏：章节卡横条 + 编辑器
- **章节卡横条**（核心输入面，F3）：编辑器顶部一条可折叠横条，字段：标题 / 一句话主旨 / 高潮点（可点编辑）/ 目标字数 / 节奏 / 档位 chip。默认折叠为一行摘要；展开即可编辑。**消灭 AgenticSettingsModal 大弹窗**——intent-driven 面板的精华（章节类型→档位、篇幅、补充说明）全部收敛到这里。
- **编辑器**：TipTap；生成流式文本以"待定稿样式"渲染（浅色底纹标识 AI 产物，用户润色后底纹消退——兼作"人工介入率"的可视化）；选中文本弹**浮动工具条**：润色 / 扩写 / 缩写 / 换语气（选区级改写，Sudowrite Rewrite 式）。
- **状态栏**：字数（含目标达成度）、档位、生成阶段、降级标记数。

### 4.3 右栏：智能副驾（inspector，四个 tab，可整栏收起）

| Tab | 内容 |
|---|---|
| **本章** | 生成主控：定档通知卡、「生成本章」按钮、生成参数折叠区、进行中的流程步骤（见 §5）、checkpoint 恢复入口 |
| **结构** | 铺垫结构图（§6）——生成前是确认点，生成后是审阅视图 |
| **审校** | 质量报告：高潮评分、指标达标条、问题清单（漏埋/泄底/未回收/文风），**点击问题→编辑器滚动并高亮对应原文**；每条可"去修复/忽略" |
| **速查** | 本章语境设定：出场角色卡（最新状态）、本章伏笔（含"本章埋设/本章回收"标记）、地点与资产；点角色卡跳到设定中心对应条目 |

## 5. 生成流程交互（统一引擎的前端映射）

**原则**：流程嵌入右栏「本章」tab，以步骤条呈现，**非模态**；确认点按档位自动开合。

### 5.1 流程展开（以转折章为例）

```
[生成本章] 点击
  ↓ ① 定档通知卡（非模态）
     "本章判定为【转折章】——依据：高潮强度 7 分 + 卷末第二章"
     [按此生成]  [改用其他档位 ▾]
  ↓ ② 确认点一：高潮点（卡片选择，可编辑，可自写）
     候选 A/B/C 各一张卡：描述 + 情绪目标 + 回答/开启的悬念
  ↓ ③ 确认点二：铺垫结构（「结构」tab 自动激活，可拖改，§6）
     [一键确认] 或编辑后确认
  ↓ ④ 确认点三：高潮段成稿（双候选左右对照视图，选一/编辑后冻结）
  ↓ ⑤ 生成中：步骤条实时阶段（蓄势段 1/2 → 铺陈段 1/3 → 组装 → 审校）
     正文流式入编辑器（待定稿样式）；可取消（checkpoint 保留）
  ↓ ⑥ 完成：「审校」tab 亮起问题数徽标 → 进入 §7 审校循环
  ↓ ⑦ 发布（沿用 PublishModal，回写进度可见：摘要/状态/伏笔登记 n 条）
```

- **过渡章**：②③④ 全部跳过，① 仅为通知——体验等同"一键生成"。
- **高潮章**：④ 为强制人工确认（全章唯一强制点），其余可快过。
- **飞行中事件**（中途升档建议/压抑校准/并章建议）：以通知卡插入流程步骤条，用户可采纳/忽略，不打断生成。
- **checkpoint 恢复**：中断后「本章」tab 显示"上次生成到蓄势段 2/3，[继续] [重新生成]"。

### 5.2 被替换/删除的旧交互

| 旧 | 新 |
|---|---|
| GenerationEngineSwitch（引擎开关） | 删除 → 定档 chip（§4.2）+ 定档通知卡 |
| BeatReviewModal（节拍大弹窗） | 删除 → 确认点二（铺垫结构图） |
| AgenticSettingsModal（90vh 参数弹窗） | 删除 → 章节卡横条 + 生成参数折叠区 |
| detonation-gate 420px 抽屉 | 重构 → 右栏步骤流（复用其 composable 逻辑与步骤组件，换容器） |
| WorkflowProgressGraph（两处重复展示） | 收敛 → 步骤条一处 |

## 6. 铺垫结构图（签名组件）

位置：右栏「结构」tab（可弹大到中栏宽度的专注模式）。

**形态**：横向阅读序时间轴——

```
 n1 ──→ n2 ──→ n3 ──→ n4 ──→ n5 ──→ ◆高潮
[铺垫][闲笔][发展][铺垫][蓄势]        │
 └──────────────╌╌╌ 回收于 n5 ╌╌╌╌┘
        距离标尺：  5    4    3    2    1    0
```

- **节点卡**：类型色（铺垫=靛蓝/发展=灰/误导=紫/闲笔=青绿），显示内容摘要、悬念标签、任务徽标（收拢/压抑/部分释放/闲笔）；双击内联编辑。
- **高潮卡**：右端金色，显示高潮点与情绪目标；可"更换高潮点"→ 确认后局部重长。
- **连线**：sets_up/payoff_of 弧线；hover 高亮一条因果链。
- **编辑**：拖拽改序、增删节点；一切编辑标记"已人工调整"并同步后端。
- **审校态**：生成审校后，问题节点带角标（漏埋=红/泄底=橙），点击跳到「审校」对应条目。
- 过渡章的扁平结构（2~3 节点）自动缩放视图，不空旷。

## 9. 交互细节

- **快捷键**：Ctrl+1/2/3/4 切副驾 tab；Ctrl+Enter 生成本章；Ctrl+Shift+Z 沉浸模式（保留现有 ZenMode，改为隐藏左右栏）；Esc 收起副驾；选区工具条跟随鼠标。
- **空状态**：每处空态给一句引导+一个主按钮（如无铺垫结构→"生成铺垫结构"；无伏笔→"伏笔会在生成后自动登记，也可手动添加"）。
- **危险操作**：换高潮点重长、重新生成、发布撤回——统一 ConfirmDialog。
- **Electron**：窗口最小宽 1200；三栏可拖拽，宽度记忆（useUiPrefs）。
- **Debug Prompt 窗口**：降级为设置内"开发者模式"开关，默认隐藏。

## 10. 设计系统（专业的视觉来源）

- **单一样式轨**：语义 token（--bg-surface/--bg-page/--text-ink/--text-muted/--accent/--border/--success/--warning/--danger）统一定义于 style.css，tailwind.config 映射为 `bg-surface/text-ink/accent` 等语义类；**禁止** `bg-[var(...)]` 与调色板直写混用（现有双色全量替换）。
- **字体**：界面 UI 用 Inter/系统 sans；**编辑器正文与章节卡用 Noto Serif SC**（写作感），正文字号 16-17px、行高 1.9、栏宽限 ~42em（长行不疲劳）。
- **AI 存在感**：AI 产物/进行中状态统一用 accent 色细线徽标；"待定稿"正文底纹用 accent 3% 透明度；chrome 界面零 emoji，图标收敛到一套（删 Icons.vue，保留 Icon.vue 并补齐）。
- **暗黑模式**：与浅色同 token 双套值，编辑器纸感在暗色下为"深牛皮纸"（沿用现有基调）。
- **动效**：仅 150ms ease 的淡入/位移；生成中的进度用文字阶段+细进度条，不用花哨动画。

## 11. 前端技术架构

### 11.1 features 重组

```
features/
├── app/            # App 外壳、AppRail、路由出口、全局 Toast/Confirm
├── library/        # 书架
├── workspace/      # 写作台：Binder / ChapterCardStrip / EditorArea / Inspector
├── generation/     # 生成流程：步骤流、三个确认点、铺垫结构图、审校报告、速写对照
├── outline/        # 大纲板看板
├── bible/          # 设定中心（characters/foreshadowing/worldview/style/assets/map/notes 子模块）
├── insights/       # 数据视图
└── shared/         # 面板原语（现 components/panels）、Icon、编辑器扩展、types
```

- `components/` 收缩为纯 UI 原语（Icon/Toast/ConfirmDialog/panels/），**全量修复分层违规**（CharacterPanel/InspirationModal/WorldviewSettings/GoldenSnippetsManager/MapSettings/StyleCardManager/SettingsPanel/RichTextEditor/AppContainer 的 services 直引）。
- `useChapterEditorContainer`（628 行）与 `AppContainer`（1663 行）按职责拆分；`useChapterGenerator` 与 `useDetonationGate` 合并为 `useGenerationSession`（统一 SSE v3 会话：定档/确认点/分区进度/飞行中事件/质量报告）。
- `services/api/domain/index.ts`（946 行）按域拆分：book/chapter/generation/bible(角色/伏笔/世界观/资产/地图)/system；删除 `services/{domain,stream,transport}` 三个空壳 re-export。
- 状态：维持 composables（不引 Pinia），但约定"会话单例 composable + 视图局部状态"两层；编辑器内容与生成流式文本分离存储。

### 11.2 SSE v3 事件映射

新增/变更事件：`TIER_DECIDED`（定档+理由）、`PAYLOAD_CANDIDATES`、`SETUP_GRAPH`、`PAYLOAD_TEXT（双候选）`、`SEGMENT_PROGRESS（zone+index/total）`、`SKETCH_BASELINE`、`GRAPH_AUDIT`、`ANCHORED_AUDIT（findings 带 offset）`、`CLIMAX_SCORE`、`TIER_UPGRADE_SUGGEST`（飞行中）、`MERGE_CHAPTER_SUGGEST`、`DEGRADED`、`DONE`。`useGenerationSession` 统一解析为会话状态机，UI 只订阅状态不接原始事件。

### 11.3 清理清单（重构时删除/合并）

删除：GenerationEngineSwitch、BeatReviewModal、AgenticSettingsModal、Icons.vue、intent-driven 四个孤儿组件、`services/` 三个空壳目录。
接入：novel-wizard（书架新建入口）、QualityReportPanel/CostReportPanel（数据视图参考实现）、SketchEditorPanel（改造为速写对照视图）、character-panel feature 版（替换 components 旧版）。

## 12. 迁移路线（每步可独立上线）

| 阶段 | 内容 | 验收 |
|---|---|---|
| **F1 外壳** | 引入路由与 AppRail；书架页；现有 9 个悬浮 tab 原样迁入设定中心路由；novel-wizard 接入 | 旧功能全部可用，浮动栏删除 |
| **F2 写作台** | 三栏重构（binder/章节卡横条/inspector）；章节列表加状态徽标；删除引擎开关与两个大弹窗 | 编辑器全流程可用 |
| **F3 生成流程** | useGenerationSession 统一会话；步骤流+三确认点；铺垫结构图 v1（只读确认+编辑）；双候选对照 | auto 定档一章端到端跑通 |
| **F4 审校与伏笔** | 审校 tab（问题定位跳转）；伏笔账本面板；选区改写工具条；速写对照视图 | 审校问题可点击定位、可修复 |
| **F5 打磨** | domain 拆分、分层违规清零、样式单轨化、图标统一、数据视图、性能（虚拟滚动长章节树） | 清理清单全勾 |

与后端 3.1 迁移（`generation-v3.1-unified.md` §11 Step 1-6）对齐：F3 依赖后端 Step 4（端点合并），F4 依赖 Step 5（飞行中事件）。F1/F2 可先行，不依赖后端。
