TRUTH LAYER · UX REDESIGN

把「AI 替你守住」写到台面上

真相层对作者的价值，一句话就说得清：记在这里的秘密，AI 写作时绝不剧透、盯着你别写漏、到点提醒该抖了。 现状把这句话埋在了十一个系统词汇和一个永远长不出内容的图谱下面——作者盯着「两面/揭示/钩子/连锁分析/一度 0」， 看不出记这个有什么用。本稿不动一个后端字段、不删一行数据，只做三件事：摘图谱、翻人话、把价值写在使用现场。

01 · DIAGNOSIS为什么「完全不知道是什么」

三个病因都是实证，不是口味问题。

病因一
图谱是空转透镜

「因果图谱」只读，但全系统没有任何入口能建边：前端建边函数 createEdge 零组件调用，候选转正只建节点不建边，后端无自动推导。于是它永远是一屏孤立圆点——截图里的「3」「2」两个大圆球不是数据太少，是它的设计上限。依赖边扩散的「连锁分析」同样永远答「没有波及」。

病因二
每个词都要查词典

两面 / 表 / 里 / 揭示 / 钩子·强度·埋设手法 / 连锁分析 / 查片段 / 一度 0——一屏十一个系统词。而作者语言里只有两个问题：「读者现在知道吗？」「打算什么时候抖出来？」字段摆了一墙，问题没人问。

病因三
价值不在现场

守秘密（生成上下文 secrets 通道）、防写漏（完稿体检比对泄密）、到点提醒（写作台感知带）——全部发生在别的界面。账本和详情里没有一个字告诉作者「记这个会发生什么」，记了像没记。

附带一笔重复建设：「钩子」类型（强度/状态/埋设手法三字段）与伏笔账本（埋设/回收/预期章）是同一回事的两份表单。 代码注释里早已写明「C2 并入伏笔账本后退役」，界面至今还在收两份租——本轮一并退役，存量由既有「迁入世界对象」面板承接。

02 · THESIS一句话立论与三条原则

真相 = 作者知道、读者暂时不知道的事。
记它只有一个理由——AI 替你守住。
不剧透（secrets 通道 + 泄密闸）· 防写漏（完稿体检比对）· 到点提醒（感知带揭示临近）
一、问作者的问题，不摆系统的字段

详情抽屉按两问组织：「读者现在知道吗？」「打算怎么抖出来？」所有字段挂进这两问，问不出归属的字段不进界面。

二、价值写在使用现场

账本标题下常驻一句「记在这里的，AI 替你守住」；填「第几章揭」时当场预告「写到第 N−2 章感知带会提醒你」——规则第一次有了回声。

三、摘掉的比新增的重要

图谱、连锁分析、钩子区三块死重先摘，再谈美化。每少一个永远答「没有」的按钮，剩下每个按钮都更可信。

03 · IA信息架构：保留、重排与退役

表面处置设计
图标栏「真相」格保留 位置与角标不动。tooltip 从「表（读者所见）与里（作者真相）的账本」改 「真相账本——读者知道与不知道的事，秘密 AI 替你守住」（第一触点就把价值说掉）。
真相账本抽屉重排 场景 A。标题下常驻一句价值句；主按钮只剩「＋ 记一条真相」；两个次动作（从章节找漏记 / 旧条目挂接）收为小字行；行内「→30章」改「第 30 章揭」。
真相详情抽屉重排 场景 B。按「读者现在知道吗 / 打算怎么抖出来」两问组织；动作行只剩「贴段正文查泄密」与「删除」。失焦即存不变。
因果图谱模态退役 两个入口（账本底部「查看因果图谱 ↗」、详情「因果图谱 · 一度 N」）摘除，组件删除。后端边表与 CRUD 路由保留——零数据风险，存量老书的历史边仍可被 API 读到；未来若有自动推边能力再议复活。
连锁分析退役 随图谱一并摘。它沿因果边扩散——边永远为零，它永远答「没有波及」，留着是谎话。后端 POST /impact/{id} 保留。
查片段保留 改名「贴段正文查泄密」。它是纯节点短语比对，不依赖边，是真能用的能力——留在详情动作行。
「钩子」字段区退役 强度/状态/埋设手法三字段从详情删除。存量 hook 条目在详情顶部给一行指引：「这是旧『钩子』条目，建议迁入伏笔账本」→ 复用账本既有迁移面板。
实体抽屉「读者认知」对齐 文案与详情抽屉同口径：表/里小徽标保留，标题改人话（「读者目前看到的版本」「实际真相」）。交互零改动。
提醒与闸门零改动 感知带揭示提醒（≤2 章）、时间轴揭示朱点、名签朱点、secrets 通道、完稿泄密比对、ghost_guard 泄密闸——本稿全部不动，纯前端表面重修。

06 · FLOWS关键流程走查

记一条秘密（流程不变，第一次就懂）
①账本「＋ 记一条真相」→ 写「林尘其实是局长的私生子」，Enter； ②不弹任何面板——行落账顶闪朱 + toast「已记下——AI 会替你守住」，记账闭环到此为止（2026-09-03 实测修正：曾 Enter 后自动滑出详情表单，作者「输入一段文字后就跳出这个面板，非常令人迷惑」）； ③想补「读者看到的版本 / 抖出来的计划」时主动点行——详情第一眼只剩「读者知道吗 + 表里两面」，问二与标签收进「补充」折叠区，有值自动展开。
到点提醒（字段第一次有了回声）
①详情里填「第 30 章揭」，旁边当场出小字：「写到第 28 章时，写作台会提醒你」； ②真写到第 28 章，感知带如期出现「揭示计划临近：预期第 30 章（还差 2 章）」——作者亲眼看到账本长脚走回写作现场，下一条真相就愿意记了。
查泄密（保留能力的真实用法）
①详情「贴段正文查泄密」→ 展开贴片框；②贴入要发布的段落点「检查」； ③命中列出「【林尘】关键短语出现在文本中：私生子」——纯节点短语比对，不依赖任何边。

07 · OPEN待拍板清单

分歧点本稿建议说明
因果图谱去留退役（摘入口 + 删组件）建边零入口是代码事实，不是数据太少。后端边表/路由保留，存量数据零风险。2026-08-17 拍板曾定「保留为只读查看器」——彼时假设边会由提取流程产生，该假设已被证伪（候选转正只建节点）。
连锁分析去留随图谱退役沿边扩散，边恒为零则恒答「没有」。若拍板保留图谱，此件一并保留。
「钩子」区退役与伏笔账本重复建设，代码注释早已写明退役方向。存量 hook 条目给迁移指引行，不强行自动迁移。
常驻价值句文案见文案表末行「不剧透、防写漏、到点提醒该抖了」三个承诺都有既有实现背书，无虚词；措辞可再酌。
表/里徽标去留保留小徽标品牌词不丢（柔化轮定档），但退居卡面角落；主标题一律人话。
类型下拉降级挂接条目只读C2 起类型由挂接对象推演，下拉对挂接条目是矛盾源；自由叙事条目保留可改。
录入即弹详情（实测修正）已拍板：不弹2026-09-03 真实使用实测否决了 C1 沿袭下来的「Enter 建条并开详情」——记账是轻动作，弹表单是重预期违背。改为行内闪朱 + toast 闭环；详情只在主动点行时打开，且补充区（问二/标签）默认折叠。

设计稿为纯静态 HTML（零依赖、零素材），沿用活舆图 M6 视觉令牌（暖纸/墨色/朱砂、衬线名签），仅作方向评审，不代表最终实现细节。
红线：本稿不动任何后端字段与提醒/闸门规则；品牌词（真相/表/里/秘密/半露/公开）保留；失焦即存交互不变。
