CANON FUSION · UX STUDIES

真相层并入活舆图

世界页已经回答「世界里发生了什么」；Canon 一直单独回答「读者该知道什么」。 本设计把后者并进前者：同一个对象，事态面之上长出读者认知面——旧「脑图」页退役， 作者从此只维护一本账。架构与数据设计见 docs/canon-world-fusion.md，本稿只管「作者看到什么、怎么动手」。

01 · MODEL两层模型，一句话立论

事态层是上帝视角的状态机，不关心读者；信息层是叙事视角的知识边界，不改变世界。 融合不是「把 Canon 搬进世界页」，是给世界页的每个对象补上第二面。

信息层 · 真相（并入的对象）
回答：读者该知道什么 / 什么绝不能写出来
  • 表（读者所见）↔ 里（作者真相），差集 = 秘密
  • 揭示计划：差集预定在 第 N 章 收敛
  • 泄密检测 / 感知带 / 审计，全在这一层
事态层 · 活舆图（已有，不动）
回答：发生了什么 / 此刻世界什么状态
  • 事件溯源推演：位置/生死/疆域/关系
  • 地图管空间 · 时间轴管时序 · 抽屉管账本
  • 与读者认知无关，全部保持现状
表 · 读者目前所见
普通纸面。读者从正文里读到的版本——可能是截断的、伪装的、错认的。空 = 读者一无所知。
「废墟区捡回来的机修工，手艺极好，沉默寡言。」
里 · 作者知道的真相
朱晕纸面 + 「密」印。生成时绝不许直接写出，只作隐藏动机；泄密会在完稿审计报警。
「统合局局长的私生子，生母因『素壤计划』被灭口。」

术语落在「表里」二字上——表里不一正是秘密的本义，作者无需学习任何系统词汇。 三态徽标：● 秘密（读者全然不知）· ● 半露（读者见过伪装版）· ● 公开（已建立事实，AI 必须遵守）。

03 · IA信息架构：入口、去处与退役

表面设计
世界页 · 图标栏第四格「真相 ◉」，排「期待」之后、实体分组之前——与伏笔/期待同属账本族（读者视角的账），与地点/事件/角色（世界结构的账）以分隔线相隔。
真相账本抽屉主过滤轴 = 表里三态（不是类型——作者翻账时的问题是「读者还不知道什么」）。行 = 对象名（衬线）+ 类型徽标 + 真相首行 + 揭示章。底部「因果图谱 ↗」。
真相详情抽屉点行滑入，与账本格互斥（同伏笔）。头部对象名（可跳实体）+ 三态切换；「两面」区就地编辑失焦即存；「揭示」区计划 + 章号；「关联」区图谱跳转。
实体详情抽屉 · 读者认知分区C2：档案/编年史之后的第四分区，默认折叠。从这里记的秘密自动挂本实体——名字永不漂移，泄密检测不失效。空态一行虚线按钮，不逼填表。
伏笔详情 · 真相面C2：伏笔天然是信息层对象（埋设=建差集，回收=收敛）。表/里两行可选字段，不填仍是普通伏笔。原 Canon 的 hook 节点由此并入。
因果图谱模态透镜而非画布：从账本底部或详情「关联」唤起。形状=对象族，朱描边=有秘密。只看+聚焦+跳转编辑，不在图上编辑。
写作台副驾「章节」tab 的「前往 Canon 脑图」改为「在世界页查看真相」→ 深链 ?panel=canon。感知带 / 泄密审计 / 高亮零改动。
退役AppRail「脑图」项移除；/canon/:bookId 重定向至世界页（旧深链不断）；CanonView 三 tab 由 真相账本 / 因果图谱 / 伏笔账本 分别接替。

04 · SCENES三张场景稿

场景 A

真相账本与表里两面

主入口。账本格的列表节奏，详情抽屉的一页两面；句子优先录入——写下这句话就行。

  • 过滤轴 = 秘密 / 半露 / 公开（表里三态）
  • 行 = 对象名 + 真相首行 + 揭示章 →
  • 「＋ 记一条真相」：句子即真相全文，主语自动挂对象
  • 详情：表（纸面）/ 里（朱晕 + 密印 + 泄密警示）
  • 就地编辑失焦即存，无保存按钮

场景 B

实体的读者认知面

C2 终态：秘密跟着人走。实体档案长出第四分区，舆图名签点朱。

  • 实体级 visibility 开关退役，归位为每条真相的表里

场景 C

因果图谱透镜

旧脑图降格为查看器，住进模态：看结构的地方，不是改数据的地方。

  • 形状=对象族 ●◆▲◉▣，朱描边=有秘密
  • 边六型换作者语言：因果/先后/暗示/铺垫/回收/呼应
  • 点节点出信息条：真相摘要 + 跳回真相详情编辑
  • 只看秘密 / 只看伏笔 / 一度邻居聚焦
  • 无常驻入口——透镜是拿来用的，不是拿来供的

05 · FLOWS关键流程走查

记一条秘密（句子优先，零翻译）
①真相账本底部「＋ 记一条真相」→ 内联输入框，光标已在； ②写「林尘其实是局长的私生子」，Enter——句子本身就是「里」的全文，没有先建节点再填字段； ③系统按实体名/别名匹配主语（可改挂/可不挂，挂不上就是自由叙事条目）； ④详情抽屉直接滑入、焦点落在「里」面板——顺手补「表」（读者目前所见）与揭示计划，不补也无妨。
给这个人记秘密（C2，从实体来）
①舆图点开实体（名签有朱点 = 已有秘密在身）；②「读者认知」分区 →「＋ 记一条秘密」→ ③直接进「里」编辑，对象已挂好，不问主语是谁。反向亦可：真相详情头部点对象名，跳回实体档案。
揭示临近（C3）
计划揭示章 − 当前写作章 ≤ 3 时：详情里「还有 N 章」转金；写作台感知带出现「针脚伏笔临近揭示计划（→12章）」—— 揭示计划从「记了就忘的字段」变成会主动回来的提醒。已揭示的条目一键转「公开」，从秘密账里销账。
旧账迁移（C2，作者确认制）
首次打开真相账本时若检测到旧 Canon 数据：顶部一条安静的黄条「检出旧脑图 23 条 · 核对挂接」→ 迁移预览按名字匹配世界实体/伏笔（含别名），逐条 ✓/✗/改挂，不匹配的保留为自由叙事条目——没有静默改库。

06 · DECIDED评审拍板记录（2026-08-17）

分歧点拍板说明
命名「真相」 与 伏笔/期待 同属账本族；全套用户术语随此定稿——表 / 里、秘密 / 半露 / 公开、真相账本、因果图谱。
半露的门槛三态 chips 直切 维持本稿方案（作者无倾向，从稿）：三态外显、一键即切；不采用「表非空自动推导半露」的隐式规则。
账本角标总条数 与伏笔/期待格一致；秘密数退居抽屉头部「柒 条 · 秘密 叁」的次级信息位，朱字仍在。
因果图谱去留保留，定位只读查看器 按场景 C 落地（只看不编、无常驻入口、从账本/详情唤起）；不预设「打开率趋零即退役」，使用观察照做。
「表」空态在写作现场的提示暂不决策 「读者还不知道这件事」的浮卡提示属写作桥 W5 之后的增量，届时再议。

设计稿为纯静态 HTML（零依赖、零素材），沿用活舆图 M6 视觉令牌（暖纸/墨色/朱砂、衬线名签），仅作方向评审，不代表最终实现细节。
数据与架构设计见 docs/canon-world-fusion.md（C1/C2/C3 分期）；本稿各场景与分期的对应关系已标注在每张场景稿页脚。
