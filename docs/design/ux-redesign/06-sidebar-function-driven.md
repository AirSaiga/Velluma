## 0. 诊断：为什么 05 期是「重新排列组合」

05 期把功能的**容器**换了一遍（binder→书脊+抽屉、感知带→批注层、抽屉→图标栏+面板），但每个功能的**组织方式**原封未动：章节列表还是那份列表、四 tab 还是那四块内容、提醒卡还是那些卡——只是从一种栏搬进另一种栏。用户截图的两个症状，根因都在「形态与功能的真实密度/时机不匹配」：

| 截图症状 | 根因（file:line 实锤） |
|---|---|
| 书脊 44px 竖栏 90% 空白 | 五元素里**两个是重复的**：返回书架 = AppRail 既有「书架」入口（`features/app/containers/AppRail.vue:30`）；章号「12/34」= 页头已有 `第N章` label（`ChapterEditorView.vue:125`）。真正独有的只有三个动作（‹ › ＋）——三个按钮的信息量是一条**横排**，不是一条竖栏。 |
| 打算面板头与内容第一行几乎逐字重复 | 面板制给每个功能造了一个头（`WorkspaceView.vue:404` PANEL_META.planning.sub「写之前想一想：这章讲什么、哪些情节非写不可——AI 会照着帮你」），而功能组件**自己本来就有头**（`SpinePanel.vue:106` spine-hint「写之前记两句：这章讲什么、哪些情节非写不可」）。两层 chrome 说同一句话。 |
| 打算面板 400px×全高摊大饼 | 「打算」的内容总量 = 一行意图 + ≤5 枚 chips + 一个建议钮 + 一个 textarea——约 200px 高的表单，被装进全高面板，底部再塞一张搬家的「本章文风」卡（`InspectorPanel.vue:489-513`）填空。 |
| 功能归属越来越怪 | 05 期 §5.4 的搬家判断（文风塞打算底、真相塞此刻底）只回答了「哪个面板还有空位」，没回答「作者在什么时候需要它」。 |

本期的做法：先把每个功能的**时机×频率×内容量**查实（§1），再让形态从功能里长出来（§2），最后才画样子（§3）。

### 1.4 调研关键发现（设计支点）

1. **两条常驻竖栏都没有功能依据**：左栏五元素里两个重复（返回书架/章号），右栏三图标里没有一个功能是「写中每分钟要扫」的——真正的写中常驻需求（进度/时空/提醒）现在反而全锁在面板里或漂在纸外。
2. **「打算」的写前主场已经在纸面**（点火卡），面板形态只服务「写前集中填 1-2 分钟」一个瞬间，其余生命周期（写中打勾=spine_progress 便签、写后对账=finish 报告 coverage/spine_note）都在别的形态里。
3. **副标题重复是结构病不是文案病**：面板制给功能再造一个头，功能组件自己有头——消灭重复的正解是消灭多余的头，不是改词。
4. **「此刻」的答案是一行字**（几点/在哪/在场几人），一屏详情是第二屏——摘要与详情应该分层，不该一起锁在面板里。
5. **检查域是唯一配拥有面板的功能**（一屏+内容量、写后对照正文修改要 pin）；收件箱是推送型裁决（事件驱动、批量、裁完即走）；文风/真相/AI 视角是极低频链接与观测。

## 2. 功能分组与承载推导

### 2.1 推导尺：时机 × 频率 × 内容量 → 四种形态

| 形态 | 判据 | 成本纪律 |
|---|---|---|
| **常驻**（顶条/章首行/纸边） | 写中可能随时扫一眼 **且** 一行/一卡可容 | 超过一行就裁到一行，详情交召唤 |
| **召唤**（浮层/面板） | 内容量一屏级、任务有明确起止（挑完/裁完/读完即走） | 默认关闭；开时有明确意图与落点 |
| **推送**（徽章+toast+peek） | 事件驱动、需要作者裁决 | 不常驻占面，到了才亮 |
| **嵌入正文流**（纸面章首） | 属于「这一章」本身的属性（标题/打算/时空） | 与纸面同排印语言，不是浮卡 |

### 2.2 三问三答（本期推导核心）

**① 章节导航需要多少常驻面积？——零栏。**
常驻需求 = L1（翻页）+L2（定位感知），是横向一行的信息量，天然落在页头（F5 已有章号，同组团聚）。L3 列表是「召唤-挑选-消失」，05 期的目录抽屉形态本身成立（保留），只是触发点不该配一条常驻书脊。书脊 44px 是「三个按钮+两个重复」伪装成的栏——**删除，功能并入顶条**（§3.1）。

**② 「打算」的真实使用曲线？——写前集中填一次，写中只读投影，写后进报告。**
证据链：写前=点火卡（F4）已是第一现场（意图+建议全有）；写中=系统早已把进度投影成 spine_progress 便签（F2）挂在纸边、把临近锚点投影成走向卡——**作者写中不编辑打算，只确认进度**；写中唯一的回写动作是「不对」纠正（一行）；写后=finish 报告附 coverage/spine_note。
结论：打算是「这一章的属性」，不是「助手的工作区」——**嵌入正文流（纸面章首卡，§3.2）**，默认折叠成一行（= 旧便签的同源取代），展开即完整表单。面板形态是错配：它假设「需要一块独立工作区反复进出」，真实曲线是「写前一次 + 写中扫一眼」。大纲（R2）/建议（R3）/纠正（R4）/本章文风（R5）同属写前配置，随行进章首卡。

**③ 写中真正需要常驻可见的是什么？——四样，全在纸面/纸边/顶条，零侧栏。**
- 打算进度（一行）→ 章首折叠行（新）
- 故事时空（一行）→ 章首时空戳行（新，R6 摘要层）
- 感知提醒（锚定卡）→ 纸边批注层（F1 保留，便签退役后更纯）
- AI 在干什么（状态丸）→ 顶条（F6 保留）
截图证明现在它们要么不存在（时空摘要）、要么锁在 400px 面板里（打算/切片）、要么漂在纸外（便签）。本期把它们全部落到纸面章首与纸边。

## 7. 考虑过并否决（防施工走样）

1. **右栏保留 44px 图标栏、只改面板内容——否决。** 图标栏三个图标里没有一个功能是写中高频（§1.4-1）；栏的存在本身即 05 期病。入口收进工作条一个「助手」钮+徽章，发现性等价（常驻可见、有货亮灯），面积省 44px。
2. **章节目录做成工作条下拉——否决（维持 05 §12-3 判断）。** 长列表+多选+底区动作不适合下拉；抽屉形态成立，只换触发点。
3. **打算卡默认展开——否决。** 写前集中填完即回归一行；默认展开=写中每章顶半屏表单，重蹈摊大饼。写前场景由点火卡（空章）与 teaser（建议到达）承担展开动机。
4. **时空戳放工作条——否决。** 工作条是「操作与反馈」语言，时空戳是「章的题署」语言；且工作条右簇已满，纸面章首与标题同列是书稿传统位置，零学习成本。
5. **检查报告模态化——维持 03/05 期判断不做。** 报告要对照正文改，模态遮纸；pin 面板是正确形态。宽版阅读诉求待真实使用数据再议。
6. **新增翻章快捷键（Ctrl+↑/↓）——否决。** 七键契约的纯净性优先；工作条 ‹ › + 目录已覆盖。
