# 09 · AI 视角面板重设计

> 状态：设计定稿，待施工 · 范围：写作台右缘助手栏「AI 视角」分区（Ctrl+5）· 现状症结：用户评价「看着很累」
> 红线继承：所见即所读（保字重排，不改写不删减）、块序=注入序、五档模式/刷新/切章复位、空块补录引导、预算可见、健康与世界模型保留、零新依赖、380px 固定宽、双主题。

---

## 0. 设计立场（一句话）

这个面板是**读给作者看的体检报告，不是读给机器看的日志**——现状把「AI 读的原文」直接怼到作者脸上（等宽 11px 直出 + 每卡内部滚动 + 全展开），重设计的核心动作只有三个：**结构化排版保字渲染、全部默认折叠只留头行、三段分组让注入序可感知**。

---

## 1. 诊断：为什么累

### 1.1 视觉层

| 症状 | 截图对应 | 根因 |
|---|---|---|
| 文字墙 | 每块正文等宽 11px、`pre-wrap` + `break-all` 直出，中文设定文以代码脸出现 | 块正文是**中文叙述文**（档案、世界观、画像），却用了**代码的字体和字号**——中文等宽小字是可读性最差的组合 |
| 字号单阶层 | 全面板几乎全是 0.6875rem（11px），层级只靠颜色和透明度撑 | 没有字号阶梯，眼睛无法靠「大小」预判信息权重，只能逐行扫 |
| 视觉权重失衡 | 紫色描边大按钮「AI 此刻读到的（预览）」是全页最重的元素，但它只是个开关 | 装饰性权重 > 内容性权重，第一眼落到按钮而不是数据 |
| 徽标噪声 | 每卡右上角一个描边胶囊「知识平面 · 世界实体」，14 个胶囊连成一列竖点阵 | 胶囊是「强身份」控件，被当成普通元数据用；且「知识平面」是内部黑话 |
| 预算条位置语义弱 | 3px 细条挤在标题行下，与「N 字」分居两行 | 占用比是调参界面最重要的数字之一，却是最弱的视觉 |

### 1.2 交互层

- **全展开 + 无折叠**：一开就是 14 张卡全部摊开，面板滚不到底。作者 80% 的问题（这次读到什么、占多少、来自哪）其实只需要**头行**就能回答，却被迫滚过全部正文。
- **嵌套滚动**：每卡正文 `max-height: 10rem; overflow-y: auto`——滚动套滚动，滚轮在卡片边界会「卡住」，长档案读起来是反复的滚轮博弈。这是「累」的交互主犯。
- **模式切换无反馈**：切档后旧数据呆立到新数据替换，中途没有任何「正在重读」的信号，不知道点了有没有用。
- **双层折叠嵌套**：先点大按钮展开分区，再面对 14 张摊开的卡——「打开面板」这个动作没有直接兑现内容。

### 1.3 布局层

- **单列平铺无结构**：汇总行、五个胶囊、14 张卡、健康条、世界模型按钮全串在一条流里，没有分节。「事实层前于文风层」这个有意设计的注入序，在视觉上完全感知不到——14 张同款卡片连排，序只是隐含的。
- **三要件无视觉分层**：主件（所见预览）、条件件（健康告警）、次要件（世界模型）占据同样的视觉重量与位置语法，作者每次都要自己定位。
- **元数据一行挤四样**：标题 + N 字 + 来源胶囊 + 预算条 + 被裁提示，在 352px 净宽里五者换行纠缠，头行经常折成两三行。

## 2. 信息架构重排

### 2.1 这一页要回答的四个问题（按作者实际追问顺序）

1. **「AI 这次一共读了多少、健康状况如何？」**——进面板第一眼。汇总数字 + 条件置顶的健康横幅。
2. **「每一块是什么、占多少、来自哪页、有没有被裁？」**——块头行全部回答，不需要展开。这是 80% 场景。
3. **「某一块到底写了什么字？」**——按需点开单块，保字排版阅读。这是 20% 场景，必须走得快、读得舒服。
4. **「AI 肚子里还记了什么账？」**——世界模型快照，最次，底部折叠。

次要信息降级路径：来源胶囊降为头行尾部纯文字；说明行压为一句话；「未配置」块从卡片降为单行虚线行；世界模型从按钮+pre dump 降为底部折叠卡。

### 2.2 结构重排（自上而下）

```
1. [条件] 健康横幅 —— 有错才出现，置顶（信任问题最先看到）
2. 主件「AI 此刻读到的」 —— 分区常开，去掉大按钮
   ├ 汇总两行（总量 + 时刻/来源 + 刷新 + 原文对照开关）
   ├ 模式五档胶囊
   ├ 段一「事实与设定」（8 块，注入序 1-8）
   ├ 段二「约束与记忆」（3 块，注入序 9-11）
   └ 段三「文风与笔感」（3 块，注入序 12-14）
3. 次件「AI 眼中的世界」 —— 底部折叠卡，结构化摘要
```

段切分严格沿真实注入序切段、不重排：场景身份 / 本章打算 / 在场与相关 / 实体称呼 / Canon 图谱 / 私有设定 / 世界观 / 人物关系 → **事实与设定**；禁词约束 / 前情回响 / 空间常识 → **约束与记忆**；文风画像 / 笔迹示范 / 白描封杀令 → **文风与笔感**。段是**视觉切分不是交互容器**（段 label 不可折叠，块才是折叠单元），避免两层折叠。安全网：前端维护 key→段 映射表，未映射的 key 追加在「文风与笔感」之后的「其他」段。

## 4. 交互规格

### 4.1 展开与折叠

- **分区常开**：删除现状的紫色大按钮。进入「AI 视角」分区即见汇总+模式+折叠块列表。数据获取语义从「点大按钮首次拉取」改为「**activeTab 切到 debug 时若无数据则拉一次**」（InspectorPanel 内一个 watch，节流语义不变：拉过就不再自动拉，之后靠手动刷新）。
- **块默认全部折叠，唯「场景身份」默认展开**：它恒居注入序首位、内容短，展开它让「保字排版」效果第一眼可见（示范作用），其余 13 块折叠为头行。
- **头行整行可点**（含空白处），箭头 `▸/▾` 随动；空块不可展开、无箭头。
- **展开动画**：`grid-template-rows: 0fr → 1fr` 过渡 0.2s（无依赖，见 §6 CSS 片段）。
- **展开后视口锚定**：若卡片底边超出面板可视区，调 `scrollIntoView({ block: 'nearest' })` 只滚面板不滚页面。
- **模式切换保留块的展开状态**：作者的典型场景是「切到拼画面看差异」——切换重拉数据期间已展开的块保持展开，直接对比。切章才复位（全折叠回默认）。
- **块级展开状态是组件内 `ref<Set<string>>`，不持久化、不入 localStorage**（对齐切章复位红线；启动脚本换 origin 的既往教训）。

### 4.2 长内容处理（替代嵌套滚动）

**方案：折叠即限额，展开即全量。** 折叠态头行恒 1.75rem——再长的块也不占位；展开后正文**不设 max-height、不设 overflow**，完整流式渲染，滚动交给面板自身的单一滚动条（一个滚动语境，无嵌套博弈）。长档案一次读完，收起即走。配「原文」对照开关兜底极长块（见 §5）。不采用「展开也限高+展开更多」——那仍是嵌套滚动的变体。

### 4.3 模式切换与刷新反馈

- 切模式 / 点刷新：**保留旧块列表，整体 `opacity: 0.5` + `pointer-events: none`**，汇总行下方出现一条 2px 不定态扫描条（accent 色，CSS 动画）+「重新读取中…」小字。数据到达后替换、恢复透明度。不清空、不闪骨架——布局零跳动。
- 首次加载（无旧数据）才用骨架：三个段 label 预置 + 5 个块头行占位（pulse）。

### 4.4 空态 / 错误态

- 未选章节：沿用壳的「从左侧选择一个章节。」。
- 请求失败：单张 danger 边框卡「读取失败：{msg}」+「重试」按钮（重试=再次 emit refresh）。
- 空块：见 §5.4——单行虚线行，引导文案随行。
- 健康横幅：`componentErrors` 为空则整块不渲染（现有语义不变）；有错折叠为「N 个辅助功能最近出错」，展开见明细，明细每行 = 组件名（600）+ 相对时间（muted）+ 错误摘要（11px，超长截断，title 悬停全文）。

## 5. 块正文保字排版方案（核心）

### 5.1 原则

「所见即所读」的可执行定义：**除结构标记（`#`、行首 `-` 、场景块的 `｜` 分隔符、缩进空格、换行）可转为排版结构外，其余任何字符不增、不删、不改写**。内联标记（`【…】〔…〕`）只做样式包裹，字符原样保留。另设全局「原文」对照开关：开启后所有块正文回到等宽 pre 直出（即现状渲染），作者可随时逐字核对——这是信任的逃生舱，也是解析不完美时的总兜底。

### 5.2 解析规则伪代码

```
函数 parseBlockContent(content) → BlockDoc:
  blocks = []; prevList = null
  对 content 按行迭代:
    1. 行匹配 /^# (.+)$/            → 节点 {type:'heading', text:捕获组}     # 弱小节标题
    2. 行匹配 /^- (.+)$/            → 节点 {type:'item',  text:捕获组};     # 列表项
                                       prevList = 本节点
    3. 行匹配 /^(\s{1,2})(.+)$/ 且 prevList 存在
                                    → 追加为 prevList 的 {type:'profile',
                                       text:捕获组2}                        # 缩进档案体
                                       （档案体多行时逐行追加为独立 profile
                                        节点，渲染时视觉连续）
    4. 行匹配 /^注：(.+)$/           → 节点 {type:'note', text:整行}         # 尾注
    5. 行匹配 /^([^：]+)：(.+)$/ 且本块 key=='scene'
                                    → 节点 {type:'kv', k:捕获组1, v:捕获组2} # 场景身份按：切
                                       （先按 ｜ 切分为段，再对每段套本规则；
                                         无冒号的段 → {type:'plain'}）
    6. 行匹配 /^【此刻·切记】/        → 节点 {type:'kv', k:'此刻·切记',
                                       v:去前缀后按 ｜ 切分}                 # recency 钉
    7. 其余                          → 节点 {type:'plain', text:整行}       # 兜底原样
  对每个节点做行内标记切分:
    inlineParse(text) → [{text}, {mark:'〔在场〕'}, {mark:'【此刻·…】'},
                         {mark:'【已死亡·…】'}, {text}, …]
    规则：按 /〔[^〕]*〕|【[^】]*】/ 切段，括号内容整段为 mark；其余为纯文本
  返回 blocks（行序 = 原文行序，永不重排行）

解析器特征：纯函数、行级保守——只认上表 7 种确定形态，
任何不确定的行落到 plain，plain 按原文等宽渲染（见 5.4）。
```

### 5.3 渲染映射表

| 原文形态 | 渲染结果 | 字符处理 |
|---|---|---|
| `# 标题（括号说明）` | 块内首行弱小节标题：0.6875rem / 600 / `--text-secondary` | `#` 与其后空格丢弃（结构标记），其余保留 |
| `- 周砚〔在场〕【此刻·t=N】（别名：X）` | 列表行：2px 圆点（`li::before`）+ 名字 0.75rem/600/primary；`〔在场〕`→ok 色小 chip；`【此刻·…】`→中性 chip（`--bg-tertiary` 底 + `--text-secondary` 字 + 等宽数字）；`（别名：…）`→0.6875rem muted 原文 | `-` 丢弃；mark 字符**原样保留在 chip 内**；别名括号字符保留 |
| `【已死亡·不得出场、不得开口】` | danger 色粗体 chip | 字符原样保留 |
| `  档案（作者录入，未删节）：` + 后续缩进行 | 档案区：label 行（0.6875rem/600/muted）+ 正文段（**衬线体** 0.75rem/1.7 行高/`--text-secondary`，左缩进 0.75rem，左侧 2px `--border-color` 竖线） | 全字符保留；缩进空格丢弃 |
| `- 王阿婆（物件）：描述文字` | 列表行（物件名 600 + muted「（物件）」）+ 描述接排 | `-` 丢弃，余保留 |
| 场景块 `A：a｜B：b｜C：c` | 每段一行 kv：k 为 0.6875rem/600/muted 固定宽 3.5em，v 为 0.75rem primary | `｜` 丢弃（结构分隔符），段内字符保留 |
| `注：…` | 尾注：0.6875rem / muted / 斜体，与上文 0.25rem 间距 | 整行保留 |
| `本章打算：…` / `非写不可的情节：a；b`（warm 块） | kv 行 | 字符保留 |
| `【此刻·切记】a｜b`（recency） | 「此刻·切记」accent 色 label + 内容按段分行 | 【】保留为 label；`｜` 丢弃 |
| 兜底 plain 行 / 未预期格式 | 等宽 0.6875rem 原样直出（同现状样式），与排版节点混排不冲突 | 零改动 |

档案体用衬线是本次最重要的字体裁决：档案/世界观/画像是作者录入的中文叙述文，等宽是给代码与坐标（`t=2177`、禁词表）的。排版视图中只有兜底行和原文视图才出现等宽。

### 5.4 「原文」对照开关

汇总行右端文本 toggle「原文」：激活时全部块正文回退 `<pre>` 等宽逐字直出（现状样式），关闭恢复排版视图。状态为组件内 ref，不持久化。title：「显示 AI 实际读到的原始文本（逐字等宽）」。

### 5.5 保字不变式（测试契约）

对拍测试（`contextBlockFormat.test.ts`）：对每个样例块，`normalize(渲染文本) === normalize(原文)`，其中 `normalize = 去除全部空白 + 去除行首 #/- + 去除场景块 ｜`。任何未来解析改动跑此测试，红线机械化。

### 6.2 颜色纪律（每视图 accent ≤ 2 处）

- `--accent-400/500`：仅用于模式胶囊 active、刷新按钮 hover、「原文」激活态、「此刻·切记」label。**内联标记一律不用 accent**（在场=ok、死亡=danger、此刻=中性 chip）——现状满屏紫胶囊是噪声源。
- `--danger`：hot 预算条、trimmed 红字、死亡 chip、错误卡、健康横幅（琥珀用现有 `rgba(245,158,11,*)` 系）。
- 块卡背景 `--bg-canvas`、边 1px `--border-color`、圆角 `--radius-sm`；空块 dashed + opacity 0.85。

- 所有新色只来自现有 token + `color-mix(…, transparent)`（透明混合无主题偏差）；chips 中性底用 `--bg-tertiary` 两主题各自成立。

## 附：施工批注（2026-09-12 施工时增补，与设计一致性说明）

以下三点是施工中对设计的小幅修正，均不违背设计立场，特此留档：

1. **兜底 plain 行改衬线，不用等宽**（修订 §5.3 末行）：实测块格式盘点发现「笔迹示范」块正文是作者亲笔散文（`【示范 N】` + 多行无标记散文）、「实体称呼」块正文是中文说明句——若 plain 兜底用等宽，这两个块将整块保持旧疾，违背本设计自己的字体裁决原则（「中文叙述文不该用代码脸」）。修订为：plain 兜底行用衬线 0.75rem/1.7 渲染（与档案体同规格）；等宽只保留给「原文」对照视图。逐字核对需求由原文开关完整承接。
2. **解析器补充三个实测形态**（扩展 §5.2 规则表）：`## 标题`（canon 块的 `[private]/[public]` 段头，升格 heading）；`【示范 N】` 独立行（样本编号行→样本 label 节点）；`  → …` 两空格缩进箭头行（canon 私有条目的写作指令行→档案体续行）。均为后端真实产出的字面格式（`consistency.py` / `adaptive_prompts.py` / `knowledge_plane.py` 核实）。
3. **切章自动重拉**（细化 §4.1）：切章复位数据后，若作者仍停在「AI 视角」分区，自动重拉一次（对齐旧「重开重装配」语义；分区未开则维持不拉）。块折叠态随数据置空复位到默认（场景身份展开）。
