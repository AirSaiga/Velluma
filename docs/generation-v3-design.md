# Velluma 生成体系 3.0 工程重构方案

> ⚠️ **本文档描述的 V3.0 Detonation（引爆链）引擎已于 2026-07-24 废弃，代码归档至 `backend/_deprecated/`。**
> 当前生效的生成引擎为 **V3.2 ADF**（`/generate-adf`，设计见 `generation-v3.2-adf.md`）与 **V4.1 Refinery**（`/refinery/*`，设计见 `generation-v4.1-refinery.md`）。
> 本文档作为 V3.0 的历史设计记录保留，其中的架构描述不再反映当前代码现状。V3.0 的核心思路（高潮倒推）曾被 V3.1 Unified 引擎复用，二者均已废弃。

> 日期：2026-07-19
> 前置文档：`generation-v2-research.md`（现状与调研）、`generation-v2-design.md`（2.0 蓝图）、`generation-v2.1-brainstorm.md`（发散）、`human-flavor-in-fiction.md`（人味原理）。
> 本文档定位：**3.0 主轴重构**。2.0 解决"写得对"（上下文、成本、校验、回写），3.0 解决"写得勾人"（因果、情绪、嗓音）——方法是把整个 pipeline 的数据流向倒过来。
> 与 2.0 的关系：2.0 的子系统（上下文引擎、文风体系、双层审计、状态回写、观测体系）**全部保留、接口微调**；3.0 替换的是脊椎——规划方式与执行顺序。

## 1. 核心思想：三个方向的翻转

| 维度 | 1.0/2.0（向前） | 3.0（引爆链） |
|---|---|---|
| 设计方向 | 大纲 → 顺序节拍 → 正文 | **引爆点 → 逆向铺垫树 → 阅读顺序** |
| 写作方向 | 第 1 拍 → 第 N 拍（爆炸在队尾） | **爆炸先写 → 引线朝爆炸写** |
| 校验方向 | 对着文字找洞（无锚、采样） | **对着图验证（有锚、免费+精准）** |

一句话：**先设计爆炸，再生长引线，最后点燃。** 原理依据见 `human-flavor-in-fiction.md`（故事是因果结构，文本只是渲染；necessity 只能从引爆点倒推出来）与调研报告 §4（BiT-MCTS 高潮优先实证、分段扩写杀死情绪曲线、市面工具全部正向流水线=空白区）。

## 2. 设计原则

| # | 原则 | 说明 |
|---|---|---|
| D1 | **逆向设计** | 每个叙事元素必须作为"引爆需要什么"的答案出生；孤儿元素在构造上不存在 |
| D2 | **爆炸先写** | 引爆场景在信息最完备时以最高规格先写，引线永远朝着已成文的爆炸写 |
| D3 | **距离即指令** | 每个引线段携带与爆炸的距离，距离决定任务（收紧/压抑/部分释放），"禁止早泄"是硬约束 |
| D4 | **图即审计** | 因果正确性用图算法免费验证；LLM 审计只做有锚验证（节点是否在文本中真实落地） |
| D5 | **伏笔即产物** | 跨章的铺垫节点自动成为 PlotLedger 条目，伏笔从"维护负担"变为"生成排泄物" |
| D6 | **闲笔预算** | 显式允许非因果的质感元素存在（防"太工整"），但闲笔是被选择的，不是失控的 |
| D7 | **问题流保温** | 每个引线段配一个"读者抱着走的问题"，压抑≠无聊 |
| D8 | **人的注意力投向 5%** | 人工闸门集中在引爆点设计与引爆场景审阅（一章里最值得人看的 ~800 字） |
| D9-P10 | （沿用 2.0 原则） | 骨架/皮肤分离、观测先行、降级不静默、模型按任务路由、校验带证据 |

## 3. 从 2.0 继承什么（工程复用清单）

| 2.0 子系统 | 3.0 中的处置 |
|---|---|
| 上下文引擎（双通道召回/预算布局/缓存前缀） | **原样保留**，新增服务：为铺垫树生长与引爆点写作供料 |
| 文风体系（文风卡/样本库/禁词表/去味审计） | **原样保留**，新增"留白预算"与"潜台词标记"进入铺垫树节点 |
| 双层审计框架 | **保留骨架**，审计内容重构（见 §7）：图校验前置、LLM 审计改有锚式 |
| 状态回写（证据携带/滚动摘要/快照） | **原样保留**，PlotLedger 更新从"提取式"改"树节点落账式" |
| 观测体系（GenerationRun/质量报告/SSE） | **原样保留**，新增引爆链阶段事件与指标 |
| 模型三槽位路由 | **原样保留** |
| 章节卡 | **保留**，增加 `payload_moment` 字段 |
| 节拍（StoryBeat/BeatSpec） | **保留字段**，从"顺序容器"变为"铺垫树的阅读序视图"，加两根因果线 |
| 失效的旧物 | 分段扩写+统稿降级为>8000 字复杂章的 fallback；对抗校对（采样对比式）废除，由有锚审计取代 |

## 4. 核心数据结构

### 4.1 DetonationChain（引爆链，新表）

```json
{
  "id": "uuid", "chapter_id": "uuid", "version": 2,
  "payload": { "...见 4.2" },
  "nodes": [ "...见 4.3" ],
  "reading_order": ["n1", "n2", "n3", "PAYLOAD"],
  "status": "growing → confirmed → writing → done",
  "created_at": "...", "confirmed_by": "user|auto"
}
```

### 4.2 PayloadMoment（引爆点）

```json
{
  "id": "PAYLOAD",
  "description": "男主把渡口票据拍在桌上，却不是质问——他烧掉了它",
  "emotional_target": "压迫感在最高点反转成更深的失望（他连质问都放弃了）",
  "answers_question": "男主到底知不知道女主在说谎？（答：知道，且选择不再追问）",
  "opens_question": "他烧掉票据是想保护她还是彻底放弃她？",
  "must_land": true,
  "candidate_index": 1,
  "text": "……（§5 Phase 3 生成的成文）",
  "approved": false
}
```

### 4.3 SetupNode（铺垫节点）

```json
{
  "id": "n3",
  "type": "plant | development | diversion | texture",
  "content": "男主独自在书房对着票据坐了半夜，最后把它揣进袖子——没有去见她",
  "sets_up": ["PAYLOAD"],
  "distance_to_payload": 1,
  "assignment": "tighten",
  "question_delays": "他会拆穿她吗？",
  "restraint_note": "不点破他为什么犹豫（那是 PAYLOAD 才给的答案）",
  "subtext": "他怕的不是被骗，是拆穿后连被骗的资格都失去",
  "satisfied_by_existing": null,
  "planted_in_text": null,
  "beat_id": "..."
}
```

字段说明：
- `type`：`texture` 即闲笔预算（D6），允许非因果的质感元素，但显式标记、控制比例（≤15% 节点数）。
- `assignment`：`suppress`（压抑）/ `tighten`（收紧）/ `release_partial`（部分释放）/ `texture`（闲笔呼吸段）——写作时的情绪任务书（D3）。
- `restraint_note`：该节点**明确不说破**的内容（人味原理：感动是读者自己干的活）。
- `satisfied_by_existing`：递归终止标记——该前提已被前章事实满足（引用角色状态/快照/记忆条目 id），**无需在文中重写**。
- `planted_in_text`：审计回填——该节点在正文中的落地证据（引用+偏移），未回填即"断线"。

### 4.4 StoryBeat 扩展

保留 2.0 全部字段，新增：`chain_node_ids`（本拍承载的节点）、`sets_up`、`payoff_of`、`assignment`、`question_open/delays`。节拍 = 铺垫树的阅读序分段视图（若干节点合并为一拍，拍数 2~5 个，不再固定 6 拍——**按树的自然分段，不按字数均分**）。

## 5. 一章的生命周期（主流程）

```
Phase 0  上下文组装（沿用 2.0 上下文引擎）
Phase 1  章节卡（沿用 2.0，含 payload 候选生成）        ✋闸门
Phase 2  引爆链生长（逆向递归）                        ✋闸门（树可视化编辑）
Phase 3  引爆点先写（最高规格，双候选）                 ✋闸门（人审 ~800 字）
Phase 4  引线写作（朝爆炸写，距离指令）                  ——SSE 实时进度
Phase 5  组装（阅读序拼接+接缝处理）
Phase 6  双层审计（图校验→有锚 LLM 审计→起爆/早泄检查）
Phase 7  局部精修（证据驱动，≤2 轮）
Phase 8  人味工序（减法引擎+潜台词校验，可选档）
Phase 9  定稿回写（沿用 2.0，伏笔自动落账）            ✋闸门（发布确认）
```

### Phase 0：上下文组装（不变）
沿用 2.0 上下文引擎。新增产物：`established_facts` 清单（供递归终止用）——从角色状态/世界快照/伏笔/滚动摘要中提取的"已成立前提"索引。

### Phase 1：章节卡（微调）
沿用 2.0。新增：生成章节卡时**同时产出 2~3 个引爆点候选**（每个含 description/emotional_target/answers_question），连同章节卡一起交人工。用户可改、可选、可自写。
- 调用：1 次 reasoning（与章节卡同次或 +1 次）。
- 过渡章处理：引爆点可以很小（一个眼神、一个安静的决定）——机制降级不失败。

### Phase 2：引爆链生长（核心新模块）
输入：确认的引爆点 + 章节卡 + established_facts + 伏笔账本。
过程（reasoning，1~2 次调用）：
1. **逆向递归**：以引爆点为根，反复问"要让它炸响，读者此刻之前必须相信/感到/误会什么"。每个答案成为节点；每个节点再同样追问，直到前提满足以下任一终止条件：a) 已被 established_facts 覆盖（标记 `satisfied_by_existing`）；b) 可用一句话带过（标记 `trivial`）；c) 达到深度上限（默认 6 层）。
2. **节点装饰**：为每个节点分配 type/assignment/question/restraint/subtext（一次结构化抽取完成，两段式防推理退化）。
3. **阅读序展开**：树→拓扑排序→按距离与节奏合并为 2~5 拍，标注每拍承载节点。
校验（代码级）：树合法性（无环、每节点可达引爆点、texture 占比 ≤15%）；不合法→带错误反馈重试 ≤2 轮。
✋ **闸门：树可视化**——节点=卡片，边=引线，支持拖动/删增/换引爆点（换则局部重长）。

### Phase 3：引爆点先写（D2）
在信息最完备的时刻写全章最重要的一段：
- 输入：引爆点+全部直接引线节点（distance≤2）+相关角色卡+文风卡+作者样本+上文末尾（如有）。
- 规格：**creative 槽、双候选生成**（Re3 选优思想），选优标准=情感强度×克制度×专属性（先代码初筛禁词/句长，再 LLM 评委 1 次）。
- 长度：目标的 15~25%（一章 5000 字则 800~1200 字）。
- 调用：2（候选）+1（选优）= 3 次 creative/reasoning。
✋ **闸门：人审引爆段**——全章唯一强制人审的文本，~800 字，30 秒可读完。人改后的文本冻结为锚。

### Phase 4：引线写作（朝爆炸写）
引爆已成文，引线写作现场彻底改变：
- **每段输入**（上下文引擎组装）：P0 文风卡/样本（缓存前缀）→ P1 章节卡+本段节点清单+角色状态 → P2 **爆炸成文（或其关键段落锚）**+本段 distance 指令+restraint_note+question 任务+前段尾巴。
- **距离指令模板**（D3 核心，直接进 prompt）：
  > 本段距离引爆点还有 {d} 个节点。你的任务是 {assignment}：{assignment 释义}。
  > 禁止：任何形式的提前释放（小高潮、情绪爆发、真相点破）。
  > 本段要让读者抱着这个问题走：「{question}」——不要回答它。
  > 本段埋设：{sets_up 节点内容}。埋设方式必须自然，禁止预告腔（"他不知道的是……"式）。
  > 不说破：{restraint_note}。
- **分段策略**（按引线总长）：≤2500 字单段一次写；2500~5000 字分 2~3 段（后段可见爆炸+前段全文尾巴 500 字，保持呼吸连续）；>5000 字退回分段扩写 fallback（复杂章/超长章）。
- 即时校验（沿用 2.0 fail-fast）：代码审计（禁词/句长/红线/字数）→带反馈重试 ≤2。
- 调用：引线 1~3 次 creative（+重试）。

### Phase 5：组装（轻量化）
按 reading_order 拼接：引线段 + 引爆段。接缝只做"抵达处理"（引线最后一段与引爆段开头的过渡句打磨，0~1 次 creative 调用，输入仅两端各 500 字）。**不再有全文统稿**——爆炸与引线共享同一因果脊柱，接缝天然柔软。

### Phase 6：双层审计（D4）
**Layer 0（零 token，代码）**：
- 图校验：每个 payoff 有 plant？每个 plant 在阅读序上先于其 payoff？texture 占比？（纯图算法）
- 文风指标：禁词命中率/句长 CV/对话占比/段末升华（沿用 2.0 审计器）
- 实体一致性：角色名/在场/红线（沿用）
- 字数达标

**Layer 1（LLM 有锚审计，reasoning，1~2 次）**：
- **落地验证**：逐节点问"该铺垫是否在正文中真实落地？"→ 证据链 JSON（引用+偏移），回填 `planted_in_text`。断线节点→进修复。
- **起爆验证**：引爆段+其前 500 字单独送读者模型："读到此刻，你的情绪是否被引爆？1-10 分+一句话理由"。<7 分→引爆段重修（优先）而非引线返工。
- **早泄检查**：各引线段单独扫描"是否存在提前释放"（情绪峰值检测+真相泄露检测）。
- **动机抽查**：本拍主要人物行动是否有 want/fear 支撑（对照节点 subtext）。
- 失败不静默：任何解析失败→标记 unaudited，绝不视同通过。

### Phase 7：局部精修（沿用 2.0）
证据驱动：断线节点补埋（定向插入/改写，输入仅相关段+节点）、早泄段降燃（重写该段，带"降一档"指令）、起爆不足则引爆段换候选重写。≤2 轮；未解→degraded 标记进质量报告随稿放出。

### Phase 8：人味工序（可选档，默认开）
- **减法引擎**：全文扫描可删区（冗余形容词/解释性句子/重复信息），生成 150%→删回 100% 的定向删除清单，LLM 执行删除（1 次 creative，输入为命中片段集合而非全文）。
- **潜台词校验**：节点 `restraint_note` 对照正文，确认"没说破的依然没说破"（代码关键词+LLM 抽查）。
- 嗓音一致性抽读（creative 自评+指标对比样本库）。

### Phase 9：定稿回写（沿用 2.0 + D5）
沿用 2.0 全部回写（摘要/记忆/角色状态带证据/快照/滚动摘要）。**新增伏笔自动落账**：树中 `sets_up` 指向未来章节 payload 的节点（Phase 2 生成时标记 `future_payoff`）→ 自动写入 PlotLedger（action=plant, 支持文本=`planted_in_text` 证据）；本章兑现的旧伏笔自动 closed。**PlotLedger 就此激活，零额外 LLM 调用。**

## 7. Prompt 契约要点（关键新增模板）

所有模板遵守 2.0 契约规范（system 静态前缀保缓存、user 动态尾部、两段式输出、降级显式化）。3.0 新增四个核心模板：

### 7.1 引爆点候选生成（reasoning，T=0.5）

```
system: 你是资深类型小说结构编辑。给定章节卡与故事现状，设计 3 个引爆点候选。
  引爆点定义：本章情绪势能的引爆瞬间——一个反转、揭盅、抉择或关系的不可逆变化。
  要求：① 必须由前文的既有张力自然导出（禁止天降）；② 必须回答一个读者正抱着的问题，
  同时打开一个新问题；③ 情绪目标具体可感（不写"很震撼"，写"压迫感在最高点反转成失望"）。
user: [章节卡] [前章摘要] [开放伏笔] [角色状态]
输出（自由分析→JSON 抽取）：{candidates: [{description, emotional_target,
  answers_question, opens_question, why_now}]}
```

### 7.2 铺垫树生长（reasoning，T=0.3，两段式）

```
system: 你在做逆向叙事设计。给定引爆点，递归追问唯一问题：
  「要让它炸响，读者在此前必须相信/感到/误会什么？」
  递归终止条件：a) 前提已被[已成立事实]覆盖（引用其 id）；b) 一句话可带过；
  c) 深度达到 6 层。
  每个节点随后装饰：type(plant/development/diversion/texture)、assignment
  (suppress/tighten/release_partial/texture)、question(读者抱着走的问题)、
  restraint(本节点不说破什么)、subtext(人物未说出口的真实动机)。
  texture 节点占比不得超过 15%。
user: [引爆点] [章节卡] [已成立事实 established_facts] [伏笔账本]
输出（自由分析→JSON 抽取）：{nodes: [...], reading_order: [...]}
```

### 7.3 引线写作（creative，T=0.8，thinking 关）

```
system: [文风卡正面画像+负面清单+替代规则] [作者样本 2~3 段]
user:
  【本章引爆点已成文】（供你对准，禁止复述其内容）：
  {payload_text 或其关键段落锚}
  【你的段落】距离引爆点还有 {d} 个节点，任务={assignment}（{释义}）。
  【硬性约束】
  - 禁止任何形式的提前释放：小高潮、情绪爆发、真相点破；
  - 让读者抱着这个问题走，且不回答它：「{question}」；
  - 自然埋设：{sets_up}（禁止预告腔）；
  - 不说破：{restraint_note}；
  - 字数目标 {n}，边写边倒数（countdown）。
  【衔接】前段结尾：{tail_500}
```

### 7.4 有锚审计（reasoning，T=0.1）

```
system: 你是结构审计员。不做文学评价，只验证三件事，全部给证据：
  ① 落地：每个铺垫节点是否在正文中真实落地？给原文引用+位置；没有则标记断线；
  ② 早泄：各引线段是否存在提前释放（情绪峰值/真相泄露）？给引用；
  ③ 起爆：读引爆段及其前 500 字，你的情绪是否被引爆（1-10 分+一句话理由）？
user: [铺垫树节点清单] [正文全文]
输出（自由分析→JSON 抽取）：{planted: [{node_id, quote, offset}],
  broken: [...], premature: [...], detonation_score, detonation_reason}
```

## 10. 实施路线图

**Phase A：原理验证（零代码，本周）**
手工跑一章：选一章"一读就漏洞百出"的典型 → 定引爆点 → 模型递归长树 → 先写爆炸 → 再写引线 → 与现有流程同章输出对照盲读。验证两个假设：逆向规划是否消除漏洞感、爆炸先写是否解决平淡。**这是所有后续工程的前置闸门。**

**Phase 0：地基（如 2.0 已完成则跳过）**
观测计量、模型三槽位路由、上下文引擎。

**Phase 1：引爆链核心（2-3 周）**
DetonationChain 数据模型与迁移；引爆候选+树生长 prompt（§7.1/7.2）；树→拍映射；Phase 3 爆炸先写（双候选）；Phase 4 引线写作（距离指令模板 §7.3）；组装轻量化；图校验（Layer 0）。

**Phase 2：审计与回写（2-3 周）**
有锚审计（§7.4）+起爆/早泄检查；精修接证据链；伏笔自动落账；restraint 校验；SSE v3 事件。

**Phase 3：交互层（2-4 周）**
树可视化编辑闸门（节点增删改、换引爆点局部重长）；引爆段人审界面（双候选对照选）；质量报告页（断线/起爆分/指标）。

**Phase 4：打磨与深化（持续）**
人味工序完整化（减法引擎/潜台词校验）；A/B 跑通→旧链下线；闲笔预算调优；复杂章 fallback 与主链统一体验；情绪曲线测量器（连接 2.1 头脑风暴的闭环设想）。

## 11. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 引线压抑=无聊 | 高 | 问题流保温（D7）已内置；Phase A 重点验证此点；必要时引线段加"微冲突配额" |
| 引爆点质量方差大 | 中 | 候选×3 + 人工选定 + 双候选写作 + 起爆验证兜底重修 |
| 树生长质量不稳（递归发散/漏关键前提） | 中 | established_facts 接地终止；深度上限；代码级树校验+带反馈重试；人工树闸门兜底 |
| 文本"太工整"（每句都有用） | 中 | 闲笔预算（D6，texture ≤15%）；人味工序保护未优化区 |
| 爆炸先写导致引线与引爆文风断层 | 低 | 同一文风卡+样本贯穿；引爆段关键句锚入引线 prompt；接缝工序 |
| 用户不买"多一道树闸门" | 中 | 树可"AI 生成+一键确认"快通过；快路径与细路径并存 |
| 超长/复杂章 fallback 体验分裂 | 低 | fallback 同样吃铺垫树（树照样生成，仅执行改分段），体验连续 |

## 12. 差异化定位（市面扫描结论的落点）

- 商业产品（Sudowrite/Novelcrafter/笔灵/阅文）全部是**正向流水线**，逆向生成、情绪工程、因果校验在商业层是**空白区**；最接近的 oh-story（社区 skill 包）只有"高潮逆推"技法文件，不是引擎。
- 海外一致性检查产品只能做"事实对账"，自认"人物行为弧、伏笔兑现只能靠人"——3.0 的图校验+有锚审计正面补位。
- 平台查杀政策（番茄封 855 账号、晋江锁章）使"非机械文风+人工介入率"成为生存项——3.0 的人审锚点（引爆段）与文风体系既是质量也是合规护城河。
- 一句话定位：**别人卷模型与上下文长度，我们卷故事结构——这是烧脑而非烧钱的赛道，且无人占位。**
