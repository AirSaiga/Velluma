# 知识检索平面（Knowledge Retrieval Plane）——正文生成的知识供给链设计 v3.1

> 2026-08-27 · 状态：v3.1，已吸收专家审阅（结论「有条件满足」，五项前置条件全部落实，见附录 A） · 定位：定义「作者录入的设定知识如何进入每一次文本生成」的目标架构与后端完整链条。
> 前提对齐 `docs/项目逻辑说明书.md` 四条产品理念（作者主导、画布即事实源、作者录入 AI 放大、裁决在人）。
> 本文档取代散落在 AGENTS.md 段落与各专项文档中的供给规则，成为知识供给的唯一权威设计。

## 0. 重构动因（实证依据，非感觉）

2026-08-27 对真实写作 trace（38 次 LLM 调用 / 9 次续写 / 52 次心跳）做代码级 + 运行时 prompt 审计，四个结论：

1. **可见性集合错位**。写正文的调用（`/adaptive/stitch-ghost` 五模式）是全系统上下文最穷的消费者：角色档案八字段、动态状态（含死亡/位置）、世界观（仅 open 档 200 字）、关系、期待、spine 意图、用户负面清单——全部不进正文 prompt；而 8-14 字挂件零件的生成（dock_generator）反而消费全量知识（nutrients/hard/soft 三级）。实测：open 档 2/2 被采纳（带世界观+大纲），stitch 档 0/7 采纳（五次输出收敛为同一微节拍、场景道具漂移、时代错乱幻觉——2177 机甲基地里出现「黄浦江雾气」）。
2. **字符截断静默销毁知识，且是双重截断**。`budget.py` 实测约 45 项截断常量；世界观在 open 档被路由侧与 builder 各截一次（adaptive.py:952 + adaptive_prompts.py:755）。《最终武装》世界观 2390 字，open 档只见 200 字（-92%），其余四档 0 字。
3. **轻重分档导致轻任务失明**。句级档（stitch/continue）被先验地设计为「轻路径」（画像压缩、样本减量、知识缺席）；实测恰恰是这些档位产出全部不可用。「轻」没有被数据支持。
4. **负面清单同构洞**。`to_prompt_context()` 有 style_negative 字段，但五模式 builder 均不消费——作者认真维护的禁词表对正文续写零作用（UI 无任何告知）。

四个目标由此确立：**知识完备性**（选中即完整）、**任务平权**（生成任务间无知识轻重）、**规模健壮性**（书越写越厚，单次 prompt 有界）、**可证伪性**（选择质量可测）。

## 1. 设计公理

- **公理一（事实/方向二分）**：事实类知识（谁在场、谁死了、什么世界、人物口音、已确立真相、在场物件）自动进入一切生成调用，无需作者操作；方向类知识（剧情走向、节拍、期待、推测）只经作者亲手或亲手选定的载体（细纲胶囊、走向卡选卡、spine 意图/锚点、零件吸附）进入正文。这是知识**类型**区分，与任务轻重无关，同时保住作者主权。
- **公理二（选中即完整）**：完备性契约的对象是**被选择器选中的知识条目**——条目一字不砍完整注入，系统内不存在任何字符级截断。所有文本生成任务消费同一份 SelectedKnowledge；任务间允许的差异只有**任务指令**（写什么/写多长/从哪接），没有知识可见性差异。「一字不砍」的对象是条目的**信息内容**；渲染层为条目添加时态前缀、优先级声明、冲突标注**不属于砍**。
- **公理三（选择语义化，预算逃逸化）**：知识增长由选择精度吸收，不由截断吸收。唯一体量约束是 token 级逃逸阀：超限按 养料→软→硬 的顺序丢弃**整条**（永不腰斩文本），丢弃必须可见（trace + AI 所见预览「未注入」区 + 原因）。
- **公理四（选择器不对称原则）**：一切选择器**宁多勿漏**（recall-oriented）——误选由逃逸阀兜住（丢整条、可见、可申诉），漏选无兜底（模型自由生发=穿帮）。精度问题交给逃逸阀与作者钉；施工期任何选择器不得向「精确」方向调参。

**边界三分**（完备性的管辖范围）：
- 设定知识（作者录入）→ 选择后完整注入；
- 正文文本（作品本身）→ 滚动窗口 + 记忆召回（画布视野问题，十万字全文塞入才是真灾难）；
- 方向数据（大纲节拍/推测/期待）→ 就近剂量（整章地图诱发冲章的实测教训在方向维度依然成立，完整注入的是事实不是路线图）。

## 3. 后端完整链条（目标态全景）

```
┌ 录入面 ─ 世界页表单（实体档案/事件/关系/五本账） · 文风页（样本/画像/负面清单）
│          写作台（正文/大纲/spine/胶囊/速记/场景钉/时间锚） · 行为信号（埋点）
├ 存储面 ─ world_entities/events/relations/locations · canon_nodes · plot_ledgers
│          style_cards · chapters(spine/outline/narrative_time/scene_pin) · books(worldview/reader_mirror)
├ 折叠面 ─ world_events --compute_world_state(t)--> 此刻状态（位置/死活/关系活跃/疆域控制）
├ 装配面 ─ settings_bundle（原始加载，全量进内存，单次）
│          → 条目化（KnowledgeEntry，原子单位）
│          → 选择器引擎（recall-oriented 组合 → SelectedKnowledge + 未选清单）
│          → UKV 渲染（时态标注 + 折叠态优先声明 → 完整文本块）
│          → [装配缓存：同章同 t 短窗，world_version 失效即重建]
├ 注入面 ─ render_system_blocks（块序定死，见 §6）+ 任务指令 + user 尾部 recency 重钉
│          → 同一份注入物给：stitch 五模式 / dock_generator / future_projection / finish 审计
├ 生成面 ─ stitch-ghost（SSE 幽灵草稿）· 心跳组件（挂件/推测/意图反推）
├ 护栏面 ─ ghost_guard（死者开口/泄密/用户禁词——事后警告，永不拦截；warning×选择集 join 埋点）
│          finish 语义扫描（换字逃逸 AI 味——报告作者裁决）
└ 回流面 ─ 行为信号（采纳/蒸发理由/忽略 → 方向权重负反馈 + quiet_learning 静音派生）
           settle/finish/auto-read → 候选池（物理隔离）→ 作者裁决 → 知识增长
```

闭环语义：**录入 → 折叠 → 选择 → 注入 → 生成 → 护栏 → 回流 → 录入**。护栏面与装配面之间埋一条观测边（warning 命中时回查选择集是否漏选），是选择质量的在线数据源。

## 4. 知识条目模型

条目 = 选择与注入的原子单位，永不劈开。五类：

| 条目类型 | 来源 | 内容（完整） | 时变性 |
|---|---|---|---|
| 实体条目 | world_entities + t 时刻折叠态 | 名/别名/类型/重要度/八字段档案全文（外貌…语言习惯…技能）/**此刻状态**（位于 X/在途 p%/已死亡）/可见性 | 此刻状态随 t |
| 世界观条目 | books.worldview_settings.items | 标题 + 内容全文 | 静态 |
| 真相条目 | canon_nodes | 表（public_text）/里（canon_text）/揭示计划/揭示章/强度；私有走 secrets 块 | 揭示状态随章 |
| 伏笔条目 | plot_ledgers（open） | 内容全文/埋设时间/成熟度 | 随回收 |
| 关系条目 | world_relations | 双方/类型/标签/备注/时间锚 | t 时刻活跃性 |

**两个恒选的非条目知识**：① **负面清单约束块**（prohibitions 四源合并——现状五模式 builder 完全不消费，同构可见性洞，v3.1 收编；提醒级全量注入，blocker 级归硬层永不丢）；② **紧前一章摘要**（previous_summary，连续性最强单一文档，恒选不截断，废除 500 字上限）。

前情记忆不条目化（三层召回 k=3 管辖）；正文不条目化（窗口+召回管辖）；事件不条目化（折叠管辖）。

**条目粒度自律**：条目是全有或全无的注入单位，超长条目（如 5000 字世界观论文）在逃逸阀下比截断更粗暴——表单侧提示「条目宜 ≤500 字，长了请拆分」，装配时超长条目写 trace 标记（不动 schema，不动红线）。

## 5. 选择器引擎

装配时对条目池跑一组声明式选择器，产出 SelectedKnowledge（有序）+ 未选清单（含原因）。全部语义判定，无数值截断，全部 recall-oriented（公理四）：

0. **场景恒选集**（硬·确定性）：场景钉存在时，场景地点条目 + 所属疆域/世界观相关条目**恒定选中，不经任何相关性判定**——封堵「黄浦江雾气」类场景失明的一行规则，不依赖选择器正确性；
1. **在场选择**（硬）：场景钉 + t 时刻折叠在场集；
2. **邻近选择**（软）：在场实体的关系一跳；
3. **提及选择**（软）：**本章全文**内名字/别名命中（扫描窗从滚动尾扩到本章全文——实体类临场事实的主要缓解手段，纯算法）；
4. **检索选择**（养料，二期）：三层召回推广到世界观/真相/档案条目——须先建条目索引（实体名/别名匹配为主、jieba 关键词为辅；SQLite 默认路径下纯 ILIKE 正文对短条目近似不命中，不做索引此选择器是摆设）；
5. **时刻选择**：t 过滤时变条目（关系活跃性、位置有效性）；
6. **逼近选择**：揭示章距本章 ≤2、伏笔成熟度（期待仅感知侧——方向类）；
7. **作者显式选择**（最高优先级，可越一切选择器）：章级绑定、@提及、场景钉、spine 锚点关联。

**二次激活扫描**（二期）：对首轮选中条目的文本做一次名/别名扫描再触发关联条目，深度 1、只增不替（Lorebook 的 recursive activation）。

**纠正回路**：① 作者钉实体/提及（即时）；② AI 所见预览「未注入清单 + 原因」；③ trace 记录每次选择集；④ ghost_guard warning × 选择集 join（在线漏选证据，见 §10）。

## 6. UKV 渲染与注入

**块序（v3.1 定死，不再施工期定）——事实层全前于文风层**（中档模型对 prompt 中部遗忘，连续性事实必须占据 primacy 位）：

```
场景身份 → 在场实体（升级自纯专名块） → canon → 私有(secrets) → 世界观 → 关系
→ 负面清单约束块 → 回响 → 空间 → 画像 → 样本
```

**recency 位重钉**：user prompt 尾部（任务指令之后）以 3-5 行重钉此刻硬事实（在场集/死亡名单/当前位置/关键物件归属），成本 <100 tokens——primacy+recency 双锚是对中档模型上下文利用的标准解法。

**时态标注与折叠态优先**：时变条目渲染必须带时间前缀（「【此刻·第M章·t=N】位于北岸要塞」/「【档案·录入于第K章】住城南」），注入文本明示「**此刻状态与档案描述冲突时，以此刻状态为准**」。完备性注入完整信息，同时防御「完整注入矛盾」——档案静态文本 vs 事件折叠态是最高频矛盾源，二者分字段渲染、各带时间戳。条目间结构性冲突（同字段不一致）以折叠态为准并渲染冲突标注；语义级矛盾留 finish 审计（裁决在人）。

五模式与挂件拿到同一份 UKV，差异只在任务指令：

| 任务 | 任务指令差异 | UKV |
|---|---|---|
| stitch/continue（句级） | fragment/零件、120-200 字、追加式契约 | **同一份** |
| burst（段级） | beat_guidance、700 字 | **同一份** |
| outline（胶囊） | 速记文本、双端锚定、spine 锚点行 | **同一份** |
| open（点火） | 大纲就近一两拍（世界观已在 UKV，废除特判与双重截断） | **同一份** |
| dock/推测（感知） | 挂件铁律/推测 stage 契约 | **同一份** |

退役清单：`_light_mode_style_positive` 画像压缩、`MODE_CONTEXT_BUDGETS` 分档差异、全部知识字段字符截断常量（~45 项）、`to_prompt_context()` 死码头、`ROLLING_SUMMARY_MAX_CHARS` 等 previous_summary 截断。

## 7. 条目级预算（逃逸阀）

- 上限**双层**：设定选择集目标带宽（模型上下文 ~10%）+ 全 prompt 硬顶（~25%，含样本/滚动窗/指令）——单层阈值会被 few-shot 样本（k=2×1200 字）挤占后才发现设定超支；
- 超限丢弃序：养料（检索选中的非在场档案）→ 软（邻近/提及）→ 硬（场景恒选/在场/死亡/canon/私有/负面清单 blocker——永不丢）；
- 丢整条，永腰斩；丢弃写 trace + 预览「未注入（预算）」。

## 8. 规模演算（100 万字 / 300 章厚书，p75 填写度）

| 知识类 | 全量（不可行路线） | 选择后（v3.1，p75） |
|---|---|---|
| 实体档案 | ~120 个 ×350 字 ≈ 42k 字 | 在场+一跳+提及 ≈ 10-30 条¹ ≈ 3.5-10k 字 |
| 世界观 | 40 条 ≈ 8k 字 | 场景恒选+检索+二次激活 ≈ 6-8 条 ≈ 1.5k 字 |
| 真相 | 100 节点 ≈ 10k 字 | 相关 4-6 节点 ≈ 800 字 |
| 伏笔/期待 | ≈ 1.5k 字 | 临近 3 条 ≈ 200 字 |
| 前情 | 折叠+回响 k=3 | ≈ 600 字 |
| **设定选择集合计** | ~60k 字 ≈ 30k tokens | **≈ 6.5-13k 字 ≈ 3-6k tokens** |
| **全 prompt 口径**（+样本 2.4k 字+滚动窗+摘要+指令） | — | **≈ 6-9k tokens** |

¹ 群像戏/战争场面一跳展开 20-30 条不夸张。

口径二分（验收「规模曲线」须分别计量）：设定选择集 vs 全 prompt。即便上限 6k tokens，对 32k 上下文 ~19%，逃逸阀依然宽松；定性结论不变——选择器把增长从 O(书厚) 压到 O(场景复杂度)。隐性提醒：300 章书召回质量会降（向量库变大后 k=3 命中精度、词法预筛重排质量）——是召回质量问题不是 token 问题，会反映在采纳率曲线上，勿误读为选择器失效。

## 10. 验收与度量

- **选择集召回率（金标准，离线）**：对历史写作断点人工标注「应选条目」，跑选择器算 recall/precision——场景锚定相关条目 **recall ≥95%** 门槛。完备性契约只保证选中即完整、对漏选零防御，此项让选择器可证伪；
- **ghost_guard × 选择集 join（在线）**：warning 命中（如死者开口）时回查对应条目是否在当次选择集——缺席即漏选直接证据，召回率的免费在线数据源；
- **场景锚定率**：产出道具/景语落在世界观与在场条目词表内的比例（本轮实测区分度最高指标）；
- **配对盲评**（优先于采纳率——采纳率受作者状态方差大）：弦上灰断点（作者亲笔下文为参考答案）+ 冷启动断点；采纳率作二级行为指标（基线 0/7）；
- **规模曲线**：设定选择集与全 prompt 两口径的 token 随章节增长曲线（验证近似不变）。

## 11. 红线与已知局限

**红线（不做的事）**：
- 柔性不拦截：知识是让模型看见，不是生成后拦稿；ghost_guard 扩检仍只警告（自动 retry 属生成内部重发，不改正文）；
- 不自动改稿、不静默入账：回流面全部经作者裁决；
- 不推翻写入侧与折叠面：世界页/事件模型/world_bridge 原样；
- 不给方向数据开后门：大纲/推测/期待不因完备性公理获得直通正文的权利；
- 无数据零变化：空书/无设定的 prompt 逐字节不变（空条目=块缺席）。

**已知局限（显式承认，勿误读为已覆盖）**：
- 非实体微事实（「他把刀放在桌上」「窗外开始下雨」）：settle 只沉淀实体不沉淀微事实，滚动窗外即丢——提及选择扩窗只缓解实体类；
- 承诺/约定类叙事契约（「三日后北门相见」）：依赖 event_scout 抽取覆盖面，需核实，不足则动写入侧独立排期；
- 场景环境速写（季节/天气/光线）：无专门来源，依赖地点条目描述兜底；专项机制（场景钉挂环境速写）动写入侧，独立排期。
