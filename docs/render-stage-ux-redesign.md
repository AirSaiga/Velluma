# Velluma 渲染阶段 UX 重设计 — 正文中心的创作工作台

> **版本**：v2（正文中心工作台）
> **状态**：设计完成，待实施
> **日期**：2026-07-30
> **范围**：BS-ADF 引擎渲染阶段的前后端交互重构
> **核心**：把渲染阶段从「AI 的流水线」改造为「作者的创作工作台」——作者对**正文**拥有完整编辑权（直接改字、可回退），对**结构**在渲染前定死后锁定。

---

## 0. 设计动机

### 现状问题（用户反馈）

用户反馈：前端生成小说的「渲染」步骤中，作者经常**不知道接下来该做什么**——微调、补充、定点渲染、推进等动作在交互层面上设计得很奇怪。

### 调研诊断（2026-07-30 前后端交叉核实）

经前后端代码级核实，问题分三层：

**范式层（根因）**：`InspectorPanel.vue:189` 将 `steppingEnabled` 硬编码为 `true`，把「逐段裁决」这个高摩擦模式变成所有人的默认。后端架构（分镜卡硬契约、降级、救援、DDE 走向）在精神上是「创作协作台」，但用户预期心智是「点生成→得成品」的代笔范式。渲染阶段正是两套范式拔河的现场——用户被卡在每段都要决策的循环里，却从未被告知「你处于一个需要逐段手动推进的模式」。

**时序层**：在用户信息最少的时候（渲染前/渲染中）要求最多决策；在信息最全的时候（渲染后）反而把介入点做弱。逐段 Space 推进尤其可疑——用户刚看完第 3 段、还没看到 4/5/6 段，无法判断第 3 段是否「OK」，这种确认往往是**虚假决策**。

**抽象层**：后端实现概念（分镜卡/核心转折/降级/救援/覆盖缺失/DDE 分叉/Loop1 缺口）原样泄漏成用户概念。用户被迫在一堆他从没预期要面对的工程词汇里找北。同一个动作三套名字两条链路（拯救/定点渲染/微调后重渲 → rerender-beat 与 advance('edit') 双链路）。

### 能力边界核实（硬约束）

前后端交叉核实确认，当前能力边界如下：

| 能力 | 现状 | 性质 |
|------|------|------|
| 改分镜卡三字段（转折/画面/台词）→ 重渲 | ✅ 现成 | — |
| Loop1 缺口自定义走向文本（`custom:` 前缀） | ✅ 现成 | 前端未给普通 DDE 节点输入框 |
| 步进会话 1 小时续期、可离开后回来 | ✅ 现成 | — |
| 全章完成后单卡重渲（`rerender-beat`） | ✅ 现成（上下文降级） | — |
| 步进态 edit 字段覆盖 | ⚠️ 收窄到 5 字段 | 后端 `_apply_edited_slot` 人为收窄，可放开 |
| **推进前直接编辑正文定稿** | ❌ 完全不能 | 后端无「作者文本定稿」通道；前端 `previewHtml!=null→disabled` 硬锁 |
| **每段可回退** | ❌ 完全不能 | 后端 index 只增不减，无 undo/back，锁死即固化 |
| **增删/重排分镜卡** | ❌ 完全不能 | 后端卡数量固定、ID 固定；冲击 segment_index/状态卡链 |

### 产品定位（决策）

> **渲染阶段 = 作者对正文拥有完整编辑权（含回退）的创作核心区；结构（段数/段序）在渲染前定死，渲染中锁定。**

这等于把 Velluma 的渲染阶段明确改造为「作者的创作工作台」，解决所有 UX 混乱的根源。核心判断：**把控制权重心从「卡」（AI 语言）下移到「正文」（作者语言）**。

---

## 1. 自由度分层主张

「极高自由度」不是「把所有开关都给作者」，而是在正确的抽象层给足够的自由度，同时挡住会制造混乱的伪自由度。

```
渲染阶段作者的自由度（新主张）
├─ 结构层（段数/段序）：锁定，不让动 ← 挡住陷阱（增删卡会级联破坏一致性）
├─ 走向层（每段剧情方向）：完全自由，可自定义文本 ← 真价值
├─ 卡片层（转折/画面/台词）：可编辑 ← 现成
└─ 正文层（最终文字）：可直接编辑、可重渲、可回退 ← 核心
```

**为何锁定结构**：段数和段序本质是「剧情结构」，应在渲染前就定好。渲染中途改结构等于「边盖楼边改图纸」，冲击 `segment_index` 连续性、`beat_id` 命名、大纲节拍分配、状态卡链、前段正文 `rolling_prefix` 依赖。结构编辑归属「渲染前」（Track B 暂停分镜规划）或「生成前」（大纲阶段）。

**为何放开正文**：作者看到 AI 写的文字，第一反应是「我自己改几个字」，而非「改分镜卡让它重新生成」。真正的创作控制权在正文层面。卡是 AI 的内部语言，正文才是作者的语言。

---

## 2. 设计原则

1. **正文是主角**：控制权重心在正文层，不在分镜卡层。作者看到的是文字，操作的是文字。
2. **每段三选一**：任何一段，作者只有三个选择，按成本递增排列——接受 / 自己改 / 让 AI 重写。
3. **结构锁，内容活**：段数段序定死后不动；走向、卡、正文全部可改。

---

## 3. 核心交互模型：段级三选一工作台

作者面对每一段，永远只有三件事可以做：

```
当前段（高亮聚焦，正文可直接点击编辑）
│
├─ ① 接受 [轻] —— 这段 OK，进下一段
│     （键盘 Space / Enter；主按钮）
│
├─ ② 自己改 [中，核心] —— 直接在正文上改字
│     （点击正文即进入编辑；改完点「采纳本段」）
│     （后端 lock_with_text，跳过 LLM，作者文本即定稿）
│
└─ ③ 重写 [重] —— 让 AI 换个方向重生成
     （展开：可改卡三字段 + 可输入自定义走向；点「重写本段」）
```

这三选一**取代**当前所有术语（推进/微调/补充/定点渲染/拯救/锁死）。作者脑子里只有三个动词。

### 三选一的执行映射

| 选项 | 前端动作 | 后端 action | 语义 |
|------|---------|------------|------|
| ① 接受 | `advanceBeat('pass')` | `pass` | 锁定当前段（以当前正文，含作者手改）→ 渲染下一段 |
| ② 改完正文后采纳 | `advanceBeat('lock_with_text', {author_text})` | `lock_with_text`（**新增**） | 以作者改后的文字定稿，跳过 LLM → 锁定 → 渲染下一段 |
| ③ 重写（改卡/走向） | `advanceBeat('edit'/'branch', {edited_slot/branch_choice})` | `edit`/`branch` | LLM 重新生成 → 回到三选一 |

### 回退（贯穿全程的信任基础）

```
[← 回到上一段]  —— 后端 advance('back')，解锁上一段，索引回退
```

- 每次 `pass`/`lock_with_text` 前，后端对当前段的（正文 + 卡 + 状态卡）做快照压栈。
- `back` 弹栈恢复，索引减 1，丢弃下游段（已渲染但未锁的）。
- 这是完整可逆性：作者敢试错（"我改这版看看，不行退回去"）。

## 4. 端到端：作者在每个时刻的经历

### 阶段 A：点生成 → 自动跳「节拍」Tab

右栏顶部「当前任务」焦点条（唯一焦点）：

```
┌─ 当前任务 ──────────────────────────┐
│ ✎ 分镜卡已就绪，请检查后开始渲染      │
│            [ 开始渲染 ]  (唯一主按钮) │
└──────────────────────────────────────┘
```

渲染前唯一的强制介入点（原 Track B 单次暂停）。卡片可编辑（转折/画面/台词三字段）。作者检查或微调后点「开始渲染」。**结构（卡数/段序）在此刻定死**。

### 阶段 B：渲染第 1 段 → 焦点条显示进度（无按钮）

```
┌─ 当前任务 ──────────────────────────┐
│ ⟳ 正在渲染第 1/6 段 · ⋯              │
└──────────────────────────────────────┘
```

中栏：第 1 段位置实时显示渲染文字（流式）。此阶段正文只读（避免与流式输出冲突）。

### 阶段 C：第 1 段渲染完 → 三选一登场（核心）

第 1 段渲染完（`BEAT_RENDER_READY`），焦点条变成**裁决区**，该段正文变得可直接编辑：

```
┌─ 当前任务 · 第 1/6 段 ───────────────────────────────┐
│ ✓ 已生成 1240 字。你可以：                           │
│                                                       │
│  [① 接受，进入第 2 段]   ← Space / Enter (主按钮)     │
│  [② 改完正文后采纳]      ← 或直接在下方正文里点击编辑  │
│  [③ 重写本段 ▾]         ← 展开改卡/走向              │
│                                                       │
│  [← 回到上一段]   (第1段时灰显)                       │
└───────────────────────────────────────────────────────┘

中栏（第1段正文，此时可直接点击编辑）：
┌─────────────────────────────────────────────────────┐
│ 段 1 · 冲突 · 1240字                                 │
│ ┌───────────────────────────────────────────────┐   │
│ │ 林晚从仓库阴影里走出来，气动扳手还滴着水……      │   │ ← 点击即编辑
│ │ (这段正文此刻 contenteditable，光标可入)        │   │
│ └───────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────┘
```

### 阶段 D：进入第 2 段 → 「回到上一段」可用

```
┌─ 当前任务 · 第 2/6 段 ──────────────────────┐
│ ⟳ 正在渲染 · ⋯                               │
│ [← 回到第 1 段]  (解锁第1段，重新三选一)      │
└───────────────────────────────────────────────┘
```

### 阶段 E：降级/救援 → 不打断，事后处理

- 某段渲染降级或核心转折未落地时**不打断流程**。焦点条照常显示当前段三选一。
- 降级段在右栏卡片列表标黄（只读提示），正文位置显示占位。
- 全部段处理完后，若有降级/救援段，焦点条提示「⚠ 2 段需复查」+「去处理」，进入逐段重写流程（走 ③ 重写）。

### 阶段 F：全章完成

```
┌─ 当前任务 ──────────────────────────────┐
│ ✓ 全章渲染完成 · 6/6 段 · 6800 字        │
│            [ 完成 ]                       │
└──────────────────────────────────────────┘
```

完成后，作者仍可对任意段事后「重写本段」（走 `rerender-beat`）。

## 7. 分阶段实施建议

| 阶段 | 内容 | 解决的问题 | 后端依赖 |
|------|------|-----------|----------|
| **P1** | 单一焦点条（当前任务）+ 三选一按钮组 + 删除散落/重复 UI + 统一术语 + 走向自定义输入 | 立即解决「不知道该做什么」、焦点散落、术语混乱 | 无（纯前端，现成 action） |
| **P2** | 正文直接编辑 + `lock_with_text` 定稿 | 核心自由度：作者改正文即定稿 | 需后端新增 action |
| **P3** | 回退能力 + `back` action + 历史栈 | 完整可逆性，作者敢试错 | 需后端新建（改动最大） |
| **P4** | 放开 edit 字段白名单 + 卡片高级编辑折叠区 | 进一步放开卡层自由度 | 小 |

**建议从 P1 开始**：纯前端、零后端依赖，能立即解决用户最初反馈的「作者不知道该做什么」。P2/P3 是把「极高自由度」做实的核心，但依赖后端，可紧随其后。

## 8. 风险与权衡

1. **`lock_with_text` 的状态卡一致性**：作者手改正文后，后端仍需抽取该段状态卡（在场角色/物品/进展），否则下游段渲染缺约束。方案：作者文本定稿时**仍调一次状态卡抽取 LLM**（轻量），保证链连续。成本 +1 LLM/段，可接受。
2. **回退的状态卡链重建**：`back` 不只是恢复正文，状态卡链也要回退到对应段。快照必须包含状态卡。这是后端 P3 的复杂点，需测试覆盖。
3. **正文编辑与流式渲染的冲突**：当前段正文可编辑时，若 AI 正在流式输出该段，编辑会冲突。方案：可编辑态仅在 `BEAT_RENDER_READY`（渲染完）后开启，渲染中保持只读。
4. **「重写」次数无上限**：作者可能无限重写一段卡住。可加软提示（如重写 3 次后建议「接受或自己改」），但不硬限。

## 9. 三选一术语对照（实施时收敛命名）

| 新统一名 | 含义 | 对应现状 | 底层链路 |
|---------|------|---------|---------|
| **接受** | 这段 OK，进下一段 | Space 推进 / 跳过本段 | `/advance-beat` action=pass/skip |
| **自己改** | 直接改正文定稿 | （无对应，新能力） | `/advance-beat` action=lock_with_text（新增） |
| **重写本段** | 改卡/走向后 LLM 重生成 | 定点渲染 / 拯救本段 / 微调后重渲 | 步进态 `/advance-beat` action=edit/branch；done 态 `/rerender-beat` |
| **编辑卡** | 修改分镜卡内容（不立即渲染） | 极速微调（编辑态） | 仅前端展开编辑 |
| **回到上一段** | 解锁上一段重新裁决 | （无对应，新能力） | `/advance-beat` action=back（新增） |

删除的叫法：「拯救本段」「定点渲染本段」「极速微调后重渲」「Space 锁死推进」「补充」「推进」——全部并入上表。
