# 章级谋篇设计（adaptive 软脉络）

> 状态：设计稿（D2 拍板产物，2026-08-18）。拍板结论：可行，**核心约束是「度」**——
> 若作者在写作前为谋篇花费过多心思，会损害写作效率与心流。本设计的每一处形态
> 都由这条约束裁决。
> 范围：`backend/routes/chapter_generation/adaptive.py` + `services/adaptive/` +
> `models.py`（chapters.spine）+ 前端 IgnitionCard / PerceptionBand / InspectorPanel /
> OutlineNoteNode。
> 前置：`docs/iteration-roadmap.md` §2.4（P1.4 章级谋篇）；BS-ADF 章级规划层已退役，
> 本设计**不是**它的复刻，而是「作者主导」哲学下的重新发明。
> 关联：`docs/canon-world-fusion.md`（设计稿格式先例）；`docs/world-writing-bridge.md`
> （切片/感知带设施）。

## 0. 背景、目标与非目标

**背景**：adaptive 写作台的共生能力全部是段落级的——心跳感知、Space 幽灵续写、
细纲胶囊都围绕「当下这几百字」。「本章要去哪」没有任何伴生参照物：走向卡是逐刻
的柔性推测，亮完就过去。作者与 AI 之间缺少一个**章级尺度的共谋物**。

**已存在的相邻设施**（本设计在其上生长，不另起炉灶）：

- 章节大纲（自由文本）：副驾「打算」tab 的大纲编辑卡可编辑（2026-08-22 副驾
  重排前旧称「章节」tab），心跳请求已携带
  `has_outline`/`outline_text`，是点火卡的唯一燃料；
- 点火卡（`IgnitionCard.vue`）：空章 + 无生成 + 无幽灵时出现在画布中央，
  两态（有大纲→「⚡ 写个开头」/ 无大纲→引导写大纲），可 dismiss（章内关闭）；
- 走向卡（`direction_cards`，层 3 未来推测组件产出，Ctrl+Space 卡舱）；
- 感知带（PerceptionBand，右缘，按行对齐）。

**目标**

1. 章级意图与关键锚点有一个**可见、可改、可无视**的伴生载体（软脉络）；
2. AI 的段落级建议（走向卡/胶囊扩写）能挂到章级意图上，从「逐刻猜测」升级为
   「朝着锚点建议」；
3. 写作中有一个极轻的进度感（「还剩哪个锚点没写到」），不弹窗、不打断。

**非目标（红线）**

- 脉络是**给作者看的参照物，不是给渲染器看的槽位**——绝不按脉络自动渲染任何
  正文（BS-ADF 老路，永久禁止）。
- 不做前置强制：不打开谋篇卡也能照常写作，体验与现状逐字节一致。
- 一期不做 LLM 自动岔路判断（见 §5，M4 数据门）。
- 不与章节大纲合并/互转（大纲是自由散文燃料，谋篇是其上的结构化薄层，见 §2.3）。

## 1. 第一设计原则：度

拍板约束的直接翻译。**谋篇的前置心智成本必须趋近于零**，具体落实为五条：

| # | 原则 | 落实 |
|---|------|------|
| D-1 | **谋篇 ≤ 一句话** | 章首谋篇的唯一「要求」是一句本章意图（可空）。锚点可一个不设。 |
| D-2 | **生长式，非前置式** | 写前一句话即可开写；锚点在写作中随时补/改/删；写完不结算、不评分。 |
| D-3 | **可完全忽略** | 章首卡可 dismiss；感知带进度条可关；从不设脉络的书，所有 UI 静默缺席。 |
| D-4 | **AI 建议预填但不落库** | 建议（意图+锚点）只在作者点「收下」或编辑后入库（沿用文风提炼红线）。 |
| D-5 | **锚点数量硬上限 5** | 超出时文案劝阻：「锚点超过 5 个说明在写大纲——细节留给大纲，谋篇只记方向」。防谋篇膨胀成第二份大纲。 |

度的**数据护栏**见 §6：埋点证明谋篇卡被持续无视时，功能自动降级收缩。

## 2. 概念与数据模型

### 2.1 软脉络（chapter spine）

```jsonc
// chapters.spine（新增 JSONB 列，MIGRATIONS 加列；NULL = 本章无脉络）
{
  "intent": { "text": "甲发现那封信是伪造的", "source": "author" },  // source: author|ai
  "anchors": [
    { "id": "a1", "text": "发现假信", "source": "ai", "status": "hit" },
    { "id": "a2", "text": "压住不表", "source": "author", "status": "pending" },
    { "id": "a3", "text": "乙的异常反应", "source": "ai", "status": "dropped" }
  ]
}
```

- `status`：`pending → hit | dropped`（hit 判定见 §4.3，纯算法；dropped 由作者
  手动划掉——「写的过程中决定不写了」是合法且值得记录的动作）。
- 锚点 `text` 是 2-12 字的短语，**不是句子**（芯片形态，非大纲条目）。

### 2.2 为什么挂 chapters 表 JSONB 列

- 语义：脉络是**章级一次性消耗品**，生命周期跟随章节——与 `chapters.narrative_time`
  / `chapters.scene_location_id` 的先例同构；
- 体量：单章 ≤1 意图 + 5 锚点，JSONB 列足够，不值得建新表；
- 迁移成本：MIGRATIONS 加一列即完成，PG/SQLite 双库同义（JSONB 方言编译已有
  `db_sqlite/type_compat.py` 处理）。

### 2.3 与章节大纲的关系

| | 大纲（outline_text，现有） | 谋篇（spine，本设计） |
|---|---|---|
| 形态 | 自由散文段落 | 一句话意图 + ≤5 锚点短语 |
| 回答 | 本章情节怎么展开 | 本章**要去哪**、哪几步不能少 |
| 消费 | 心跳/点火的 LLM 燃料 | 走向卡挂载、进度感知、胶囊意图锚定 |
| 心智成本 | 中（值得认真写） | 趋近于零（一句话） |

两者并存不互转；谋篇卡的 AI 建议以大纲为输入之一（有大纲时建议更准），作者也可
「从大纲抓建议」一键生成——但产出永远只是预填（D-4）。

## 3. 交互设计（前端）

### 3.1 章首：点火卡进化为「谋篇 + 点火」复合卡

空章时（现有 IgnitionCard 显示条件不变）卡片改为两行：

```
┌──────────────────────────────────────┐
│ 本章还是白纸                            │
│ ┌──────────────────────────────────┐ │
│ │ 一句话：本章要去哪？（可空）        │ │   ← 意图输入，autogrow 一行起
│ └──────────────────────────────────┘ │
│ ✨ AI 建议（有大纲/世界数据时可用）      │
│ [⚡ 写个开头]  [我自己写]               │
└──────────────────────────────────────┘
```

- 意图输入失焦即存（`PATCH /api/chapters/{id}/adaptive/spine`），一个字不写直接开写也毫无亏欠；
- 「✨ AI 建议」点击 → `POST /api/chapters/{id}/adaptive/spine-suggest`（1×creative，输入：
  大纲 + 世界切片 + 前情回响 + 开放伏笔 + 上一章 spine 的未兑现锚点）→ 预填
  意图 + 3-5 锚点 chips，作者逐条收下/改掉/删掉，**未收下的不落库**；
- dismiss 行为沿用现状（章内关闭，切章重置）。

### 3.2 写作中：副驾 + 感知带

- **副驾「打算」tab**（旧稿称「章节」tab——2026-08-22 副驾重排为 打算/此刻/
  本章/检查 后，谋篇区落在「打算」）：SpinePanel 谋篇区——意图一行 + 锚点
  chips（就地编辑/增删/划掉= dropped）；有大纲时显示「从大纲抓建议」。
- 意图输入的保存链（7003e4e，2026-09-01 丢稿修复后）：面板本地草稿 + 输入即
  600ms 防抖提交 + 失焦兜底（旧「单向 value + 仅失焦 @change」在失焦前遇心跳
  重渲染即被清空，输入从未进保存链）→ 入本地状态后 2s 防抖自动保存；切章/
  离页时在途防抖**冲刷落库不丢弃**（`useChapterSpine._flushPendingSave`，回包
  快照守卫防串章）。章首复合卡（§3.1）的意图输入仍为失焦即存。
- **感知带顶部**加一条极细进度行（默认开，可关）：`意图短语 · ⚑⚑⚐⚐` 样式，
  hover 出锚点清单。锚点判 hit 时原地打勾（玩具感的来源——像划掉 todo 的满足
  感，不是弹窗祝贺）。

### 3.3 走向卡挂锚点

- 走向卡若带 `serves_anchor`（§4.2），卡面右上角显示对应锚点小签 `⚑2`；
- 点击小签高亮副驾谋篇区对应锚点——「建议为什么而来」可追溯。

### 3.4 细纲胶囊挂锚点

- 胶囊创建/编辑时可从脉络锚点中选一个「服务于 ⚑N」（可不选）；
- 落笔扩写（stitch-ghost mode=outline）时该锚点文本注入 prompt 意图块——
  扩写从「双端锚定」升级为「双端 + 意图」三锚定。

### 3.5 完稿

finish 审计报告加附注行：「未兑现锚点：⚑2 压住不表（pending/dropped）」——
仅提示不阻塞；dropped 的锚点不计入「未兑现」警示（作者主动放弃是合法结局）。

## 4. 后端集成

### 4.1 端点（adaptive 惯例：BaseModel 直接定义在路由文件内）

| 端点 | 说明 |
|---|---|
| `PATCH /api/chapters/{id}/adaptive/spine` | 存/改脉络（轻量，不进正文版本历史，不触发 world-refresh） |
| `POST /api/chapters/{id}/adaptive/spine-suggest` | 1×creative 建议，**不落库**；REASONING_DISABLED 不适用（要质量，走 creative 默认）；max_tokens = `budget.SPINE_SUGGEST_MAX_TOKENS`（2400，2026-08-25 由 800 上调——800 曾被 MiMo 隐藏思考整个烧光返回空）；空输出兜底重试一次（关思考小预算再试，仍空则按空建议返回，契约不变） |

### 4.2 心跳集成（`adaptive.py` heartbeat）

- 服务端按 chapter_id 读 `chapters.spine`（请求体不加字段，零前端传输膨胀）；
- 注入两个组件的现有 prompt（边际成本 0 LLM）：
  - 未来推测（走向卡）：锚点块（pending 锚点列表），要求产出卡带
    `serves_anchor: "a2" | null`——代码侧校验锚点 id 必须命中，非法置 null
    （沿用 DDE「不信任 prompt 约束」的代码闸门思想）；
  - 挂件生发：仅在意图存在时注入意图一行（8-14 字零件不吃画像的同款克制：
    只给方向不给展开）；
- 响应 `HeartbeatResponse` 加 `spine_progress` 字段（§4.3）。

### 4.3 进度判定（纯算法，宁漏勿误——D-5 同款保守）

> **2026-08-25 B2 治理修订**（3b466d5，台账见 `docs/adaptive-assist-hardening.md`
> §P2）：初版「jieba 关键词全词命中」被实测噪声推翻（通用关键词误 hit + 进程
> 重启后 growth=全文 + 等长改写吃旧缓存）。现行判据如下。

```
对每个 pending 锚点：
  片段 = text_match 共享判据的 3 字滑窗片段（命中率阈值/就近窗口唯一权威，
        禁止在此另写滑窗逻辑）
  若全部片段命中新增区段（就近窗口内）→ hit
```

- 全片段命中才判 hit——宁可不跳勾，不可误报已兑现（误报会破坏信任，漏报
  只是作者自己划掉）；整串捷径仅对 ≥3 字锚点开放（2 字通用词裸子串命中
  正是旧噪声之源），<3 字锚点按未命中处理——漏判由 finish 报告 spine_note
  兜底，误判没有出路；临近岔路走低阈值档宽松提示；
- 新增区段由 orchestrator 记录的上次正文长度推（growth=正文[上次长度:]）；
  **首轮只记基线不判定**——进程重启/重新进章后 growth=全文的大面积误 hit
  不可逆（hit 只前进不回退）；改写收缩（正文变短）退化为尾部 500 字；
- 结果按**内容 hash** 缓存（治等长改写吃旧缓存），心跳零 LLM；
- 写库防并发（9d6c066）：判 hit 期间作者侧防抖 PATCH 可能已改 spine——
  commit 前结束读事务 refresh 重读整行，hit 按 id 单向（pending→hit）应用
  到新鲜 anchors 再写回（逐锚点浅拷贝防 JSONB 按值相等漏 UPDATE）；作者
  已清空锚点则不回写（编辑权在作者）；
- `spine_progress = { anchors: [{id, text, status}], pending_count, hint: "还剩 1 个锚点" }`。

### 4.4 预算

心跳编排的 creative 预算（单章 ≤3000 tokens）不变——走向卡标注与挂件意图注入
都是既有调用的 prompt 增量；spine-suggest 是独立的 1×creative，不占心跳预算。

## 5. 岔路分期（DDE 迁移的度控制）

| 期 | 内容 | LLM 成本 |
|---|---|---|
| M3（随本设计一期落地） | **作者声明岔路**：谋篇区给锚点标「⚡这里有岔」+ 手填 2-3 个走向短语；进度感知判定临近该锚点时，走向卡舱以**硬提示样式**（朱色描边，区别柔性建议）置顶呈现这些走向，选定后写入 `adopted_direction` 走既有负反馈降权 | 0 |
| M4（数据门，默认不开） | **DDE 自动岔路判断迁移**：`dde/decision_card_generator.py` 解耦 BeatSlotCard（beat_id 闸门改为锚点 id 闸门或纯文本校验），触发时机=进入新章且 spine 存在时一次 1×creative；产出同样走作者过目 | 1×creative/章 |

M4 的开启条件：P0 埋点显示 spine 覆盖率 ≥50% 且走向卡采纳率 ≥30%——否则说明
作者群体（含本人）根本不在章级尺度上思考，自动判断做了也没人看。

## 6. 埋点与「度」的数据护栏

并入 P0-3 协作埋点（本地 jsonl 零上报）：

| 事件 | 裁决用途 |
|---|---|
| 谋篇卡展示 / dismiss / 意图落字 | **忽略率 = dismiss÷展示；持续 >70%（≥10 章样本）→ 章首卡自动降级为副驾常驻**（不再出现在画布），不问作者 |
| spine-suggest 调用 / 收下 / 编辑后收下 / 全弃 | AI 建议质量；全弃率 >60% 时降建议锚点数为 3 |
| 锚点 hit / dropped / 章末仍 pending | hit 判定阈值校准依据；dropped 占比高=锚点设多了，文案劝减 |
| 走向卡 serves_anchor 标注率 × 采纳率 | 挂锚建议是否比游离建议更准（§3.3 的价值验证） |

## 7. 分期表

| 期 | 内容 | 出口标准 |
|---|---|---|
| M1 | chapters.spine 列 + PATCH 端点 + 复合谋篇卡（意图 + AI 建议）+ 副驾谋篇区 | 空章一句话能存住；建议不过目不落库；忽略一切写作体验与现状一致 |
| M2 | 心跳 spine 注入 + spine_progress + 感知带进度行 + 走向卡 serves_anchor | 走向卡带 ⚑N 小签；锚点 hit 打勾；零 LLM 进度判定 |
| M3 | 胶囊挂锚点（三锚定扩写）+ 作者声明岔路（硬提示样式） | 胶囊扩写 prompt 含锚点意图；岔路锚点临近时卡舱置顶硬提示 |
| M4 | DDE 自动岔路判断（数据门，默认不开） | spine 覆盖率与走向卡采纳率达阈值后再评估 |

**M1+M2 即构成最小可用闭环**（谋篇有存、建议有挂、进度有感）；M3/M4 可独立推迟。

## 8. 风险登记

- **死字段风险**：作者从不写 spine → 功能空转。对策即 §6 的自动降级——数据裁决，
  不靠感觉保留功能。
- **概念混淆**：谋篇 vs 大纲文案必须划清（「大纲写情节，谋篇写方向」）；副驾两区
  相邻摆放，谋篇区永远在上（方向先于情节）。
- **hit 误判**：全词命中阈值可能过严（锚点「发现假信」正文写「信是赝品」就不命中）。
  接受漏判（D-5 哲学），作者手动点掉即可；后续若漏判率数据难看，再加同义词扩展，
  绝不引入 LLM 判定（成本+延迟换不来信任）。
- **spine-suggest 质量依赖大纲**：无大纲无世界数据的新书建议必然空泛——此时按钮
  文案降级为「先写两句大纲，建议才靠谱」（点火卡无大纲态的同款诚实）。
