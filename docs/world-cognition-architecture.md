# 世界认知架构（World Cognition Architecture, WCA）——v1.0

> 2026-08-27 · 状态：设计定稿（已经 teacher-kimi 导师审阅修正，附录 A）· 定位：取代「每次调用现场装配知识」的范式，回答「AI 如何认知这个小说的世界」。
> 前置：`docs/knowledge-retrieval-plane.md`（v3.1，已施工）是本架构的车道底座；方向权重引擎（`services/adaptive/direction_weights.py`）的尸检是本架构的直接动因——一周 18 次生成输出恒为常量，先验力学模型无观测无回路。

---

## 0. 范式转变

**从 per-call 装配 → 维护一份活的、分层的、版本化的世界认知。**

- 旧范式：每次生成调用加载设定→选择→注入→丢弃；模型对世界的理解每次从零冷读文本。
- 新范式：世界认知被**持续维护**成三层物化视图，注入走「稳定前缀 + 动态后缀」，注意力由作者正在写的字与作者的打算共同驱动。
- 业界对应（导师核证，非原创风险）：冷层 ≈ Generative Agents 的 reflection / GraphRAG 社区摘要 / Letta sleep-time compute；温层 ≈ 情景记忆；热层 ≈ 工作记忆。**本系统的不可复制优势：已有结构化事实源（事件日志 + 纯函数折叠），因此冷层是权威库之上的派生物化视图，LLM 永不做记录作者（author of record）——这条是不可违反红线。**

## 1. 四层认知（导师修正：计划层是第四层，也是与「又一版方向权重」的分界线）

| 层 | 内容 | 更新时机 | 生成方式 | 车道位置 |
|---|---|---|---|---|
| **冷层·世界总账** | 世界格局的分节叙述（实体状态/悬置之事/弧线张力/基调） | settle/finish/世界编辑事件，节级增量 | 事实节纯代码；综合节 LLM 输出结构化 ops | 前缀（章间稳定） |
| **温层·场景卡** | 本章此刻：在场者状态/脚下/手中/未决钩子/**本章打算（spine 意图+锚点+就近一拍）** | 章锚/场景钉/切章/settle（低频刷新点） | 纯代码（复用 scene_slice，禁止平行实现） | 前缀（章内冻结） |
| **热层·注意力窗** | 当前段提及实体/物件/悬置动作的显著集 | 每心跳 | 纯代码（三族信号×段距衰减） | **后缀**（随段变） |
| **计划层**（并入温卡固定节） | spine 意图、锚点、大纲就近节拍 | 作者编辑 spine/大纲时 | 纯代码 | 前缀（章内稳定） |

**判据一句话（与 v3.1 的分工）**：「一般真」压缩（冷层），「此时此地真」逐字（温/热车道）——人类作者的工作方式：全局格局是感觉，局部事实是查的。

## 2. 冷层 digest：分节带键、按键失效、按节再生（承重设计）

```
DigestSection {
  section_key: str          # "entity:zhou_yu" / "arc:northern_war" / "tone"
  text: str                 # 有界：在场实体节 ≤150 字，离场一行码 ≤40 字
  source_refs: {entity_ids, event_seq_max, chapter_anchor}
  frozen: bool              # source_refs 未变 → 逐字节冻结（缓存友好）
  derived: "code" | "llm"
}
```

五条规则：
1. **事实节零 LLM**（谁在哪/死活/活跃关系——折叠态代码可生成）；LLM 只做综合节（悬置之事/弧线张力/基调）；
2. **dirty-tracking 由 source_refs 承担**：world_version 变更 → diff 出脏节 → 只再生脏节。键引用同时白送：预览显示每节出处（「AI 所见」升级为「AI 所见及依据」）、校验层可比对 digest 节与死者状态；
3. **LLM 再生走结构化 ops**（ADD/UPDATE/DELETE/NOOP——Mem0 纪律）：输入=权威折叠态+旧节文本（仅措辞连续），代码执行。禁止自由改述；
4. **定期全量对账重建**（每 N 章或手动通读触发）——纯派生缓存，重建永远安全。预算走 read_budget 模式但**分池**（auto-read 已占 30/日，共池会互相饿死）；
5. **厚书纪律（有数值）**：总注入硬顶 ~2.5k 字；在场实体全节 / 离场一行码（名字+状态+位置，代码生成）/ 已闭环弧线归档出局。「厚书不涨」= 节数与一行码增长而节长与总量封顶，复用 budget 两级 allocate，不发明第二预算器。

**时态失效边纪律（Zep）**：digest 内论断必须能被事件「作废」（按键失效），不是被 LLM 改写。

## 3. 前缀缓存工程（导师实测修正：v3.1 现状接 DeepSeek 命中率也≈0）

| 端点 | 机制 | 价格 | 需要做什么 |
|---|---|---|---|
| DeepSeek | 自动前缀缓存 | 命中约 1/10 | 前缀逐字节稳定 |
| OpenAI | automatic（≥1024 token 起） | 约 5 折 | 同上 |
| Anthropic | 显式 cache_control 断点 | 写 1.25x/读 0.1x | 适配层插断点（对称工程：reasoning_adapter 同款 prompt_cache_adapter） |
| mimo | 无 → 按 none 对待 | 无 | 降级路径逐字节等于今天 |

**最大的缓存敌意点（必须修）**：v3.1 的「提及」选择器每次调用扫本章全文，而实体块在注入序第 2 位——作者每打一段字实体块就变，前缀从第 2 块起整体作废。修法：**提及驱动注入挪到后缀热层；前缀实体块冻结为「进章版本」，只在切章/settle/场景钉变更时刷新**（每章数次，失效可接受）。

前缀纪律四条：时间戳/run_id/用量计数绝不进前缀（加对拍单测：同状态两次装配 prefix byte-equal，扩展既有零变化测试族）；JSON 序列化固定 key 序；注入序调整须同时回答质量与缓存两个问题；usage 记 `prompt_cache_hit_tokens`（DeepSeek）/`cached_tokens`（OpenAI）进 generation_runs，设数据门。

**近端收益的现实检验**：当前唯一模型 mimo 无缓存——前缀纪律的近期价值是 ①逼清楚「什么随段变、什么章内冻结」（分层正确性的检验器）②DeepSeek 接入当天生效。当下 token 杠杆仍是总量控制。

## 4. 热层显著性（取代方向权重）

**信号三族（全部纯代码）**：文本流（段距新近、提及频次 log 饱和、对话说话人、@/# 显式提及、末句未决动作——复用 paragraph_source 尾段口径）；世界（实体先验重要度、在场沉默者、开放伏笔/临近揭示≤2 章、canon_watch 命中）；行为（零件采纳 +/蒸发 -/hint 收起 -，继承 quiet_learning 纪律：一次肯定胜过三次否定+宽恕）。

**衰减**：`score = Σ wᵢ·exp(-Δ段/τᵢ)`，提及 τ≈3 段，开放环 τ=∞（闭环才衰减），行为做乘性系数。**参数总数个位数**——方向权重死因之一是参数比观测多，调参只走实测回收流程。

**防窄化配额（6 槽）**：≤3 给 top 显著、≥1 给「被冷落的重要」（高先验且 K 段未提——方向权重「未兑现伏笔」信号的正当转世）、≥1 给在场沉默者、1 给系统事件。新实体带随创建时间衰减的新颖性加成。

**升降级闸门（与缓存纪律强耦合）**：热→温只在温层重建点晋升（绝不连续晋升，否则显著性抖动污染前缀缓存）；温→冷随 digest 维护；**冷层绝不读热层**——事实路径（事件→折叠→digest）与注意力路径（段落流→显著性→选择加权）物理分离，显著性是注入权重不是事实来源。

**方向权重的葬礼**：力学模型埋掉；有价值的输入信号（期待张力、未兑现伏笔计数、采纳反馈）拆解进热/温层信号集。

## 5. 与 v3.1 知识平面的车道表（不许两套平行系统）

| v3.1 现有件 | WCA 去向 |
|---|---|
| 条目 schema / 逃逸阀 / 时态标注 / 出处徽标 | 保留，全部层共用 |
| 「选中即完整」契约 | 保留，适用范围收窄到温/热车道 |
| 场景恒选/在场/时刻选择器 | → 温层输入 |
| 提及选择器 | → 热层，从前缀逐出 |
| 作者显式（章级绑定） | 独立最高优先车道，章内稳定住前缀 |
| 世界观大块整体注入 | 降级（digest 取代的部分） |
| 三层召回检索 | 长尾补层，现状保留 |

工程约束：WCA 三层全部作为 `stitch_context`/`render_system_blocks` 的**新生产者**接入（块序：冷节→温卡→现有软块→[后缀：热窗+任务+recency 钉]）；任何知识项单次调用**有且仅有一个主车道**；context-preview 按车道展示来源（扩展 _block_source）。digest 若综合私有信息必须走 secrets 车道（双轨纪律继承，digest 生成器感知 visibility）。

## 6. 分期路线（每期以遥测为开工许可——方向权重死因是先建引擎后建观测）

- **Phase 0（1-2 天，先于一切新工件）**：trace 增 `context_manifest`（每块 key/车道/字符/条目键/prefix 哈希/cache hit tokens）；后处理算「**注入但未消费率**」（注入实体×生成/采纳文本提及重叠、canon 跟随率、分车道采纳率）。攒一周数据，直接回答「digest 值不值得建」。
- **Phase 1（温层场景卡，纯代码）**：复用 build_scene_slice 同源；章内冻结+前缀纪律落地。数据门：章内 byte-equal+装配方差下降+dock 采纳率不降。
- **Phase 2（热层，纯代码，影子先行）**：log-only 跑一周（算而不注，对照 v3.1 实际选中集看重叠率）；再只开 dock 一条车道 A/B。τ 参数此刻才允许调。
- **Phase 3（冷层 digest，唯一烧 LLM，最后建）**：先服务 finish/audit（非交互、错了不脏画布），验证后进 stitch。**开工许可 = Phase 0 未消费率数据 + 双模型对照（假设一）共同签发。**
- 每期写死 kill criterion（如「digest 上线 N 章无采纳率提升→回退 v3.1 全注入」）；回退路径开工时即存在。

## 7. 三个待证伪假设（导师推翻清单，按杀伤力）

1. **「瓶颈是知识供给」**——mimo 三连不服从禁令的记录提示绑定约束可能是模型本身。证伪测试先于 Phase 3：同 context manifest，mimo vs DeepSeek 各跑一周对比采纳率/canon 合规；若提升只在 DeepSeek 出现，WCA 的 ROI 按出货模型重算。
2. **「1-2k digest 承载全量注入且厚书不涨」**——压缩的失败模式是安静的（不报错，只是走向四平八稳）；「有界」与「认知密度」在厚书极限冲突。解法=§2.5 的有数值分层纪律（在场全节/离场一行/归档出局）。
3. **「注意力由当前段驱动」**——08-25 视野配比修复证明计划层信号（spine/锚点/就近节拍）是防驴头不对马嘴的第一杠杆；纯 recency 显著性会系统性低估「这章要去哪」，症状是局部合理全局无目的。解法=计划层并入温卡固定节（第四层）。

## 8. 红线汇总

- LLM 永不做记录作者（digest 是派生物化视图，DB 是唯一事实源）；
- 冷层绝不读热层（事实/注意力路径物理分离）；
- 单知识项单主车道（预览按车道可见，重复注入直接暴露）；
- 事实节零 LLM；LLM 综合节只输出结构化 ops；
- 私有信息走 secrets 车道（digest 感知 visibility）；
- mimo/无缓存端点降级路径逐字节等于今天（零劣化）。

结论：骨架成立（维护式+分层+稳定前缀+派生缓存），三件必须改：①digest 节级键控化（自由文本增量合并必死）；②提及注入从前缀逐出（v3.1 现状接 DeepSeek 命中率也≈0——提及选择器×注入序第 2 位的组合）；③计划层补位（分界线：没有它就是又一版方向权重）。另吸收：Mem0 结构化 ops、Zep 时态失效边、reflection 节点化、Anthropic/Manus 上下文工程纪律、段落距离衰减（非墙钟）、6 槽防窄化配额、热温晋升闸门、Phase 0 遥测先行、双模型对照签发 Phase 3。
