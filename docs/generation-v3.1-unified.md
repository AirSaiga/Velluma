# Velluma 生成体系 3.1：统一引擎工程方案（高潮倒推 × 双轨）

> 日期：2026-07-19
> 前置文档：`generation-v3-design.md`（3.0 高潮倒推法蓝图）、`generation-v2-design.md`（2.0 蓝图）、`human-flavor-in-fiction.md`（原理）。
> 本文档定位：**把 3.0（高潮倒推）与 2.0（双轨）合并为一条管线**，程序自主决策，不再由用户选择引擎。
> 术语：本文档起启用新术语规范（见附录 A），旧名（引爆链/payload/起爆分等）全部废弃。

---

## 1. 核心思想：一条连续谱，而非两个引擎

**双轨是高潮倒推法在"高潮强度趋近于零"时的极限形态。**

每一章都有"最重要的一笔"——哪怕最平淡的过渡章也有它存在的理由。把 3.0 对高潮点的定义从"惊天动地的反转"放宽到"本章最重要的一笔"，高潮倒推法就是普适方法：

- **高潮章**：高潮分量重，重兵投入高潮段与蓄势段；
- **过渡章**：高潮只是一笔，全章 90% 是正常叙事推进——跑起来就是原来的双轨。

因此统一不是缝合两个引擎，而是：**一条管线，一个"章节定档"参数，程序自动判断本章落在谱上的哪一段。**

两个旧引擎的分工：

| 旧引擎 | 在统一管线中的角色 |
|---|---|
| 高潮倒推（3.0） | **全书节拍器**：负责骨架（铺垫结构图）、高潮段、蓄势段、全部审校 |
| 双轨（2.0） | **铺陈工艺**：负责铺陈段的写法（前向滚动扩写）；速写功能重生为"自由速写对照" |

一句话：**双轨从"章节哲学"降级为"铺陈段工艺"，高潮倒推从"独立引擎"升格为贯穿全程的骨架。**

## 2. 章节定档（自主决策核心）

### 2.1 四档定义

| 档位 | 章节类型 | 铺垫结构深度 | 高潮段规格 | 人工确认点 | 铺陈段占比 |
|---|---|---|---|---|---|
| 高潮章 | 大高潮/揭盅/决裂/卷尾 | ≤6 层 | 双候选 + 人工过目冻结 | 3 个全开（高潮点/铺垫结构/高潮段成稿） | ~30% |
| 转折章 | 中等转折、重要推进 | ≤4 层 | 单发 + 代码初筛选优 | 可一键快速确认 | ~50% |
| 推进章 | 小转折、日常推进 | ≤2 层 | 单发免审 | 无（通知式，可改） | ~70% |
| 过渡章 | 纯过渡、衔接 | 1 层（扁平） | "本章一笔"单发 | 无 | ~90% |

### 2.2 定档依据（决策函数）

输入信号（按权重）：
1. **候选高潮强度自评**：定档与候选高潮生成同次调用完成，模型给出强度分（1-10）与理由；
2. **章节在卷/弧中的位置**（弧高潮位、卷首卷尾加权）；
3. 章节卡 `tension_level`、`word_count`；
4. 用户显式标注（若有）。

决策规则：**宁低勿高**。挂低档的代价是"章平庸但完整"，挂高档的代价是"过渡章硬造高潮"（更伤）；低估可靠**中途升档**（§8）修正，高估没有好下场。

### 2.3 透明与覆盖

定档结果与理由在生成前以**通知**形式呈现（非确认点）："本章判定为【转折章】，依据：高潮强度 7 分 + 位于本卷倒数第二章"。用户可一键强制改档；不改则按档执行。

## 3. 统一流程：一章的生命周期

```
Phase 0  上下文组装（沿用：双通道召回 + established_facts）
Phase 1  章节卡 + 高潮候选（2~3 个） + 章节定档          ← 通知式确认
Phase 2  铺垫结构生长（逆向递归，深度随档）              ← 高潮章/转折章有人工确认点
Phase 3  高潮段先写（规格随档）                          ← 高潮段成稿确认（仅高潮章强制）
Phase 4  蓄势段写作（朝着已定稿的高潮写，带高潮距离标注）
Phase 5  铺陈段写作（双轨工艺：前向滚动扩写 + 自由速写对照）
Phase 6  组装（阅读序拼接 + 接缝打磨，无全文统稿）
Phase 7  审校（图校验 → 有锚审校 → 高潮验收/泄底检查）
Phase 8  局部修改（漏埋补写 / 泄底压低调子 / 高潮段重写）
Phase 9  定稿回写（沿用 + 伏笔自动登记）
```

写作顺序：**高潮段 → 蓄势段 → 铺陈段**。阅读顺序反之。
- 高潮段先写：全章最重要的一段在信息最完备时写；
- 蓄势段朝着已成稿的高潮写：知道自己在为什么蓄力；
- 铺陈段最后写：此时高潮与蓄势都在，铺陈只需把读者平稳送到蓄势段门口——压力最小，正好交给双轨的前向工艺。

各 Phase 与 3.0 的差异只在两处：**定档决定一切投资参数**；**Phase 5 由双轨工艺接管**。其余（上下文引擎、铺垫结构生长、高潮先写、审校、回写）与 `generation-v3-design.md` §5 相同，不再重复。

## 4. 分区写作

每章按"离高潮的距离"分三个区，工艺各不同：

### 4.1 高潮段（高潮倒推工艺）
- 先写。高潮章双候选+人工过目；其余档位单发+代码初筛。
- 输入：高潮点 + 直接铺垫节点（距离≤2）+ 角色卡 + 文风卡 + 作者样本。
- 长度：全章 15~25%。

### 4.2 蓄势段（高潮倒推工艺）
- 朝着已成稿的高潮写，高潮成稿（或关键段落锚）在 prompt 中可见。
- 高潮距离标注进 prompt：
  > 本段距离高潮还有 {d} 拍，任务={收拢/压抑/部分释放/闲笔}。
  > 禁止提前抖包袱（泄底）；让读者抱着这个悬念走且不回答：「{悬念}」；
  > 自然埋入：{本段铺垫}；不说破：{restraint_note}；字数 {n}（边写边数）。
- 每段配一条悬念（D7：压抑≠无聊，靠未解的悬念保温）。

### 4.3 铺陈段（双轨工艺，复用现有实现）
- 前向滚动扩写（沿用现有 Track A / fuse_writer 实现）：前段尾巴 + 章节卡 + 本段铺垫节点。
- 不施加"压抑"约束（离高潮远，无需压着写）——双轨"每拍自我完满"的病灶在这个距离上不发作。
- 并发与速度优先；>5000 字超长章沿用串行多段写法（现有 fuse_writer 能力）。
- **自由速写对照**（见 §5）在本区按需启用。

区间接缝：铺陈段与蓄势段的接缝天然柔软——两侧共享同一张铺垫结构图与滚动尾巴，组装时只做过渡句打磨（0~1 次调用）。

## 5. 自由速写对照（双轨速写的重生）

**问题**：蓄势段"压着写"的最大风险是压成无聊。怎么知道压劲是否合适？

**方法**：写蓄势段（或长铺陈段）之前/之后，对同一区域生成一份**无约束自由速写**（creative，不带距离标注、不带压抑约束，顺情节自然流），然后与正式稿对照：

| 对照发现 | 诊断 | 处置 |
|---|---|---|
| 速写在某处自然达到情绪高点，正式稿同处也出现高点 | 疑似泄底 | 泄底检查复核，确认则压低调子 |
| 速写明显比正式稿抓人（读者模型盲评） | 压抑过度 = 无聊 | 对该段注入一个小波折（一个未解的小悬念），局部升温 |
| 两者轮廓一致（低点对低点） | 压抑执行正确 | 通过 |

**本质**：速写给出"自然情绪轮廓"，铺垫结构给出"设计情绪轮廓"，**两者的差值就是诊断信息**。双轨时代的对抗校对由此从"找信息差"升级为"校准压劲"，速写也终于有了真正的消费者。

成本：每蓄势段 +1 次 creative 调用（速写长度为该段 40%）；转折章以下档位可关闭。

## 6. 数据结构（v3 演进，仅列变更）

**DetonationChain → SetupGraph（铺垫结构图）**：
```json
{
  "chapter_id": "...",
  "tier": "climax | turn | progress | transition",
  "tier_reason": "高潮强度 7 分 + 卷末第二章",
  "climax_point": { "description": "...", "emotional_target": "...",
                    "answers_question": "...", "opens_question": "...",
                    "text": "...", "approved": false, "candidates": [...] },
  "nodes": [ SetupNode ],
  "zones": { "climax": ["PAYLOAD"], "buildup": ["n4","n5"], "development": ["n1","n2","n3"] },
  "reading_order": ["n1","n2","n3","n4","n5","PAYLOAD"],
  "status": "..."
}
```

**SetupNode 变更**：`distance_to_payload` → `distance_to_climax`；`assignment` 取值改为 `收拢 | 压抑 | 部分释放 | 闲笔`；`type` 保留 `plant/development/diversion/texture`；其余字段（question/restraint_note/subtext/satisfied_by_existing/planted_in_text）不变。

**StoryBeat**：`sets_up/payoff_of` 保留，加 `zone`（development/buildup/climax）。拍数仍按结构自然分段（2~5），不按字数均分。

**PlotLedger**：登记来源加 `setup_graph_auto`，含 planted_in_text 证据。

## 7. 审校体系（沿用 3.0，术语更新）

**Layer 0（零 token，代码）**：
- 图校验：每个高潮点/回收点有铺垫？每个铺垫在阅读序上先于其回收？闲笔占比 ≤15%？
- 既有指标：禁词命中率/句长 CV/对话占比/段末升华/字数/实体一致性。

**Layer 1（有锚 LLM 审校，reasoning，1~2 次）**：
- **落地验证（漏埋）**：逐节点"该铺垫是否在正文中落地？"证据链 JSON 回填 `planted_in_text`；
- **未回收检查**：每个铺垫是否服务于高潮或后续章节？无归属的铺垫要么删、要么登记为伏笔；
- **泄底检查**：各蓄势段是否存在提前抖包袱（情绪峰值检测 + 真相泄露检测）；
- **高潮验收**：高潮段 + 其前 500 字送读者模型，"情绪是否被顶起来？1-10 分+一句话理由"。<7 分→进入 §8 高潮段重写；
- 失败不静默：解析失败标 unaudited，绝不视同通过。

**修改（Phase 8）**：漏埋→定向补写；泄底→压低调子重写该段；高潮不足→重写高潮段并润色邻近蓄势段（**巡航的铺陈段不动**——高潮重写的波及面被结构局部化）。≤2 轮，未解 → degraded 标记进质量报告。

## 8. 飞行中自主调节（自主决策的第二层）

定档只是开始，管线在生成中持续自我校正：

| 触发 | 动作 |
|---|---|
| 蓄势段写作中发现高潮比定档评估的更强（或用户看了高潮段点"值得放大"） | **中途升档**：暂停→补生长铺垫结构→按新档位追加投资 |
| 高潮验收 <7 分 | **高潮段重写**（换候选/换角度），仅波及高潮段+邻近蓄势段 |
| 自由速写对照判定"压抑过度" | 该段注入一个小波折，局部升温后复审 |
| 铺陈段写到一半发现节点全 trivial（本章确实无事发生） | **建议并章/删章**——管线第一次能反过来教作者做减法（通知式，用户决定） |
| 树生长违反图校验（环/孤儿/闲笔超标） | 带错误反馈重试 ≤2 轮，仍败→降级并标记 |

## 9. API 合并与代码复用

### 9.1 端点合并

| 现状 | 目标 |
|---|---|
| `POST /generate-chapter`（双轨）+ `POST /generate-v3`（高潮倒推）并行 | **统一为 `POST /api/chapters/{id}/generate`**，参数 `tier: auto\|climax\|turn\|progress\|transition`（默认 auto） |
| 前端"引擎：双轨/引爆链"开关 | 改为"章节定档：自动（推荐）/手动指定"，UI 不再出现引擎概念 |
| 章节卡/铺垫结构/高潮段三个人工确认点 | 保留，按档位自动开合（过渡章全部跳过） |

其余端点（card、detonation-chain、payload、quality-report、publish）沿用 3.0 设计，字段按 §6 改名。

### 9.2 代码复用映射

| 现有资产 | 在统一管线中 |
|---|---|
| Track A / fuse_writer 串行扩写 | **铺陈段写作实现**，原样复用 |
| SketchGenerator | **自由速写对照**的生成器，prompt 改造（去约束化） |
| stitching.py | 超长章分段拼接 fallback，保留待用 |
| 3.0 全链（card/chain/payload/audit/refine/publish） | 主链，字段改名 |
| 对抗校对（采样对比式） | 退役，由速写对照 + 有锚审校取代 |
| 上下文引擎 / 文风体系 / 回写 / 观测 | 不变 |

**工程红利**：数据结构只有一张铺垫结构图，下游（审校/修改/回写/伏笔登记）零分叉；双轨代码一行不删，全部以"铺陈工艺"身份存活。

## 10. Token 预算（按档位，可见 token，5000 字章）

| 阶段 | 过渡章 | 推进章 | 转折章 | 高潮章 |
|---|---|---|---|---|
| 章节卡+候选+定档 | ~4k | ~4k | ~4k | ~4k |
| 铺垫结构生长 | ~3k（1 层） | ~6k | ~9k | ~9k |
| 高潮段写作 | ~3k（单发） | ~3k | ~3k | ~7k（双候选+选优） |
| 蓄势段+速写对照 | ~2k | ~8k | ~14k | ~14k |
| 铺陈段（双轨工艺） | ~10k | ~8k | ~6k | ~4k |
| 组装/审校/修改 | ~6k | ~9k | ~12k | ~14k |
| **生成合计** | **~28k** | **~38k** | **~48k** | **~52k** |

全书加权（按典型网文 过渡:推进:转折:高潮 ≈ 3:4:2:1）约 **~37k/章**——比"全章走高潮倒推全礼"省 ~25%，比"全章走双轨"质量高出一整个结构层。**钱花在了该高潮的章上。**

## 11. 迁移路线（从并行双引擎到统一）

**Step 1：数据结构统一**（改名字段 + tier/zones 字段，MIGRATIONS 增量；旧端点读旧字段，互不影响）
**Step 2：铺陈段接入**（统一管线内实现 Phase 5：调用现有 fuse_writer；速写对照 prompt 改造）
**Step 3：定档器**（候选生成 prompt 加强度自评；决策函数按 §2.2；通知式 UI）
**Step 4：端点合并**（新 `/generate` 上线，旧两端点 deprecation；前端开关改为定档选择）
**Step 5：飞行中调节**（升档、高潮重写、压抑校准、并章建议）
**Step 6：A/B 验收**（同书 10 章：旧双轨 vs 统一管线 auto，盲评 + 高潮评分 + 人工润色计时）→ 旧端点下线

每步独立可上线、可回滚（旧端点 deprecation 期内随时切回）。

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| 定档错误（该高潮的章挂了低档） | 宁低勿高原则 + 定档透明可改 + 中途升档兜底；低档代价远小于高档 |
| 区间接缝（铺陈→蓄势过渡生硬） | 共享铺垫结构+滚动尾巴；接缝打磨工序；盲评验证 |
| 自由速写对照误判（自然轮廓≠正确轮廓） | 对照结论仅作"建议"，二次复核才动手；转折章以下默认关闭 |
| 模式复杂度（一套管线四种形态） | 单一数据结构兜底；档位即参数表，代码路径唯一，差异仅在投资参数 |
| 用户想全程手动 | tier 可强制指定，四档行为完全确定可预期 |
