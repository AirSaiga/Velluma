# 百炼 SFT 点选路径（阶段6操作指引）

- 写给谁：第一次用阿里云百炼的操作者，照着点即可。
- 写法约定：本指引只描述**路径和要选什么**，不编造精确按钮名。凡是引用官方文档出现过的入口名（如"数据管理""新增数据集""模型调优""开始训练"）都可能与控制台当前显示有出入——**一律以控制台当前文案为准**；拿不准就截图发回来，不要凭感觉点。
- 我方约束：AI 不替你点击；本指引的终点是**计费确认页，不点最终提交**。

## 0. 开始前准备

- 阿里云账号，已完成实名认证（个人/企业均可）。
- 两个文件在本机路径：
  - 训练集：`D:\deai\data\sft\train30.jsonl`（30 条，messages 格式，已通过 check_jsonl.py 校验）
  - 评测提示：`D:\deai\data\eval\eval15.jsonl`（15 条，仅 system+user；见第 3 节的重要说明）
- 文件名只有小写字母和数字，符合百炼"文件名仅用 a-z/A-Z/0-9/_/-"的要求，**不要改名上传**。
- 手边留个记事本，按第 8 节表格记录。

## 1. 开通/进控制台

1. 浏览器打开百炼控制台：`https://bailian.console.aliyun.com/`（以官网为准）。
2. 用阿里云账号登录。首次进入可能要求：开通百炼服务、勾选服务协议、选择业务空间。都按页面默认走。
3. 如果提示账号无权限或需要授权，说明你用的是 RAM 子账号——换主账号操作，或让管理员授权后再来（见第 7 节第 1 条）。

## 2. 数据管理：新增训练集，上传 train30.jsonl

1. 左侧菜单找「数据管理」（官方文档名称，以控制台当前文案为准）→ 点「新增数据集」。
2. 数据集用途/类型：选**训练集**，场景选 **文本生成 / SFT** 对应的选项（不要选评测集，不要选 DPO/CPT）。
3. 上传方式选"本地上传"，选择 `train30.jsonl`。
4. 若页面提供"下载数据模板"，可以下载打开对照一眼——我们的格式是每行一个 JSON：`messages` 数组，system 在最前（可选），之后 user/assistant 交替，最后一条是 assistant。官方文档确认支持该 ChatML 结构。
5. 等平台校验通过后保存。**把平台显示的数据集名称记下来**（第 8 节表格）。
6. 校验报错 → 去看第 7 节第 3 条，把报错原文发回来。

## 3. 新增评测集：上传 eval15.jsonl（重要说明，先读再点）

官方文档（调优数据上传规则，2026-08-31 查证）写明：百炼"评测集"是 **xlsx 模板格式**，且每条评测数据是 **Prompt + Completion（期望输出）成对**，用于平台内模型评测。

而我们的 `eval15.jsonl` 是 JSONL、只有输入没有标准答案——**它不是百炼评测集格式，直接上传大概率被拒**。它是我方评测脚本（阶段8）喂给训练后模型用的提示文件。

所以这一步给你两个方案：

- **方案 A（推荐，省事）**：跳过评测集上传。第 5 节训练任务里把验证方式选成"从训练集自动划分 10%"。eval15.jsonl 留在本地给我方评测用。
- **方案 B（要在百炼平台内跑自动评测才需要）**：在「新增数据集」里选评测集类型，**先下载官方 xlsx 模板**，把模板发回来，我按模板用 E01–E15 生成带参考答案的 xlsx（参考答案需新写，不复用训练数据，符合隔离要求）。

如果你仍想试着直接上传 eval15.jsonl：可以试，**被拒就停下截图**，不要为了传上去去改数据集类型为训练集。

## 4. 模型调优：创建 SFT 任务

1. 左侧菜单找「模型调优」（官方文档名称，以控制台当前文案为准）→ 创建/新建训练任务（文案可能是"训练新模型"等）。
2. 训练方式选 **SFT（有监督微调）**。不要选 DPO（那是后续阶段的事），不要选 CPT（继续预训练）。
3. 按页面顺序走：选基础模型 → 配置数据 → 配置参数。各选项见第 5 节。

## 5. 模型与参数（按既定优先级，逐项核对）

| 配置项 | 你要选的 | 说明 |
|---|---|---|
| 基础模型 | 优先找**千问3-4B**（可能写作 Qwen3-4B 之类）；控制台若无 4B，按官方默认选**千问3-8B** | 只在千问3 系列里挑；列表文案以控制台当前为准 |
| 训练方式 | **高效训练** 或 **LoRA**（两者任选其一；若只出现一个就选出现的那个） | 不要选"全参训练/全量微调"类选项 |
| 超参数（学习率、轮数等） | **全部保持默认**，不手动改 | |
| 混合训练/通用数据混合 | **不开启** | 官方提示：混合百炼通用数据会计入总训练 Token 并计费 |
| 验证集 | **自动划分 10%**，或选已按训练集类型上传的独立验证数据集 `val15.jsonl`（见下方"验证集说明"） | |
| 训练集 | 选第 2 节创建的那个训练数据集 | 别选反成别的 |

**验证集说明（2026-08-31 官方核实）**：评测集（xlsx）**不能**选为验证集——官方定义评测集用于训练完成后的"模型评测"功能，不参与训练任务；验证集"选择数据集"方式下拉里只有训练集类型的数据集。要独立验证集：把 `data/eval/val15.jsonl`（E01–E15 的 messages 格式，与训练集事实隔离）按第 2 节方式以训练集类型上传后，在验证集下拉中选择它。

## 6. 停止点：计费确认页

1. 参数配完往下走，通常会进入任务确认/费用预估页（文案可能是"确认订单""费用预估"等，以控制台当前文案为准）。
2. **到此为止：不要点最终确认/提交/开始训练。**
3. 截图发回来，画面里尽量包含：基础模型、训练方式、训练集与验证方式、预估费用、计费方式。
4. 顺手帮我确认三件事（截图或抄文案即可，用于回填 open_questions）：数据配置页对 messages 格式的说明、是否提及额外字段（如 name/weight 被拒）、单文件大小/条数提示。

同时给你一个官方数据点做决策参考：百炼官方对 SFT 文本训练的**推荐数据量是"至少上千条"**。我们这次 30 条属于"小样本效果验证"性质——第一次任务费用如果偏高，可以等扩数据后再跑（扩数据管线已就绪：加事实卡→教师跑批→六闸→重新导出）。

## 7. 常见报错对照表

| 报错/现象 | 可能原因 | 怎么处理 |
|---|---|---|
| 权限不足 / 无法访问该页面 | 未开通百炼，或用的是 RAM 子账号且无百炼权限 | 换主账号；或让管理员给子账号加百炼相关权限策略（策略名以官方文档为准）；开通入口在产品首页 |
| 模型未授权 / 无权使用该基础模型 | 所选基础模型需单独开通/申请，或不在当前地域 | 按页面指引申请授权；或换列表里可直接用的千问型号；截图发回来 |
| JSONL 格式错误 / 数据校验失败 | ①文件被其他软件另存过（编码/换行被改）②数据集场景类型选错（把 messages 对话选成了纯文本/问答对类）③行内有空行 | 用 `D:\deai\data\sft\train30.jsonl` 原文件重新上传，不要用 Excel/记事本转存；核对场景选项；仍报错就把报错原文发回来 |
| 上传 eval15.jsonl 当评测集被拒 | 非平台评测集格式（平台要 xlsx 且 Prompt/Completion 成对） | 正常现象，见第 3 节方案 A/B |
| 训练/评测集类型选反 | 创建数据集时用途点错，或训练任务里关联反了 | 数据集删掉重建，用途对应；训练任务里重新关联正确的数据集 |
| 提示数据量过少 | 官方推荐 SFT 至少上千条 | 属预期内警告；是否继续由你在看完费用预估后决定 |
| "training 数据集大小（N）必须大于 batch size（M）" | 默认 batch size（如128）大于小数据集条数 | 在超参里把 batch size 改小（本项目30条训练集：改为8；同时8<验证集15条，避免验证环节再报错）。本次唯一偏离默认的参数，已记入记录表 |
