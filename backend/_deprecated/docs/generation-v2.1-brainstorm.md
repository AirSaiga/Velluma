# 2.1 头脑风暴：重新思考"怎样生成好小说"

> 日期：2026-07-19
> 性质：发散性探索，不是设计文档。参考科研与产品成果但不受其约束。
> 前置：`docs/generation-v2-research.md`（现状与常规方案）、`docs/generation-v2-design.md`（2.0 蓝图）、上一轮范式讨论（分段-扩写-统稿的结构性缺陷）。
> 使用方式：每个方向标注【依据】（有实证）或【概念】（无实证、纯推演）；第 5 节用工程过滤器收敛；第 6 节是本周就能跑的验证实验。

---

## 1. 原点重构：我们一直在优化错的东西

现有所有范式——包括我们自己的 2.0/2.1——都在优化**"文本是怎么生产出来的"**（规划→起草→修订）。但好小说的本质不在生产侧，在体验侧：

> **好小说 = 信息差管理 × 情绪建筑 × 嗓音**

- **信息差管理**：读者在任何时刻"知道什么、好奇什么、猜到什么"是被作者精确操控的。翻页的动力不是"写得好"，是"有个问题没答案"。
- **情绪建筑**：张力需要在高潮前很久通过措辞、节奏、语调逐层铺垫（上轮调研的 "multi-scale emotional architecture"）；AI 文的"诡异平静"（eerie placidity）正是缺了这个。
- **嗓音**：AI 味的反面不是"没有 AI 腔"，而是"有明确、可辨认的说话人"。

**如果把生成目标从"生产一段合格的文本"换成"制造一连串读者体验"，流水线的每个环节都会变形。** 下面的想法都从这个重构里长出来。

### 顺手打破的默认假设

| 默认假设 | 重构后 |
|---|---|
| 章节是生成的单位 | 体验流才是单位，章节只是读者侧的切分 |
| 规划 = 规划情节 | 规划 = 规划读者心理（问题流/情绪曲线），情节是载体 |
| 生成 = 逐字直出 | 生成可以是搜索、模拟、删除、填空等任何算子 |
| 一致性靠记忆检索 | 一致性可以靠构造（模拟）或联动（文本→状态即时回写） |
| AI 味靠负面清单 | 负面清单只能"去腥"，嗓音要靠"有人格"正面建立 |
| 质量靠生成端提升 | 可以**校验器先行**——先有尺子，再驱动生成方法迭代 |
| 作者是润色者 | 作者的最佳位置可能是：导演 / 首席读者 / 骨架师 |

## 2. 体验驱动类：把读者心理变成生成目标

### 2.1 读者问题流（Question Flow）【概念+旁证】

规划一章时，不规划"发生什么事件"，而规划**"读者问题的开合"**：每个节拍标注——开了哪个坑？吊着哪个旧坑？答了哪个（答一半）？读者此刻最大的疑问是什么？

- 钩子密度、坑的存活时长、"答一送二"（答一个旧坑开两个新坑）全部变成**可测量的规划约束**。
- 依据：悬念的"不确定性削减"计算模型已有人做出接近人类的判断准确率（Wilmot & Keller, ACL 2020, arXiv:2004.14905）；网文的"追读"机制本质就是问题流。
- 风险：过度公式化会让节奏变得可预测；需要"节拍模板"而非"铁律"。

### 2.2 情绪曲线闭环控制【概念+旁证】

把情绪当作**控制系统的被控量**：
1. 生成前：定目标曲线（可参考 6 种基本情绪弧的聚类结论——Reagan et al. 2016；U 形弧与商业成功相关——6174 部电影研究；或按网文类型的节奏模板）。
2. 生成后：对成稿按段做情感评分，画出实际曲线，**算与目标的距离**。
3. 差距超标 → 定向修订情绪不足的段落。

- 警示：COLM 2025（arXiv:2508.15794）证明 LLM 能判断"是否意在制造悬念"但**不能复现人类对悬念强弱的排序**——所以闭环里的"测量器"要用粗粒度意图检测或公式化指标，别指望 LLM 当精密读者。
- 这是直接对治"诡异平静"的方案：平静 = 曲线方差为零，而方差是可以写进验收标准的。

### 2.3 对抗读者模型（Reader-in-the-Loop）【概念+反证约束】

生成后不让"编辑"审查，而让**模拟读者**通读并交报告：哪里跳读了？哪里困惑？此刻你预测接下来会发生什么？哪个人物的行为让你觉得假？

- "读者预测"特别有价值：如果读者总能精准预测下文，说明文本俗套（呼应 Magellan 的"高概率引力井"问题，arXiv:2510.21341）。
- 修订以读者报告为导向，比 checklist 审查更接近真实体验。
- 同样受 2.2 的反证约束：当**粗筛**用（找明显问题），不当精判。

### 2.4 叙事动作库（Narrative Moves）【概念，生成侧研究空白】

把叙事学手法变成**可组合、标注了预期效果的算子库**：伏笔、误导（红鲱鱼）、延宕、视角限制、信息揭示时机、闪回、in medias res、对比剪辑……规划器像下棋一样为每个章节选配动作组合。

- 调研确认：伏笔/误导/延宕的**生成侧**计算化基本空白（只有分析侧工作）——空白意味着差异化机会，我们的 PlotLedger 已经是现成的伏笔追踪底座。
- 每个动作附带"使用成本"（延宕用多了读者流失）和"配伍禁忌"（误导后必须及时回收）。

## 3. 生成算子类："写"不一定是逐字直出

### 3.1 减法引擎（Subtraction Engine）【概念+社区共识】

中文网文编辑的共识：**"有经验的作者往死里做减法，AI 往死里做加法。"** 那就把减法做成独立算子：

- 生成时故意写 150%（放开描述），然后一个"删节 pass"砍到 100%——删冗余形容词、删重复解释、删不推进剧情的描写。
- 删除是最便宜的提质算子，且**可客观验收**（删后信息量保持率、禁词命中率变化）。
- 与"高潮段落只做减法"指令同源，但把它从 prompt 愿望变成独立工序。

### 3.2 潜台词双层生成（Subtext Layer）【概念+分析侧实证】

AI 文平，是因为它写"发生了什么"，不写"没说出口的是什么"。双层生成：

1. 先生成**潜台词层**：这个场景里每个角色隐藏什么、想要什么、怕什么、话里哪句是言不由衷。
2. 再生成表层文本，硬性约束：**禁止直接说出潜台词层的任何内容**，只能通过动作、对话弦外之音、生理反应让读者自己猜到。

- 这是 "show, don't tell" 第一次变成可执行的工程约束（而不是 prompt 里的美好愿望）。
- 校验可先行：LIIPA（arXiv:2412.04576）已证明 LLM 能从行为动作推断角色隐性塑造——拿它当检测器，反向验证我们的文本"真的 show 了"。

### 3.3 转折点搜索（Search at Pivots）【实证较强】

**95% 的文本线性写，5% 的关键转折点做搜索选优。** 俗套的本质是模型掉进了训练数据的"高概率引力井"——在剧情决策点上，最高概率的走向往往就是最俗的走向。

- BiT-MCTS（arXiv:2603.14410）是专为中文长篇做的实证：把弗雷塔格金字塔操作化为"**高潮优先、双向扩展**"——先生成核心高潮，再前向/反向搜索扩展两翼；消融显示去掉搜索直接生成，平均败率 93.5%。
- 轻量版落地：转折点处生成 N=3 个候选走向，用"意外性 × 必然性（回过头看是否合理）× 角色一致性"打分选优——成本只加在 5% 的决策点上。
- Magellan 的"语义罗盘"（正交投影逃离高概率区域）可作为打分器里的"反俗套项"。

### 3.4 扩散式调度（Diffusion-Inspired Scheduling）【概念，长线】

扩散语言模型（LLaDA、Mercury）的核心启发：**非顺序生成**——先有全文轮廓再任意位置填细节、可反复重掩码重写——"统稿"被内化为生成过程本身，接缝从机制上不存在。

- 短期不用等 dLLM 成熟，可用现有 AR 模型**模拟扩散调度**：先生成稀疏锚点句 → 锚点间"填空"扩写 → 随机选段重写 1-2 轮（等价 remasking）。
- 长线关注：dLLM 目前无长篇小说实证，但架构属性值得盯。

### 3.5 对话先行（Dialogue-First）【概念】

网文对话占比动辄 40%+，且对话是角色嗓音的主场。翻转生成顺序：先出纯对话脚本（像剧本），再包裹叙述层。叙述变成脚手架，嗓音从对话里长出来。

## 4. 一致性与嗓音类

### 4.1 文本→世界状态即时联动（Language-as-Reality）【机制实证】

AI 原生游戏 1001 Nights（AIIDE 2023，Steam 在售，2055 名玩家实测）的机制：玩家说出的关键词**具现化**为世界状态。

- 搬过来：正文里出现的物件、伤势、关系变化**在生成过程中就即时回写**世界状态库，而不是等发布时才回写——从机制上消灭"第三章受的伤第五章忘了"。
- 这比"生成前检索记忆"更根本：记忆是提醒模型别写错，联动是让错误无法存活。

### 4.2 角色智能体幕间模拟（Character Simulation）【实证，moonshot】

不立大纲，让角色在沙盒里按人设自由行动，涌现事件，叙事者再冶炼成文。StoryBox（AAAI-26）已做到万字级 SOTA，BookWorld（ACL 2025）做到了对原著 75% 胜率的保真衍生。

- 完整模拟对我们过重，但**轻量版"幕间小剧场"**很诱人：主线之外，让配角们"过自己的小日子"，把涌现的事件当作伏笔原料库——配角的行动因此有独立逻辑，而不是围着主角转的工具人。
- "异常行为因子"是现成的戏剧性旋钮。

### 4.3 校验器先行（Detector-First）【方法论，实证】

**凡事先造尺子，再谈生成。** 想解决什么问题，先做出它的检测器：show-don't-tell 检测器、悬念计算器（不确定度×威胁度×逃脱限制，SA-MCTS 现成公式）、情绪弧测量、事件切分（LLM 的事件切分已与人类对齐，Michelmann 2023）、钩子密度统计。

- 有了尺子，任何生成方法都能快速 A/B；没有尺子，所有"改进"都是玄学。
- 这与我们 2.0 观测体系一脉相承，是把"观测"从成本扩展到**体验指标**。

### 4.4 作者写作表（Author Writing Sheet）【实证】

Mythos（arXiv:2502.13028，112 位作者数据集）验证的路径：**先分析出显式的"作者写作表"**（情节/创意/发展/语言四维度，人可读、可编辑），再拿表约束生成——风格捕捉 78% 胜率，且 Creativity/Language Use 比 Plot 更易个性化。

- 比 LoRA 微调更经济、可解释，且**作者可以亲手改自己的写作表**——这本身就是产品功能（"看看 AI 眼里的你的文风"）。
- LoRA（<20 美元、500-2000 条样本起步）可作为远期补充层。

### 4.5 怪癖人格（Designed Imperfection）【概念】

AI 文太光滑，因为 RLHF 把"一个完美平均人格"放在了舞台中央。对策不是继续打磨，而是**故意设计不完美**：给叙事者一个有人格缺陷的 persona——口头禅、句式癖、视角偏见、对某些细节的执念——并作为一等状态跨章维持。嗓音 = 一致的怪癖。

### 4.6 风格移植后处理（Voice Transplant）【概念+评估警示】

内容与嗓音彻底解耦：先生成剧情完美但风格中性的稿子，风格 pass 只改 voice 不动事实（配内容保持度校验，防止带跑剧情）。一份稿子可出多种嗓音，作者声音定制只需定制风格层。

## 5. 工程过滤器：哪些值得先做

评估坐标：**体验增益 × 实现成本 × 与 2.1 流水线兼容性 × 验证成本**。

| 梯队 | 方向 | 理由 |
|---|---|---|
| **第一梯队**（本周 prompt 级验证） | 减法引擎 3.1 / 潜台词双层 3.2 / 情绪曲线闭环 2.2 / 对抗读者报告 2.3 | 全部不改架构，直接在现有生成端做 prompt 原型；直击"AI 味"与"平静"两大痛点 |
| **第二梯队**（一个迭代周期） | 读者问题流规划 2.1 / 转折点轻量搜索 3.3 / 文本→状态即时联动 4.1 / 作者写作表 4.4 | 需要动规划器或数据流，但证据最硬（BiT-MCTS 中文实证、Mythos、1001 Nights 机制） |
| **Moonshot 观察** | 角色智能体模拟 4.2 / 扩散调度 3.4 / 怪癖人格 4.5 | 潜力大但成本/风险高，先跟踪或做玩具验证 |
| **随时可做** | 叙事动作库 2.4 / 校验器先行 4.3 / 对话先行 3.5 | 渐进积累型，不设独立里程碑 |

## 6. 本周就能跑的四个实验（纯 prompt 级，每个 ≤ 半天）

| # | 实验 | 对照 | 判据 |
|---|---|---|---|
| E1 | **潜台词双层**：同一张章节卡，A=直接生成，B=先生成潜台词层再禁言式生成 | 盲评：哪版"更有人味/更有嚼头" | 3 人盲评偏好率 |
| E2 | **减法 pass**：生成 150% 再删到 100% vs 直接生成 100% | 指标（禁词/句长/信息密度）+ 盲评 | 指标变化 + 偏好率 |
| E3 | **情绪闭环**：定目标曲线→生成→测曲线→修订 1 轮 vs 无闭环 | 曲线拟合度 + "是否平淡"盲评 | 拟合度提升、盲评偏好 |
| E4 | **读者报告修订 vs checklist 修订** | 同稿两路修订后对比 | 盲评偏好率 |

原则：每个实验用同一章、同一模型、同一上下文；先小样本看方向对不对，方向对再进工程。

---

## 7. 一句话总结

**2.0/2.1 解决的是"写得对"（逻辑、一致性、成本），这轮头脑风暴解决的是"写得勾人"（问题流、情绪建筑、嗓音）。两条线共享同一个底座——可测量的读者体验指标——谁先建尺子，谁就赢。**
